# 反馈与状态设计 — Feedback & States（深度蒸馏）

> agent 的「反馈决策手册」：什么时候该出声、用哪种形态、持续多久、放在哪里、失败时说什么。**凡涉及 toast / 弹窗 / 加载 / 骨架屏 / 空态 / 错误页 / 确认框 / 乐观更新，先读本文件。**
> 所有数值取自官方原文或源码（Material 3、IBM Carbon、Ant Design、Atlassian、GOV.UK、W3C WCAG 2.2、NN/g、微信小程序文档），非二手总结。快照 2026-11-01

**本文件解决的核心问题**：反馈不是"加个 toast"——它是**一套按严重度与等待时长分层的系统**。选错层级（用 toast 报严重错误）、选错时长（3 秒让人读完 40 字）、选错形态（空态只放插画），都会让用户错过关键信息或产生"系统卡死"的错觉。

---

## §1 反馈的五个层级与选择决策

### 1.1 层级表（先定层级，再选组件）

| 层 | 形态 | 是否打断 | 是否留存 | 典型场景 |
|---|---|---|---|---|
| **L0 微反馈** | hover / press / 焦点 / 开关动画 | 否 | 否（≤120ms） | 任何可交互元素的即时响应 |
| **L1 轻提示** | toast / message / snackbar / flag | 否 | 否（3–5s 自动消失） | 操作已完成的确认、可撤销动作、后台推送 |
| **L2 就地状态** | inline alert / banner / 字段错误 / 空态 | 否 | **是**（随内容常驻） | 需要用户读到并据此行动的说明、区块级失败 |
| **L3 阻塞决策** | modal / dialog / popconfirm | **是** | 是 | 不可逆操作确认、必须立即处理的错误 |
| **L4 结果页** | result page / 404 / 500 / 维护页 | 是（换页） | 是 | 流程终点、整页不可用、权限拒绝 |

### 1.2 三问决策树（照此走，不要凭手感）

```
① 这条信息需要用户「做一个决定」吗？
   是 → L3 模态（不可逆/高代价）或 L4 结果页（流程终点）
   否 → ②

② 用户此刻的上下文还在这块内容上吗？（他正看着出问题的那个字段/区块吗）
   是 → L2 就地状态（字段下红字 / 区块内 inline alert / 空态）
   否 → ③

③ 这条信息必须被读到、且事后还要能找回吗？
   是 → L2 banner（页顶常驻，可关闭）或通知中心；**不要用会自动消失的 toast**
   否 → L1 轻提示（toast / message）
```

### 1.3 三条硬规则

1. **一个动作只给一次主反馈**。点了保存 → 按钮变 loading → 成功后按钮旁出现"已保存"，就**不要再弹 toast**。双层反馈 = 噪音。
2. **同屏并发反馈 ≤2 条**。第三条出现说明设计有问题（该合并、该降级为 L2、或该进通知中心）。
3. **严重度决定形态，不决定颜色**。把严重错误做成红色 toast 仍然是错的——红色只解决"看见"，不解决"读到"。Ant Design 原文明确：**重要的失败信息建议用对话框**，因为浮层展示时长太短（默认 3s），用户会漏。

## §2 时间阈值（唯一的权威刻度）

### 2.1 三个经典阈值（Nielsen，1993 提出，2014 复核仍成立）

| 阈值 | 含义 | 设计含义 |
|---|---|---|
| **0.1 s** | 感觉"系统在直接响应我" | 任何点击/按键，**100ms 内必须有视觉变化**（按下态、选中高亮）。没有变化用户就会重复点击 |
| **1.0 s** | 思维流不被打断 | 0.1–1s 之间用户会察觉延迟，但**不需要额外指示器**。超过 1s 必须给"正在处理"的信号 |
| **10 s** | 注意力仍停留在当前任务 | 超过 10s 必须给**百分比进度 + 明确可中断的出口**。超过 10s 用户会切走，回来需要重新定向 |

### 2.2 现代细化（把三个阈值翻译成组件选择）

| 等待时长 | 用什么 | 不用什么 |
|---|---|---|
| **< 1 s** | 什么都不加（最多按钮按下态） | **不要**加 spinner 或骨架屏——快速闪现反而让人焦虑（NN/g 明确） |
| **1–2 s** | 按钮内 loading（宽度锁定）或局部 spinner | 全屏遮罩 |
| **2–10 s** | 骨架屏（整页/容器级）或局部 spinner | 静态文字"Loading…"（等于没反馈） |
| **> 10 s** | 进度条 + 粗略时间估计 + **取消入口** | 无限旋转的 spinner（用户分不清"在跑"还是"卡死"） |

- Ant Design 的口径是 **> 2s 就应给加载状态**，并明确"若加载时间较长，应提供取消操作"。
- NN/g 补充：**预估波动越大，越应提前**从 spinner 切到进度条——因为"以为 2 秒"实际 15 秒是最伤信任的场景。

### 2.3 两个被明令禁止的做法

- ❌ **静态 "Loading…" 文案**：任何反馈优于无反馈，但静态提示信息不足——系统卡死时用户无法判断是否需要重启。
- ❌ **"请勿重复点击"警告**：这是把系统的问题转嫁给用户。正确做法是让第一次点击**立刻可见地生效**（按钮进入 loading / 置灰 / 文案变化），从根源消灭重复点击。

## §3 Toast / Snackbar / Message（轻提示）

### 3.1 时长与位置：五个体系的精确值

| 体系 | 组件 | 默认时长 | 位置 | 关键数值 |
|---|---|---|---|---|
| **Ant Design** | `message` | **3 s**（`duration:0` 常驻） | 顶部居中，`top: 8px` | padding `9px 12px`，`zIndex 2010`，`pauseOnHover` 默认 true |
| **Ant Design** | `notification` | **4.5 s** | 右上，`top/bottom: 24px` | **width 384px**，堆叠阈值 3，`zIndex 2050`，`role` 默认 `alert` |
| **IBM Carbon** | Toast | **默认常驻**，可设为 **5 s** | 右上滑入 | 堆叠间距 `$spacing-03`，新条在顶部 |
| **Material 3** | Snackbar | **4–10 s** | 底部 | 移动端高度 48→64dp，**同时只允许 1 条** |
| **sonner**（React） | toast | **4000 ms** | 右下 | `dismissible: true` |
| **微信小程序** | `wx.showToast` | **1500 ms** | 屏幕中 | `mask` 默认 false |

> 取值纪律：**同一产品内所有 toast 用同一时长**。Carbon 甚至要求时间戳"全有或全无"——混用会训练用户"有的能读完有的读不完"，最终全都不读。

### 3.2 尺寸与内容上限

- **行数**：Carbon 明确 **≤2 行**、内容 **1–2 句**；M3 要求**尽量 1 行**，移动端最多 2 行。超 2 行 → 改用带"查看详情"链接的 L2 通知。
- **宽度**：Ant notification 固定 **384px**（可用 token `width` 改，但**不要**用 `max-content`，会破坏堆叠一致性）。Carbon：toast 固定宽度、高度随内容。
- **动作**：**只允许 1 个**（Carbon："Only one action is allowed for each notification"；M3 同样只允许一个 text button）。标签 **1–2 个词**。
- **关闭按钮**：toast 应始终可关（Carbon）；M3 认为有自动消失就**不必**再给 dismiss。二者取舍：**自动消失 → 可省关闭；常驻 → 必须有 ×**。

### 3.3 该用 / 不该用（最容易出错的一节）

| 场景 | 用什么 | 为什么 |
|---|---|---|
| 保存成功、复制成功 | L1 toast（3s） | 无需行动，看一眼即可 |
| 删除成功 + 可撤销 | L1 toast + "撤销"动作，**时长 5s 起** | 给用户反悔窗口；M3 明确"允许用户修正选择时给 Undo" |
| **保存失败 / 支付失败 / 数据丢失** | **L3 对话框** 或 **L2 inline** | 用户必须读到并行动；3s 会漏（Ant 原文） |
| 表单字段格式错误 | L2 字段下红字 | 就地、不消失、可对照 |
| 后台任务完成（导出好了） | L2 通知中心 + L1 toast 提示 | toast 会消失，但结果要能找回 |
| 网络断开 | L2 banner（常驻） | 状态持续存在，恢复后才消失 |
| 多步流程失败 | L4 结果页 | 需要完整解释与重试入口 |

### 3.4 无障碍（这一节决定能不能过验收）

- **必须能被程序化确定**：容器用 `role="status"`（成功/进度）或 `role="alert"`（错误），见 WCAG 4.1.3 与 §10.1。
- **自动消失是 web 上的已知风险**：M3 原文——"On web, auto-dismissing snackbars are inaccessible for people with low vision or who require additional time"。两种解法：
  1. **同一信息另有就地表达**（如保存按钮文案变"已保存"）；
  2. **把 toast 变成可操作**，直到用户处理才消失。
- Atlassian 的纪律：**关键警告与错误永不自动消失**；且**不要把可关闭与不可关闭的 flag 混在同一个堆叠里**（能自动消失的那些，对需要更多时间的用户等于不存在）。
- **toast 不抢焦点**。抢焦点是模态的特权；toast 抢焦点会让键盘用户丢失位置。

### 3.5 中文与小程序专属坑

- `wx.showToast`：`icon` 为 `success`/`error`/`loading` 时，**title 最多 7 个汉字**（超出直接截断，不换行）；`icon:'none'` 时**可显示两行**。→ **中文提示超过 7 字就必须用 `icon:'none'`**，否则文案被吃掉。
- `wx.showToast` 与 `wx.showLoading` **同时只能显示一个**；两者都必须与 `hideToast`/`hideLoading` 配对，否则会一直挂着。
- 微信默认 1500ms，**比 web 的 3s 短一半**。中文句子要更短：建议 **≤14 字**（如"已保存"、"已复制到剪贴板"）。

## §4 加载与进度

### 4.1 三种加载形态的分工（Carbon + NN/g 合并口径）

| 形态 | 用在哪 | 不能用在哪 |
|---|---|---|
| **骨架屏 Skeleton** | 容器型组件（卡片、列表、表格、tile）、整页首屏 | **按钮、输入框、勾选框、开关**（动作型组件不需要骨架）；**toast、下拉菜单、弹窗本身、loader** 绝不用骨架 |
| **局部 Spinner / Loading** | 单个模块（一张卡、一个视频、一次提交） | 整页长时间等待（应升级为进度条） |
| **进度条 Progress** | > 10s 的确定型流程（上传、导出、批处理） | 不知道总量的场景（用不确定型进度或 spinner） |

- **不要 frame-only 骨架**（只有页头页脚、中间一片空）：NN/g 明确不推荐——它不传达页面结构，用户等久了会以为页面坏了，等价于一个 spinner。
- **骨架屏必须还原真实结构**：图片位用矩形、标题用粗短线、正文用细线。骨架与最终布局**不对齐**比没有骨架更糟（内容会跳动）。
- **表格/列表的空态必须替换表头与分页**（Carbon）：否则读屏会先把整张表念完才念到"没有数据"。

### 4.2 防闪烁（实践建议值，非官方规范）

- 请求 **< 200ms** 返回时**不显示**任何加载态——避免"闪一下"。
- 做法：加载态延迟 **200–300ms** 再出现；若数据在此之前返回则永不出现。
- 加载态一旦出现，**至少停留 300ms** 再撤（否则用户看到一闪而过的骨架，像故障）。

### 4.3 进度条的六条铁律

1. **> 10s 必须给百分比**，并给**粗略**时间（"大约还需 1 分钟"）。不要给精确到秒的倒计时——必然不准，且不准会损害可信度。
2. **宁慢勿快**：进度动画起步慢、接近完成时加快。用户对"超出预期"的容忍度远高于"承诺了却没做到"。
   - 例外：**问卷/多步表单**相反，应**先快后慢**（降低中途退出率）。
3. **不后退、不长时间卡在 99%**。用户会据此形成速度预期，停滞等于宣告"卡住了"。
4. **不知道总量时显示步骤数**："正在处理 3 / 50 条"，比假的百分比诚实得多。
5. **必须能取消**。超过 10s 还不给出口，等于劫持了用户对系统的控制权。
6. **循环动画只用于 ≤10s**。长任务用无限 spinner，用户无法区分"在跑"和"死了"。

### 4.4 按钮内 loading（最高频、最容易做错）

```css
/* 关键：锁定宽度，避免 loading 文案把按钮撑大导致布局跳动 */
.btn.is-loading { min-width: 8em; pointer-events: none; }
.btn.is-loading::before { content: ""; /* spinner */ }
```

- 文案：**动词进行时**（"保存中…"→"已保存"），不要"提交"→"提交中"→"提交"。
- 状态机：`idle → submitting（禁用 + loading）→ success（按钮旁打勾 2s）| error（恢复可点 + 就地红字）`。
- **失败后按钮必须恢复可点**，且**已填内容不清空**（WCAG 3.3.7）。

### 4.5 乐观更新（Optimistic UI）

- 适用：**成功率高、失败代价小、可回滚**（点赞、收藏、勾选完成、拖拽排序、发消息）。
- 不适用：**涉及金钱、不可逆、需要服务端裁决**（支付、删除、审批、库存扣减）。
- 三态必须都设计：`pending`（先改 UI + 轻微透明度/角标）→ `confirmed`（静默）→ `rolled back`（**恢复原状 + 一句说明 + 重试入口**）。
- 反模式：失败后静默回滚。用户会以为"我点过了"，然后在下次刷新时发现数据没了——比一开始就失败更伤信任。

## §5 空态 / 空状态（五种"空"）

### 5.1 分类（先判是哪一种，文案完全不同）

| 类型 | 触发 | 用户心理 | 该给什么 |
|---|---|---|---|
| **首次空** | 新账号/新项目，从没有过数据 | "这东西怎么用？" | 说明将出现什么 + **一个主操作**（新建/导入/用模板） |
| **无结果空** | 搜索/筛选后为 0 | "是不是我筛错了？" | 说明筛选条件 + **清除筛选**（不要给"新建"） |
| **无权限空** | 有数据但不可见 | "为什么我看不到？" | 说明原因 + **申请权限/切换账号** |
| **失败空** | 请求失败 | "是不是坏了？" | 说清失败原因 + **重试**（不要伪装成"暂无数据"） |
| **完成空** | 待办清空、收件箱为 0 | 正向情绪 | 一句肯定 + 可选的下一步（**不要塞广告**） |

> 最常见的错误：把**失败**渲染成**无数据**。用户会以为"真的没有"，于是不再重试。

### 5.2 结构五件套（Carbon）

```
[图（可选）]      ← 与情境相关；空间小就省略，只留文字
标题             ← 正向表述："添加第一个数据源" 优于 "您还没有数据源"
说明             ← 一句：这里将出现什么 + 为什么现在是空的 + 做这一步的好处
主操作           ← 按钮 或 正文内链接 或 指向界面元素（"点击右上角 + 新建"）
次操作（可选）    ← 文档链接等，弱化为文字链接
```

- **标题必须正向**。Carbon 原文举例："Start by adding data assets" 比 "You don't have any data assets" 更好；退一步可用 "还没有…"（带"还"字暗示会变）。
- **只给一个主操作**。多个选项 → 挑最重要的一个，其余降为文字链接。
- **不要制造死路**：任何空态都不该只留一句"暂无数据"。

### 5.3 布局与尺寸

| 容器 | 对齐 | 图的位置 |
|---|---|---|
| 小 tile / 侧栏 | 图**居中**，文字与按钮**左对齐**（Carbon 特例：防止空态被误认为内容而跳过） | 图在上 |
| 大卡片 / 表格区 | 整块**左对齐**，可用较宽左边距或整体居中 | 宽图在上，高图在左 |
| 整页 | 整块居中或左对齐（二选一，全站统一） | 宽图在上 |

- **空间不足就只留文字**（Carbon 明确）。塞一张缩小的插画比没有更乱。
- **同屏多个空态**（仪表盘多卡片失败）：用 **tertiary 按钮**，避免一屏出现五个主按钮；此时优先**纯文字**空态，不要每个都配插画。

### 5.4 文案公式与中文示例

**公式**：`标题（正向，≤12 字）` + `说明（这里会出现什么 + 怎么做，≤30 字）` + `按钮（动词，≤6 字）`

| 类型 | 标题 | 说明 | 按钮 |
|---|---|---|---|
| 首次空 | 创建第一个项目 | 项目用来归类素材与成员，创建后即可邀请同事 | 新建项目 |
| 无结果空 | 没有匹配的结果 | 试试减少筛选条件，或换个关键词 | 清除筛选 |
| 无权限空 | 你没有查看权限 | 该看板属于「增长组」，可向管理员申请访问 | 申请权限 |
| 失败空 | 内容加载失败 | 网络似乎不稳定，请稍后重试 | 重新加载 |
| 完成空 | 今天的任务都完成了 | 新任务分配后会出现在这里 | 查看历史 |

## §6 错误状态的分级

### 6.1 五级错误与承载位置

| 级别 | 范围 | 承载 | 关键要求 |
|---|---|---|---|
| **E1 字段级** | 单个输入 | 框下 4–8px 红字 + 图标 | 就地、不消失、`aria-invalid` + `aria-describedby` |
| **E2 表单级** | 整张表单 | 页首 **错误摘要**（可聚焦，锚点跳到字段） | 提交失败时**焦点移到摘要**；列出全部错误而非第一条 |
| **E3 区块级** | 一个模块/卡片 | 区块内 inline alert（替换内容区） | 保留页面其他部分可用；给"重试" |
| **E4 页面级** | 整页不可用 | 结果页（404 / 403 / 500 / 维护） | 说清"是不是你的错"+ 出路 |
| **E5 全局级** | 整个应用 | 全屏状态页 + 状态页链接 | 给预计恢复时间与备用通道 |

### 6.2 页面级错误页的规则

**404（GOV.UK 原文口径）**：
- `<title>`：`Page not found – 服务名`
- `H1`：**Page not found**（中文："找不到页面"）
- **禁止**：面包屑、技术术语（404 / Bad Request）、俏皮话（"哎呀"/"Oops"）、**用红字警告**
- 给联系方式（若真实存在且能满足需求），且写明电话与工作时间
- 语气：清楚、简洁、**不责怪用户**

**500 / 服务不可用**（把 GOV.UK 与 Ant Result 合并）：
- 标题写"我们这边出了问题"，**明确不是用户的错**
- 一句现状 + 一句下一步（"已记录，正在修复" / "请 5 分钟后重试"）
- 给**至少两个出口**：重试、返回首页/联系支持
- **不要**显示堆栈、错误码裸奔（可折叠展示 request id 供报障）

**403 / 无权限**：说明"缺什么权限、找谁要"，而不是"禁止访问"。

### 6.3 错误文案三段式（报错文案怎么写）

```
[发生了什么] + [为什么] + [怎么办]
```

- ❌ "系统错误，请稍后重试"（三样全缺）
- ❌ "操作失败"（等于没说）
- ✅ "验证码已过期（5 分钟内有效），点「重新获取」再试一次"
- ✅ "这张图片超过 5MB 上限，压缩后再上传"
- 长度：**≤30 字**（沿用 `form-table.md` §7）；不用"非法/格式不正确/请重新输入"。
- **不责怪用户**：Atlassian 原文——说"我们连接出了点问题"，而不是"你的网络有问题"。

### 6.4 重试的纪律

- 重试按钮**始终可见可用**，不要倒计时锁死 60s。
- 自动重试用指数退避（1s / 2s / 4s，最多 3 次），且**必须有可见状态**（"正在重连…"）。
- **不要**自动整页刷新循环——用户填的内容会丢，且屏幕闪烁。
- 失败后**保留已输入内容**（WCAG 3.3.7 冗余录入的实践延伸）。

## §7 弹窗、确认与破坏性操作

### 7.1 NN/g 八条（原文提炼）

1. **只给严重后果用**：毁掉用户成果、花大钱、**不可撤销**。
2. **不要给例行操作用**：喊狼来了太多次，确认框就失去防护力。
3. **必须具体**：不要问"确定吗？"，要说清**对什么、做了什么、后果是什么**。
4. **按钮写结果，不写 Yes/No**：「删除 3 个文件」/「保留」。
5. **允许展开细节**（渐进披露），但正文保持可扫读。
6. **不要给"是"设默认值**：最理想是**没有默认焦点**，至少默认落在安全项。
7. **极危险操作要求非常规动作**：输入对象名（如输入 `DELETE` 或项目名）。**只用于最危险的少数场景**，用多了也会变成肌肉记忆。
8. **能撤销就别确认**：优先给 undo，确认框是退而求其次。

### 7.2 弹窗尺寸与结构（M3 精确值）

| 属性 | 值 |
|---|---|
| 最小宽度 | **280dp** |
| 最大宽度 | **560dp** |
| 圆角 | **28dp** |
| 四周内边距 | **24dp** |
| 标题与正文间距 | **16dp** |
| 正文与按钮间距 | **24dp** |
| 按钮之间间距 | **8dp** |
| 图标 | 24dp（可选） |
| 全屏对话框头/底栏高 | 56dp / 56dp |

### 7.3 形态选择

| 形态 | 何时用 | 何时不用 |
|---|---|---|
| **Popconfirm** | 轻量、单对象、后果可逆（删除一条评论） | 涉及多个对象或需解释 |
| **Modal** | 不可逆、需完整解释、需输入确认 | 只是"确认一下"（用 popconfirm） |
| **Drawer** | 需要保留上下文、内容较多（编辑详情） | 需要强阻断 |
| **独立页面** | 多步、需要 URL 可分享/可刷新（结算、删除账号） | 单步小操作 |

### 7.4 危险确认的文案模板

```
标题：删除「项目 A」？            ← 动作 + 对象名
正文：该项目下的 128 个文件与 6 名成员将一并移除，
      此操作不可撤销。            ← 数量 + 不可逆性
[取消]  [删除项目]                ← 中性在前，危险在后；按钮写动词
```

- **危险按钮用危险色，取消按钮用中性色**。两个都红 = 没有重点。
- **焦点默认不给危险按钮**（Enter 误触即灾难）。
- 危险按钮**不做成页面主色**（品牌色留给正向主操作）。
- 删除成功后**优先给撤销 toast**（5s 起），而不是"删除成功"四个字。

## §8 五态数据模型（工程落地）

### 8.1 每个数据区块都必须实现的五态

```
idle → loading → success
              → empty        （成功但为 0 条，见 §5 分类）
              → error        （失败，可重试）
     → partial             （有数据但部分失败：保留成功部分 + 局部错误提示）
```

**`partial` 是最常被漏掉的一态**：一个仪表盘 6 张卡片挂了 2 张，正确做法是**其余 4 张正常显示 + 2 张各自显示错误与重试**，而不是整页报错。

### 8.2 列表页的加载序列

| 阶段 | 反馈 | 注意 |
|---|---|---|
| 首屏 | 骨架屏（行数 = 首屏可见行数） | 骨架行高必须等于真实行高 |
| 翻页 | 表格区半透明 + 局部 spinner，**保留表头** | 不要整页白屏 |
| 加载更多 | 底部按钮变 loading；到底显示"没有更多了" | 到底提示不能省，否则用户会一直滚 |
| 刷新（已有数据） | 顶部 2–3px 细进度条，**内容不动** | stale-while-revalidate：旧数据继续可读 |
| 筛选变化 | 列表区 loading，**筛选控件保持可用** | 页码重置到 1 |

### 8.3 保存状态指示（编辑器类必做）

三态文案，位置固定在标题栏或状态栏（**位置不变，只变文字**）：

| 状态 | 文案 | 视觉 |
|---|---|---|
| 编辑中未保存 | 未保存 | 中性灰 + 小圆点 |
| 保存中 | 保存中… | spinner + 禁用重复提交 |
| 已保存 | 已保存 · 刚刚 | 弱化灰，2s 后可淡出 |
| 离线 | 离线，恢复后自动保存 | 黄色 banner，常驻 |
| 保存失败 | 保存失败，点此重试 | 红色 + 可点 |

> **不要**用 toast 报告"已保存"——编辑器每次保存都弹一次，一天弹上百次。

## §10 可访问性与合规

### 10.1 WCAG 4.1.3 状态消息（AA，最容易被忽略的一条）

- **定义**：不是上下文变化、但向用户传达「操作成功/结果、等待状态、流程进度、存在错误」的内容变化。
- **要求**：能被 `role` 或属性**程序化确定**，从而**无需获得焦点**即可被辅助技术播报。
- 角色分工：

| role | 播报行为 | 用于 |
|---|---|---|
| `status` | polite（等当前朗读结束） | 成功、计数、进度、保存状态 |
| `alert` | assertive（打断当前朗读） | 错误、紧急警告——**只给错误用** |
| `log` | 顺序追加 | 进度日志、聊天流 |
| `progressbar` | 配合 `aria-valuenow/min/max` | 确定型进度 |

- **失败做法 F103**：状态消息没有 role/属性 → 读屏用户完全不知道发生了什么。
- **不属于状态消息**（不用处理）：对话框里的错误（抢焦点 = 上下文变化）、菜单展开、按回答动态新增的问题。

### 10.2 WCAG 2.2.1 时限可调（A）——toast 到底算不算时限？

- 规则：内容自设的每个时限，至少满足其一：**可关闭** / **可调整（≥默认 10 倍）** / **到期前警告并给 ≥20 秒延长，且可延长 ≥10 次**；或时限 **> 20 小时**（长于一个清醒日）。
- **关键豁免（原文例证）**：若存在不依赖计时器的替代访问方式（例：邮件客户端用 5 秒 toast 提示新邮件，但收件箱仍可查看），则该计时提示**不构成时限**。
  → **所以 toast 合规的前提是"信息另有出口"**：通知中心、就地状态、按钮文案变化。没有出口的 3 秒 toast 就是不合格的时限。
- 会话超时：必须**提前警告**并给 ≥20 秒延长机会，且延长后**恢复到提问前的确切状态**。

### 10.3 加载动画与 2.2.2

- 自动播放、移动、闪烁超过 **5 秒**的内容，需提供暂停/停止/隐藏（轮播、无限滚动动画、持续闪烁的骨架 shimmer）。
- **`prefers-reduced-motion: reduce` 下关掉 shimmer**，保留静态骨架（否则是持续动画）。
- 加载中给容器 `aria-busy="true"`，完成后移除。

### 10.4 焦点与播报纪律

- **toast 不抢焦点**；**模态抢焦点**（打开入框、`Esc` 关闭、关闭后焦点回触发元素、背景 `inert`）。
- **`aria-live` 容器必须先存在再改内容**——渲染时才插入的节点不会被播报（详见 `accessibility.md` §10）。
- **播报增量**："已处理 48 项" 而不是整块重播。
- **不只靠颜色**：成功 = 绿 + 勾 + 文案；失败 = 红 + 图标 + 文案。色盲用户只看颜色等于没有反馈（详见 `accessibility.md` §12）。

## §11 中文场景与弱网

- **toast 文案 ≤14 字**（微信默认 1.5s，比 web 短一半）；**错误文案 ≤30 字**。
- 小程序 `icon` 有值时 **title ≤7 个汉字**，超了就用 `icon:'none'` 换两行空间。
- 中文不用感叹号堆砌（"操作成功！！！"）；不用"哦/啦/呀"这类轻佻语气处理失败。
- 全角标点；省略号用 `……`。
- **弱网策略**：请求超时 **8–10s** 主动断开并给重试（不要无限转圈）；离线时 banner 常驻；恢复后**自动重试一次**并提示"已恢复"。
- 大文件上传：显示**已传/总量 + 速度**，支持断点续传提示（"网络中断，已保留进度"）。

## §12 反模式（逐条对照，命中即改）

1. 用 toast 报严重错误（3s 内消失，用户漏掉）
2. 保存成功弹 toast，同时按钮又变"已保存"（双层反馈）
3. 一屏同时弹 3 条以上 toast
4. toast 堆叠且互相遮挡（应排队，一条一条来）
5. 把失败渲染成"暂无数据"
6. 空态只放插画，没有一个可点的下一步
7. 空态给"返回首页"当唯一出路
8. 骨架屏结构与真实布局不一致（加载完内容跳动）
9. 给按钮/输入框/弹窗本身做骨架屏
10. frame-only 骨架（只有页头页脚）
11. < 1s 的请求也闪一下 spinner
12. 加载 15s 还在转无限 spinner，没有进度也没有取消
13. 进度条从 90% 退回 40%
14. 进度条卡在 99% 不动
15. "请勿重复点击"警告代替即时反馈
16. 确认框问"确定吗？"，不说是哪个对象
17. 确认框按钮写"是/否"，且默认焦点在"是"
18. 每次保存都弹一次 toast（编辑器场景）
19. 失败后静默回滚乐观更新，不告诉用户
20. 状态消息没有 `role`，读屏完全静默

## §13 上线自检（15 条，全部可判定）

1. 每次点击/按键，**100ms 内**有可见变化？
2. 1s 内返回的请求，**没有**多余 loading？
3. 2–10s 的等待，有骨架屏或局部 spinner，且**骨架结构与真实布局一致**？
4. >10s 的流程，有**进度 + 时间估计 + 取消**？
5. 进度条不后退、不卡 99%、速度不突变？
6. 每个 toast 都能在 **3–5s 内读完**（≤2 行、≤14 字）？
7. 严重错误**没有**用 toast，而是 inline 或对话框？
8. toast 有 `role="status"`（或 `alert`），且**另有就地出口**（符合 2.2.1 豁免）？
9. 空态**分对了类**（首次/无结果/无权限/失败/完成），且各有**一个主操作**？
10. 空态标题是**正向表述**，没有责怪用户？
11. 表格空态**替换了表头与分页**？
12. 错误文案包含「发生了什么 + 为什么 + 怎么办」，且 ≤30 字？
13. 确认框写了**对象名与数量**，按钮写**动词**，默认焦点**不在危险按钮**？
14. 破坏性操作有**撤销**（优先）或二次确认（次选）？
15. 模态：焦点入框、`Esc` 可关、关闭后焦点返回、背景 `inert`？

## §14 可抄代码

### 14.1 Toast 容器（预置 aria-live，避免"插入即不播报"）

```html
<!-- 常驻在 DOM 里，页面加载时就存在 -->
<div id="toast-region" role="status" aria-live="polite" aria-atomic="false"></div>

<script>
function toast(msg, type = 'info', ms = 3000) {
  const region = document.getElementById('toast-region');
  // 错误改用 assertive：临时切换 role，播报后复原
  if (type === 'error') { region.setAttribute('role', 'alert'); }
  const el = document.createElement('div');
  el.className = `toast toast--${type}`;
  el.textContent = msg;                       // 增量：只追加这一条
  region.appendChild(el);
  setTimeout(() => {
    el.remove();
    if (type === 'error') region.setAttribute('role', 'status');
  }, ms);
}
</script>
```

### 14.2 骨架屏（结构对齐 + 尊重 reduced-motion）

```css
.skeleton {
  background: #EEF0F3; border-radius: 6px;
  position: relative; overflow: hidden;
}
.skeleton::after {
  content: ""; position: absolute; inset: 0;
  background: linear-gradient(90deg, transparent, rgba(255,255,255,.65), transparent);
  transform: translateX(-100%);
  animation: shimmer 1.4s infinite;
}
@keyframes shimmer { to { transform: translateX(100%); } }

@media (prefers-reduced-motion: reduce) {
  .skeleton::after { animation: none; }   /* 静态骨架，不闪 */
}
/* 行高必须等于真实行高，否则加载完会跳动 */
.skeleton-row { height: 47px; }
```

### 14.3 按钮 loading（宽度锁定，不跳版）

```html
<button class="btn" data-state="idle">保存</button>
<script>
btn.addEventListener('click', async () => {
  btn.dataset.state = 'loading';
  btn.disabled = true;
  btn.textContent = '保存中…';
  try {
    await save();
    btn.dataset.state = 'success';
    btn.textContent = '已保存';           // 就地反馈，不再弹 toast
    setTimeout(() => {
      btn.dataset.state = 'idle'; btn.disabled = false; btn.textContent = '保存';
    }, 2000);
  } catch (e) {
    btn.dataset.state = 'idle';
    btn.disabled = false;                 // 必须恢复可点
    btn.textContent = '保存';
    showInlineError(e.message);           // 就地错误，不清空已填内容
  }
});
</script>
```

### 14.4 危险确认（结构 + 焦点纪律）

```html
<div role="dialog" aria-modal="true" aria-labelledby="d-title" aria-describedby="d-desc">
  <h2 id="d-title">删除「项目 A」？</h2>
  <p id="d-desc">该项目下的 128 个文件与 6 名成员将一并移除，此操作不可撤销。</p>
  <div class="actions">
    <button autofocus>取消</button>              <!-- 焦点默认在安全项 -->
    <button class="danger">删除项目</button>      <!-- 按钮写动词 -->
  </div>
</div>
```
