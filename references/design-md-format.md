# DESIGN.md 规范与品牌 DNA — Design Spec

> 本文件解决「**怎么把设计意图写成 AI 和人都能执行的一份契约**」。
> 素材来源：[Google Stitch 提出的 DESIGN.md 概念](https://stitch.withgoogle.com/docs/design-md/overview/)、[VoltAgent/awesome-design-md](https://github.com/VoltAgent/awesome-design-md) 收录的 54 个真实产品设计系统（本地副本位于 `~/.workbuddy-ai/skills/awesome-design-md/references/`）。
> 使用时机：① 用户说"做成 XX 那种感觉"→ 查品牌 DNA；② 需要输出可长期复用的设计规范 → 产出 DESIGN.md。
> 快照 2026-10-29

---

## 一、DESIGN.md 是什么，为什么值得作为交付物

**定义**：一份纯 Markdown 的设计系统文档，放在项目根目录，AI 编码 agent 读了就能生成风格一致的 UI。

**它解决的三个真实痛点**：

| 痛点 | 没有 DESIGN.md | 有 DESIGN.md |
|---|---|---|
| 风格漂移 | 每次生成都是新风格，第 5 个页面和第 1 个不像同一产品 | 每章都是硬约束，生成结果收敛 |
| 知识流失 | 设计决策只在设计师脑子里，人走了就没了 | 决策与理由落成文字，可审计 |
| 沟通成本 | 设计稿 → 开发 → 偏差 → 反复对齐 | 一份文档同时是设计规范和实现依据 |

**关键认知**：DESIGN.md 不是"设计说明文档"，是**约束清单**。写得越具体（具体色值、具体 px、具体 do/don't），agent 产出越稳；写得越抽象（"现代简约"），越没用。

## 二、九章骨架（照此结构写，不增不减）

| 章 | 标题 | 必须包含 | 常见错误 |
|---|---|---|---|
| **1** | Visual Theme & Atmosphere | 一段散文式气质描述（3–5 句）+ 6–8 条 Key Characteristics | 写成形容词堆砌（"现代、简洁、大气"）；应写**手法**（"暖白底 + 沙灰中性色 + 单一红强调"） |
| **2** | Color Palette & Roles | 按**角色**分组：Primary Brand / Text / Interactive / Surface & Border / Semantic，每色带 hex + 用途 + token 名 | 只列色值不标用途；把 20 个色平铺不分层 |
| **3** | Typography Rules | 字体族完整栈、层级表（字号/行高/字重/字距/用途）、特殊规则（tabular-nums 等） | 只写"用 Inter"；缺行高与字距 |
| **4** | Component Stylings | 按钮（各态）、输入框、卡片、导航、徽标——每个给尺寸/圆角/内边距/状态 | 只写"圆角 8px"，缺 hover/active/disabled/error 四态 |
| **5** | Layout Principles | 画板宽、栅格、间距系统、容器最大宽、区块垂直节奏 | 只写"响应式"，无具体断点与间距值 |
| **6** | Depth & Elevation | 阴影层级（几层、每层参数）、何时用阴影 vs 边框 | 阴影写 8 层；或阴影边框同时用 |
| **7** | Do's and Don'ts | 各 5–8 条，**具体到可执行** | 写"保持简洁"（不可执行）；应写"卡片只用阴影不用边框" |
| **8** | Responsive Behavior | 断点值、各断点下的布局变化、触控目标尺寸 | 缺移动端；或只写"适配手机" |
| **9** | Agent Prompt Guide | 给 agent 的 3–5 条生成指令 + 一段可直接用的 prompt 模板 | 这章最常被漏，但它是"可执行"的关键 |

**篇幅参考**：一份合格 DESIGN.md 约 **230–370 行**（本地 54 份实测区间）。低于 150 行通常不够具体。

## 四、项目类型 → 风格推荐（选风格先看场景）

| 项目类型 | 推荐风格 | 理由 |
|---|---|---|
| SaaS 官网 / Landing page | **Stripe / Vercel / Linear** | 经典高转化结构，简洁专业 |
| 开发者工具 / 技术产品 | **Vercel / Cursor / Raycast / Supabase** | 暗色、代码友好、极客气质 |
| AI 产品 / Chat UI | **Claude / Mistral / ElevenLabs** | AI 原生语言，温暖或未来感 |
| 金融科技 | **Stripe / Revolut / Coinbase** | 信任、精密、数据密集 |
| 效率工具 / 生产力 | **Notion / Linear / Superhuman** | 极简、高密度、键盘优先 |
| 电商 / 消费品牌 | **Airbnb / Apple / Spotify** | 视觉驱动、大图、情感化 |
| 内部后台 / Dashboard | **Sentry / PostHog / ClickHouse** | 数据密集、暗色仪表盘 |
| 创意 / 设计工具 | **Figma / Framer / Clay** | 大胆配色、动感 |
| 企业级 / B2B | **IBM / HashiCorp / MongoDB** | 稳重、结构化、体系成熟 |

**兜底规则**：用户说"随便/你决定"→ 默认 **Vercel**（干净、现代、专业，最不易出错），并明确告知"我先用 Vercel 风格（简约黑白），不喜欢随时换"。

## 五、何时把 DESIGN.md 作为交付物

| 场景 | 是否产出 DESIGN.md |
|---|---|
| 单页/单图一次性需求 | ❌ 不必，直接做 |
| 多页面产品（≥3 页） | ✅ 先出 DESIGN.md 再动手，避免风格漂移 |
| 用户要求"给我一套规范/设计系统" | ✅ 核心交付物 |
| 用户要"做成 XX 那种感觉" | ✅ 先匹配品牌 DNA，再产出定制版 DESIGN.md |
| 交付给工程团队长期维护 | ✅ 必须，附 token 表 |
| 已有 DESIGN.md 要改 | ✅ 按章增量修改，不重写 |

**产出流程**：
1. 第 2 步 brief 澄清拿到调性/明暗/品牌约束
2. 查 §3 定位气质母本，或查 §4 按项目类型选
3. 用 `design-tokens.md` 的数值体系填充具体值（色阶 10 档、字阶 3–5 种、间距 8 倍数）
4. 按 §2 九章骨架成文
5. 第 6 步自检：每章是否有具体数值？Do/Don't 是否可执行？

## 六、写 DESIGN.md 的四条纪律

1. **数值优先于形容词**。"圆角 10px，全站统一" 优于 "圆角柔和"。
2. **每色必有角色**。没有用途的色值就是噪音，删掉。
3. **四态齐全**。任何交互组件必须写清 default / hover / active / disabled（表单再加 error）。
4. **Don'ts 比 Do's 更重要**。Do's 说方向，Don'ts 防跑偏——agent 最容易犯的错都在 Don'ts 里。
