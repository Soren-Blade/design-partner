# 03 · 后台表格

## 任务（一句话）

为运营后台的「任务列表」设计一张 12 列数据表，让运营在 1280px 宽屏上完成筛选、排序与批量处理而不横向滚动。

## 目标用户与场景

- 用户：一线运营，日均处理 200+ 条任务，键盘与鼠标混用。
- 场景：早班先筛「失败 + 今日」，再逐条重试；月末批量导出。
- 前置认知：熟悉 Excel，但不会读 API 字段名；对「批量删除」高度警惕。

## 硬约束

- 载体：Web 后台，内容区 1280px 起，最大 1600px；表头吸顶，首列与操作列固定。
- 品牌：中性企业风格，沿用既有 token；状态色不得单独承载语义。
- 合规：WCAG 2.2 AA（表头 `scope`、键盘可达、焦点可见、排序状态可播报）；批量危险操作二次确认；导出需权限校验提示。
- 交付：默认态 + 筛选态 + 空结果态 + 加载态；行高 ≥44px，数字右对齐、文本左对齐。

## 必须回答的 3 个问题

1. 首屏必须保留哪 5 列？其余列如何在不横向滚动的条件下可达？
2. 批量操作中的危险动作如何确认，才能防误触又不拖慢日常？
3. 「筛选后无结果」与「本来就没有数据」在视觉和文案上如何区分？
