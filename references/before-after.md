# 改稿案例（Before / After）

> 快照 2026-11-19 · 适用：网页 / 落地页 / 海报 / 长图 / 演示文稿 / 表格 / 后台 / 移动端 / 暗色
> 24 组「病稿 → 诊断 → 改稿 → 为什么更好 → 代价与边界」。每组只改一条主线，数值口径统一见 §0。

## §0 立场：改稿不是把参数调对，是换一个更好的结构

分工：本文件只管「同一方案改前改后」；**方案之间**选哪个用 `comparison-protocol.md`，五轴判据见 `taste-criteria.md` §8，受众与禁忌见 `user-modeling.md`，数值一律以 `numeric-truth.md` §1 为准。

**五条工作定义**

1. **改稿的最小单位是结构。** 对齐方式、栏数、容器、信息顺序、颜色角色——任一项变了才算改稿；把 14px 改成 16px 只是调参。
2. **一次只改一条主线。** 每组只给一条主改法。同时改五处，读者无法归因，也无法在下个项目复用。
3. **每个改法都要付代价。** 「代价与边界」不是免责声明：不写清什么时候不成立，这条经验就不能复用。
4. **数值只用一套口径。** 不把 1.2 与 1.5 两套阶梯混进同一屏；不把「看起来舒服」写成 px。
5. **「为什么更好」必须落在机制上。** 视觉重量、扫读路径、对比关系、认知负荷，四选一；「更高级 / 更大气 / 更有质感」不算理由。

**数值口径**（本文件全部案例共用）

| 项 | 口径 |

| 屏显字号 | 12 / 14 / 16 / 20 / 24 / 32 / 40 / 48 / 64；网页正文 16，后台正文 14 |

## 一 · 网页与落地页（8 组）
### 案例 1｜网页 · 落地页首屏｜SaaS 试用页把标签、标题、副标、双按钮、插画全部居中堆叠
**1 · 病稿**
- 视口 1440×900，版心 1200；导航高 72；首屏以下内容被裁掉。
- 小标签 12px、全大写、字距 +0.12em、主色；H1 56px 两行，行宽 900；副标 18px 三行，行宽 720。
- 两个按钮均为实心：主色「免费试用」与深灰「预约演示」，各 160×48，间距 16。
- 插画 560×420 居中，高饱和蓝紫渐变；H1 与插画在灰度图上的明度接近。
- 所有元素各自居中；副标题三行形成左右双锯齿。

```text
首屏 1440×900 / 版心 1200
├ 导航 72，logo 左、菜单右
├ 小标签 12（居中，字距 +0.12em）
├ H1 56 / 2 行（居中，行宽 900）
├ 副标 18 / 3 行（居中，行宽 720）
├ [主按钮 160×48] [次按钮 160×48]（间距 16）
├ 插画 560×420（居中）
└ 信任条 y=880，被首屏裁掉
```

**2 · 诊断**
- **判据 J1**：H1 与 560×420 的高饱和插画争夺第一焦点，视线在两者之间来回；灰度测试下两者明度差 <10%。
- 病灶一：五个元素五条中轴，眼睛每读一行都要重新找起点；副标居中且三行不等长，两侧锯齿放大这种不稳定。
- 病灶二：两个按钮都是实心、同尺寸、同重量，等于告诉用户「两个都是主操作」；选择从「做 / 不做」变成「三选一」。
- 病灶三：小标签用字距加主色「做层级」，但它不承载信息，是纯装饰；主色同时出现在标签、按钮、插画高光三处，失去「行动色」的角色。

**3 · 改稿**

| 改哪一笔 | 病稿 | 改后 |
|---|---|---|
| 结构 / 栏数 | 单列居中堆叠 | 两栏 7:5：左 690 文字，右 486 插画，gutter 24；版心 1200 |
| 对齐 | 全部居中 | 文字左对齐到 x=0 一条轴；插画右栏顶对齐 H1 基线 |
| 字号阶梯 | 标签 12 / H1 56 / 副标 18 | 标签 14（写「面向 20–200 人团队」）/ H1 48、行高 56 / 导语 20、行高 32 / 按钮 16 |
| 间距 | 24 / 40 / 56 混用 | 标签→H1 16；H1→导语 24；导语→CTA 32；导航→内容 96 |
| 颜色角色 | 主色用于标签、两个按钮、插画高光 | 主色只给主按钮；次按钮改 1px 边线加文字色；插画去饱和 20% |
| 信息顺序 | 标签→H1→副标→双按钮→插画 | 给谁→结果→怎么做→主行动→风险解除（「14 天免费，无需信用卡」14px） |
| 移动端 | 同比例缩小 | 单列：H1 32/40，按钮全宽 48，插画移到 CTA 之后 |

**4 · 为什么更好**

左对齐把五次「重新定位」压成一条垂直扫读线；插画从第二焦点降为证据，H1 成为唯一最重元素——视线 0.5 秒落在「得到什么」，再沿同一条轴走到按钮。

**5 · 代价与边界**

这个改法要求你有一句能独立成立的结果句；如果品牌靠居中对称建立仪式感（婚礼、纪念、高奢），左对齐会削弱庄重。纯图片主导的品牌页也不适合右栏插画，可改为全幅图加左下文字块，仍然是单轴。移动端把图放在 CTA 之后，会让首屏更「干」，但保证主张与行动在 900px 内完成。
### 案例 2｜网页 · 功能入口｜三张等宽等高的能力卡，三个图标三种颜色
**1 · 病稿**
- 版心 1200，三卡各 373 宽、280 高，gap 24；卡内居中：48px 线性图标、20px 标题、14px 三行说明、底部「了解更多 →」。
- 图标底色分别为蓝、绿、橙，各占 48×48 圆角方块；卡片 1px 边线加 4px 圆角。
- 三卡等高，正文行数 2/3/2，导致第三卡底部空 24px。
**2 · 诊断**
- **判据 J1**：三张同尺寸、同饱和度的卡在灰度下完全等价，读者无法判断先读哪张；「三个都重要」被编码成「三个都不重要」。
- 病灶一：图标三色没有任何分类含义，只是装饰；同一套界面里颜色不携带信息，就只剩噪音。
- 病灶二：三个「了解更多」把一次选择拆成三次决策；每张卡都是完整闭环，页面没有主路径。
- 病灶三：等高卡片强迫短文案留白、长文案换行，卡内节奏由容器决定，而不是由内容决定。

**3 · 改稿**

| 改哪一笔 | 病稿 | 改后 |
|---|---|---|
| 结构 / 栏数 | 三等分 3×373 | 7:5 非对称：主卡 690×296，右栏两张 486×136 横卡，gap 24 |
| 对齐 | 卡内全部居中 | 卡内左对齐；主卡图 280 宽居左、文字居右；辅助卡删图标位，文字从 x=24 起 |
| 字号阶梯 | 图标 48 / 标题 20 / 正文 14 | 主卡标题 24/32、正文 16/28；辅卡标题 16/24、正文 14/22；区块标题 32/40 |
| 间距 | 卡 padding 24，gap 24 | 主卡 padding 32，辅卡 padding 24；卡间 24；区块上下 96 |
| 颜色角色 | 三图标三色 | 无图标底色；主色只给主卡一个按钮；辅卡无按钮，整行可点 |
| 信息顺序 | 三个并列能力加三个 CTA | 最独特能力（主卡）→ 两个补充能力（辅卡）→ 一个总文字链「查看全部能力」 |

**4 · 为什么更好**
7 栏主卡成为页面上唯一的孤立项（Von Restorff），读者 3 秒内知道先读哪；三个决策点收敛为一个行动加两个了解入口，选择成本从三选一降为「做 / 不做」。

**5 · 代价与边界**

如果三项确实同权且可独立购买（三档定价、三种套餐），不要伪造主次——改用逐项对比表。主卡需要一张能扛住 690px 宽的图，否则大卡片只是更空的卡片。辅助卡去掉按钮后，点击热区必须覆盖整行，并在 hover 与 focus 时给出整行反馈。
### 案例 3｜网页 · 首屏｜全屏轮播 5 张，每 5 秒自动切换
**1 · 病稿**
- 首屏 100vh；5 张全幅照片，每张叠 40px 居中白字 H2 和主色 CTA；自动播放 5s，底部圆点，左右箭头 hover 才出现。
- 照片明度差异大：最亮一张白字实测 2.1:1，最暗一张 4.8:1；无暂停按钮。
- 第 2–5 张的 CTA 文案各不相同（试用 / 预约 / 下载 / 报名），指向四个落地页。
**2 · 诊断**
- **判据 J1 + J6**：照片、40px 白字、CTA 三者在同一帧里争夺重量；白字对比度随照片变化，颜色不再可控。
- 病灶一：每 5 秒重置一次阅读。读者刚建立「这是什么」，画面就换了；记忆点归零，只留下动画成本。
- 病灶二：违反 WCAG 2.2.2——自动移动超过 5 秒的内容必须可暂停、停止或隐藏；当前没有暂停控件。
- 病灶三：其余四张 slide 承担四个不同目标，实际是把信息架构问题藏进了轮播。

**3 · 改稿**

| 改哪一笔 | 病稿 | 改后 |
|---|---|---|
| 结构 | 5 帧自动轮播 | 1 帧静态主视觉加 1 条证据带（3 个数字 / 客户 / 一句评价） |
| 对齐 | 全幅图加居中白字 | 全幅图加 60% 暗色 scrim，文字左对齐在 640 栏、距左 96 |
| 字号阶梯 | H2 40 / CTA 16 | H1 48/56 / 导语 20/32 / CTA 16 / 证据数字 32、说明 14 |
| 间距 | 圆点压在图上 | 文字块内 16 / 24 / 32；主视觉与证据带之间 64 |
| 颜色角色 | 白字直接压图 | scrim 后白字在最亮像素 ≥4.5:1；主色只给唯一 CTA |
| 顺序 | 5 个并列主张 | 一个主张 → 一个行动 → 三个证据；其余四个主题移到二级页的静态入口卡（3 列 gap 24） |

**4 · 为什么更好**
静态帧不会在读者读到一半时重置，主张才有机会被记住；把「自动播放」换成「用户发起」，控制权回到读者，也消除了对比度随图片漂移的问题。要曝光多个主题时，三张静态入口卡比五帧轮播更可扫读。

**5 · 代价与边界**

静态首屏对主图质量与文案硬度要求更高，不能靠换图续命；如果五个活动都必须首屏曝光，那是运营政治而非设计问题——轮播是妥协，应明确标注「临时」。图片主导的品牌（酒店、时尚）可保留全幅图，但文字块要固定在同一位置并加 scrim，不能每帧换对齐。
### 案例 4｜网页 · 功能页｜灰字同时当「次要说明」「分组标题」「禁用态」
**1 · 病稿**
- 12 条能力平铺，每条：能力名 16px #1A1A1A、说明 14px #999999；三个分组标题也是 14px #999、加粗。
- 分组标题与上一条说明间距 24，与组内首条间距 24；组间与组内距离相同。
- 禁用项用 #BFBFBF；引用来源用 #999；正文里强调词用 #999 加粗。
**2 · 诊断**
- **判据 J2 + J3**：灰色同时承担三种语义（次要、分组、禁用），颜色超载；分组标题与说明同字号同色，邻近性被颜色抹平。
- 病灶一：#999 on #FFF 实测 2.85:1，正文级文字不达 WCAG 1.4.3 的 4.5:1。
- 病灶二：组间 24 与组内 24 相等，读者无法用距离判断「这四条是一组」；分组只剩一个「加粗」的微弱信号。
- 病灶三：强调词用灰色加粗，等于把「重点」降级为「更淡」，违反强调的方向。

**3 · 改稿**

| 改哪一笔 | 病稿 | 改后 |
|---|---|---|
| 颜色角色 | 灰承担次要 / 分组 / 禁用 / 强调 | 只留两级：主文字 #1A1A1A（17.4:1）、次文字 #595959（7.0:1）；删 #999 与 #BFBFBF 的正文用法 |
| 字号阶梯 | 分组 14 等于说明 14 | 分组标题 20/28 semibold；能力名 16/24；说明 14/22；条目名与说明差 2px 以上 |
| 间距 | 组间等于组内等于 24 | 组间 64，组内首行 24，条目间 16（组间与组内为 4:1） |
| 结构 | 12 条平铺 | 3 组 × 4 条；每组一个 20px 标题加一句 14px 组说明 |
| 辅助 | 无 | 每条前 20px 勾选图标，单色主色；图标不单独承载信息 |
| 强调 | 灰字加粗 | 强调改 600 字重加主文字色；不用颜色深浅表达重点 |

**4 · 为什么更好**
分组由「距离加字号」两个通道共同编码，颜色退回「主 / 次」二元角色；读者不再需要猜「这块灰字是标题还是注释」，扫读时每一组有明确入口。

**5 · 代价与边界**

长文档里灰色能降低视觉噪音，全删会显得硬；可以保留唯一一档「元数据灰」，但必须 ≥4.5:1（#767676 约 4.54:1）。品牌若规定浅灰正文，应改为浅底深字，而不是把正文调到 3:1 以下。禁用态不靠颜色单独表达，需同时降低不透明度或加锁图标。
### 案例 5｜网页 · 产品侧栏｜6 个无文字图标，靠 hover tooltip 解释
**1 · 病稿**
- 左侧栏 72px 宽，6 个 24px 线性图标竖排，间距 32；hover 400ms 后出现 tooltip；选中态只换图标颜色。
- 图标分别为：房子、九宫格、闪电、柱状图、两个人、齿轮。
- 主内容从 x=72 开始；图标点击区 40×40。
**2 · 诊断**
- **判据 J4（L1 组织）**：闪电、九宫格、柱状图三者在语义上都能指向「自动化 / 应用 / 分析」，图标无法自解释，识别退化为回忆。
- 病灶一：hover 才给文字，触屏与键盘用户拿不到同样的信息；tooltip 也不能替代可访问名称。
- 病灶二：72px 栏宽让主内容左移、与图标列形成一条无用的窄带；点击区 40×40 低于 44×44 的触控建议。
- 病灶三：选中态只靠颜色，3:1 对比与非颜色线索都缺。

**3 · 改稿**

| 改哪一笔 | 病稿 | 改后 |
|---|---|---|
| 结构 / 宽度 | 72px 纯图标 | 240px：20px 图标加 14px 文字，行高 40，左 padding 16 |
| 对齐 | 图标居中，无文字轴 | 图标固定在 x=16，文字从 x=48 起；一级项共享一条左轴 |
| 字号阶梯 | 无 | 一级项 14/40，分组标签 12/16（字距 +0.04em），不抢一级 |
| 间距 | 图标间距 32 | 项间 4，组间 24；栏顶 24，栏底 16 |
| 颜色角色 | 选中只换图标色 | 选中等于 3px 左侧条加 #F0F4FF 表面加主文字；hover 只加表面 |
| 顺序 | 6 个平级 | 6 个一级保留；把「设置」内的 4 个二级项收进展开组；移动端底部 5 项、12px 标签 |

**4 · 为什么更好**
文字把「回忆图标含义」变成「一次竖扫识别」；240px 固定栏形成稳定左轴，主内容与导航各有一条边。选中态同时用位置（左条）、表面、文字色三种线索，不再依赖单一颜色。

**5 · 代价与边界**

240px 在 1280 笔记本上会挤压内容；若确实空间紧张，用 72px 图标加首屏默认展开的标签，而不是 hover tooltip。专家工具（IDE、剪辑软件）可以保留纯图标，但必须支持自定义与始终可见的标签。无论哪种形态，每个图标都要有可访问名称。
### 案例 6｜网页 · 注册表单｜9 个字段，标签右对齐 120px 列
**1 · 病稿**
- 640 宽卡片，标签右对齐到 120px 列，输入框 320 宽；9 个字段单列，字段间距 16。
- 标签与输入框间距 8，部分字段因标签过长被截断成「联系方式（手…」；必填星号在标签左侧。
- 提交按钮 320 宽，与输入框左对齐；帮助文字 12px #999。
**2 · 诊断**
- **判据 J5（form-table.md §2.1）**：顶对齐是默认；右对齐只在「字段多、追求密度」的 B 端成立。这里 9 个字段、面向新用户，右对齐让每个标签起点参差，眼睛在 120px 标签列与 320px 输入框之间横向往返。
- 病灶一：标签被截断，说明列宽由「最长标签」而不是内容决定；中文标签超过 8 字就该拆字段或写进帮助文字。
- 病灶二：字段宽度全部 320，等于放弃「输入框宽度传达预期长度」这条免费提示；验证码与公司名同宽。
- 病灶三：帮助文字 12px #999（2.85:1）不达 4.5:1，且与错误文案共用灰色，状态不可辨。

**3 · 改稿**

| 改哪一笔 | 病稿 | 改后 |
|---|---|---|
| 对齐 | 标签右对齐 120 列 | 标签顶对齐，与输入框共享 x=0 左轴；标签可两行 |
| 结构 / 宽度 | 单列 320 | 单列 480；字段宽度按内容：姓名 240、手机 240、邮箱 320、公司 320、职位 240、验证码 160 加 96 按钮、密码 320、确认 320、同意 480 |
| 字号阶梯 | 标签 14 / 帮助 12 | 标签 14/22 #333；输入 16/24；帮助 12/18 #595959（7.0:1）；错误 12/18 #B42318 |
| 间距 | 字段 16，标签到控件 8 | 标签到控件 8；字段间 24；组间 32；按钮上 32 |
| 颜色角色 | 灰同时用于帮助与错误 | 帮助 #595959，错误 #B42318 加图标加文案；成功 #067647 |
| 顺序 | 姓名→手机→邮箱→公司→职位→验证码→密码→确认→同意 | 先「你是谁」（姓名 / 手机 / 邮箱）→「你在哪家公司」（公司 / 职位）→「验证」（验证码 / 密码 / 确认）→「同意」 |

**4 · 为什么更好**
标签与输入框共享左轴，视线只上下移动，不再横向找起点；字段宽度传递「这里该填多长」，验证码 160 与公司名 320 一眼可分；顶对齐允许长标签换行，中文不再被截断。

**5 · 代价与边界**

垂直高度增加约 25%，首屏可见字段变少；如果这是密集后台且字段超过 7 个，右对齐仍然合理——但一个产品只允许一种标签对齐，混用会让用户每次重新找标签。移动端必须顶对齐并全宽，48 高输入框。
### 案例 7｜网页 · CTA 区｜三个实心按钮，三种主色
**1 · 病稿**
- 首屏下方 CTA 区：蓝实心「立即购买」、绿实心「预约演示」、橙实心「下载白皮书」，各 160×48，gap 16，水平居中。
- 三个按钮圆角 8、白字 16、阴影相同；品牌主色为蓝，绿与橙来自「语义色板」。
- 按钮下方没有任何解释文字。
**2 · 诊断**
- **判据 J6**：绿在系统里表示「成功」、橙表示「警告」，这里却用来表示「另一种行动」，语义色被降格为装饰色。
- 病灶一：三个实心、同尺寸、同阴影的按钮等于三个主操作；视觉重量完全相等，用户必须读完三个词才能决策。
- 病灶二：等距并排加相同尺寸，误点成本高；没有「更容易命中的主目标」。
- 病灶三：品牌蓝被两个语义色稀释，页面上再出现真正的成功或警告时，读者已经不信颜色。

**3 · 改稿**

| 改哪一笔 | 病稿 | 改后 |
|---|---|---|
| 层级 | 3 个实心 | 1 主（实心 200×48）加 1 次（1px 边线 48 高）加 1 文字链（14px 下划线） |
| 颜色角色 | 蓝 / 绿 / 橙都表示行动 | 主色 #1F5EFF（白字 5.1:1）只给主按钮与链接；绿 / 橙 / 红只留给系统状态 |
| 间距 | gap 16，居中 | 按钮组左对齐；主到次 gap 12；文字链距按钮组 24 |
| 字号 | 16 | 主 / 次 16/24；文字链 14/22；按钮内左右 padding 24 |
| 顺序 | 购买 / 演示 / 白皮书 | 主行动 → 次行动 → 低承诺入口（白皮书） |
| 移动端 | 并排 | 主按钮全宽 48；次按钮全宽 ghost；文字链左对齐，距 16 |

**4 · 为什么更好**
视觉重量序列恢复为「实心大于边线大于文字」，读者不需要比较三个色块；决策从「三选一」降为「做 / 不做」，低承诺入口仍保留但不争夺第一眼。

**5 · 代价与边界**

如果三个动作服务三类人群（购买 / 试用 / 合作），把它们塞进同一屏本身就是信息架构问题，应拆成三个入口区块，而不是靠按钮颜色区分。主次不能只靠颜色，必须同时有填充与边线差异（色盲与灰度打印）。品牌若有多主色，仍只允许一个「行动色」，其余做主色阶。
### 案例 8｜网页 · 案例列表｜9 张等大图卡，标题只在 hover 出现
**1 · 病稿**
- 3×3 网格，卡片 373×240，纯图；标题、客户名、结果只在 hover 浮层出现；浮层为 90% 黑底白字 14px。
- 移动端整块图可点，但没有任何文字；键盘 focus 无浮层。
- 九张图明度接近，均为冷色调办公场景。
**2 · 诊断**
- **判据 J4（L2 顺序）**：九张等大图没有起点，读者只能逐张悬停；选择动作从「读标题」变成「猜图」。
- 病灶一：关键信息只在 hover，触屏与键盘用户直接丢失；即便桌面端，WCAG 1.4.13 也要求悬停内容可关闭、可悬停、可持久。
- 病灶二：九张图等权，没有「先看哪个案例」的引导；页面的信息价值被压成图片墙。
- 病灶三：标题不常显，SEO 与分享卡片也拿不到文本。

**3 · 改稿**

| 改哪一笔 | 病稿 | 改后 |
|---|---|---|
| 结构 / 栏数 | 3×3 等大 | 1 条 featured（图 690×460 加文 486）加 2 列 8 条（各 584 宽） |
| 对齐 | 图占满卡片 | featured 图左、文字右；小卡图在上、文字在下，全部左对齐 |
| 字号阶梯 | hover 14 | featured 标题 24/32、结果 16/28、标签 12；小卡标题 16/24、客户 14/22 |
| 间距 | gap 24 | featured 与网格间 64；小卡 gap 32；卡 padding 24 |
| 颜色角色 | 浮层黑底白字 | 无浮层；标题常显于图上（40% 底部渐变）或图下；hover 只做 2% 抬升 |
| 顺序 | 9 个并列 | 1 个主案例加 8 个按行业 / 结果排序；每条：客户 → 做了什么 → 结果数字 |

**4 · 为什么更好**
信息从「隐藏」回到「可扫」，读者用标题与结果数字筛选，而不是逐张悬停；1 加 8 的结构给出唯一入口，九宫格从「图片墙」变成「有主张的索引」。

**5 · 代价与边界**

常显文字让卡片变高，首屏可见条目从 9 降到 4–6；如果图片本身就是作品（摄影、视觉设计），应让图主导，但标题仍需常显在图下或图上。hover 只做位移，不承载信息；移动端点击区覆盖整卡。

## 二 · 海报与长图（4 组）

> 共同病灶：信息按「版面还剩哪里」摆放，不按「读者先问什么」排序。
### 案例 9｜海报 · 活动｜标题居中，时间、地点、二维码分居四角
**1 · 病稿**
- A2 420×594；主标题 72pt 居中两行；logo 40×40 左上距边 20；时间 18pt 右上；地点 18pt 左下；二维码 60×60 右下、距裁切线 8mm；主办方 12pt 底部居中。
- 背景满版径向渐变（蓝紫）加 3 个半透明装饰圆，最大圆直径 260，压在标题右侧。
- 全部信息均为白色，背景最亮处白字对比度约 2.4:1。

```text
A2 420×594 / 四个角落，四条起点
├ logo 40×40（左上，距边 20）
├ 时间 18pt（右上，距边 20）
├ 主标题 72pt（居中，两行）
├ 地点 18pt（左下）
├ 二维码 60×60（右下，距裁切线 8mm）
├ 主办方 12pt（底部居中）
└ 背景：满版渐变加 3 个装饰圆（最重）
```

**2 · 诊断**
- **判据 J1**：装饰圆直径 260、饱和度高于标题，成为事实上的第一焦点；标题、二维码、时间三个信息块各自抢一个角。
- 病灶一：四个角落等于四条起点，读者读完标题后要跳三次才能拼出「何时、何地、怎么报名」，信息顺序被版面位置打散。
- 病灶二：时间与地点同为 18pt，读者无法一眼分出先看哪个；二维码与主办方都在底部，却没有说明文字。
- 病灶三：二维码距裁切线 8mm，等于出血 3mm 加安全区 5mm 全部用满，裁切误差 ±1mm 就会切到码；白字压渐变的对比度也不达 4.5:1。

**3 · 改稿**

| 改哪一笔 | 病稿 | 改后 |
|---|---|---|
| 结构 | 四角散落 | 单轴三段：标题区 40–200mm、信息区 200–460mm、行动区 460–530mm |
| 对齐 | 各自居中或贴角 | 全部左对齐到 x=40；二维码在右，与信息区右缘对齐 |
| 字号阶梯 | 标题 72 / 信息 18 / 底部 12 | 标题 96（行高 0.95，两行）/ 信息值 28 / 标签 18 / 底部 12 |
| 间距 | 无尺度 | 左右边距 40、上 40、下 64；标题到信息 40；信息行距 12；二维码距边 ≥28mm |
| 颜色角色 | 白字压渐变加三装饰色 | 背景 #F5F1E8；文字 #1A1A1A；强调 #C8452D 只给日期数字与「扫码报名」 |
| 顺序 | 标题→时间→地点→二维码 | 是什么→谁讲→何时何地→怎么报名；二维码旁配 18pt 说明 |

**4 · 为什么更好**

单轴把「四个角落」变成「一条阅读线」，读者按「是什么→谁讲→何时何地→怎么报名」一次走完；删掉装饰圆后标题成为唯一最重元素，留白回到 40–60%，信息块之间靠 40mm 的组间距自然分组。

**5 · 代价与边界**

单色底加大留白在昏暗场地不如满版图显眼；若海报的核心任务是「3 米外抓眼球」（音乐节、大促），保留满版图，但信息压成底部一条信息带，仍是单轴。二维码的安全区不能省：出血 3mm 加安全内缩 5mm 加裁切误差 1mm，至少留 9mm。观众需要扫码时，二维码边长建议 ≥60mm，并配文字说明。
### 案例 10｜长图 · 信息图｜8 段同构，读者在第 3 段失去位置感
**1 · 病稿**
- 1080×7200；8 段，每段 900 高；统一白底；每段：44px 小标题加 3 段 32px 正文加一张 960×540 图。
- 段间距 96，段内行高 44，图与文间距 24；没有任何章节编号、色块或分隔。
- 全图 8 个标题同字号、同字重、同颜色。
**2 · 诊断**
- **判据 J3 + J5**：8 个同构段之间没有「组间大于组内」的差别，读者无法用距离判断章节；长图没有气口，等于一堵墙。
- 病灶一：32px 正文在 1080 宽下低于「正文 ≥44px」的长图底线，手机端缩放后更难读。
- 病灶二：所有标题同级，等于没有章节；读者滑到第 5 段时既不知道进度，也不知道还剩多少。
- 病灶三：图文比恒定 16:9、图永远全宽，节奏没有强弱变化，连续阅读疲劳。

**3 · 改稿**

| 改哪一笔 | 病稿 | 改后 |
|---|---|---|
| 结构 | 8 段平铺 | 4 章 × 2 节；每章首插入 1080×480 停顿带 |
| 字号阶梯 | 标题 44 / 正文 32 | 章标题 96/112、节标题 64/84、正文 44/76、图注 28/40、大数字 132/140 |
| 间距 | 段间 96 | 章间 160、节间 96、段间 64、图注上 16（全部 4 的倍数） |
| 对齐 / 版式 | 全部全宽居中 | 奇数节图全宽 1080×608；偶数节图 720×405 右对齐，左侧 296 放说明 |
| 颜色角色 | 全白底 | 停顿带 #F2EEE8；强调色只给章节数字与关键结论；正文纯黑 |
| 顺序 | 无章节 | 封面（1 屏）→ 4 章（每章 2 节）→ 结论与行动（1 屏）；每 3–5 个信息块一个气口 |

**4 · 为什么更好**
停顿带同时给「章节边界」和「进度锚点」，7200 高的墙变成 4 个可完成的小段；全宽与窄图交替制造呼吸，读者在每章结束时有一次视觉休息，愿意继续下滑。

**5 · 代价与边界**

高度会增加约 1000px，文件更大、加载更慢；说明书、条款、菜谱这类需要恒定密度便于查找的长图，不应加装饰性停顿，用编号与小标题即可。微信首图只露前 3 屏，主张与第一个停顿带必须在前 2160px 内出现。
### 案例 11｜海报 · 促销｜五种字体、四种强调色、描边加阴影
**1 · 病稿**
- 1080×1440；标题书法体 120px、描边 3px 加外阴影 8px；副标圆体 48px；正文黑体 28px；英文手写 36px；价格数字艺术字 3D 倾斜 160px。
- 强调色：红、金、紫、青各占一块；背景径向渐变加光斑加礼花。
- 信息三层混在一起：折扣、利益点、门槛、时间都用相近字号。
**2 · 诊断**
- **判据 J2 + J6**：每个元素都在加描边、阴影、渐变、色块，等于所有元素同时喊；没有对比方向，就没有层级。
- 病灶一：5 种字体让品牌识别碎片化；书法标题与圆体副标的气质互相抵消。
- 病灶二：金色同时表示「高级」和「折扣」，红色同时表示「促销」和「警告」，颜色不携带稳定含义。
- 病灶三：3px 描边加 8px 阴影压在小字上，笔画粘连；3D 价格倾斜让数字难以核对。

**3 · 改稿**

| 改哪一笔 | 病稿 | 改后 |
|---|---|---|
| 字体 | 5 种 | 1 个家族（思源黑体）加 2 个字重（400 / 700） |
| 字号阶梯 | 120 / 48 / 36 / 28 / 160 | 主张 96/104、价格 132/140（tabular-nums）、利益点 44/60、门槛 28/44 |
| 颜色角色 | 红金紫青加渐变 | 底色 #F7F3EC、文字 #1A1A1A、强调 #D62828；金色只给「会员」标签 1 处 |
| 装饰 | 描边、阴影、光斑、礼花 | 全删；标题无描边无阴影，靠字号与留白建立重量 |
| 对齐 | 元素各自居中或倾斜 | 全部左对齐到 x=72；价格与利益点共享左轴 |
| 顺序 | 信息混排 | 主张（5 折）→ 3 条利益点 → 门槛与时间 → 底部 1080×120 行动带（二维码加开抢时间） |

**4 · 为什么更好**
去掉四种装饰后，字号与色块成为唯一的对比手段：96px 主张在缩略图里仍可读，132px 价格只需一眼；两色系统让品牌红重新只表示「行动 / 价格」，不再被背景噪音稀释。

**5 · 代价与边界**

强促销需要「热闹」的心理暗示，极简可能显得不够划算；平台缩略图竞争激烈时，可保留满版红底，但仍限一个字体家族与两级字号。国潮、手作品牌若需要性格，用一款有特征的标题字加一款中性正文，仍限 2 款。价格用 tabular-nums，避免 1 与 7 宽度不一。
### 案例 12｜海报 · 讲座｜12 条信息同为 18pt，从顶部排到 380mm
**1 · 病稿**
- A3 297×420；12 条信息：主题、副题、主讲人、头衔、机构、时间、地点、地址、主办、协办、报名方式、二维码。
- 全部 18pt、同字重、同黑色，行距 8，左对齐 x=36，从 y=60 连续排到 y=380。
- 没有分组线、没有编号、没有字号差；二维码 50×50 混在最后一行文字里。
**2 · 诊断**
- **判据 J4**：12 条等权信息落在同一层，读者无法回答「这是什么、我为什么来、怎么去」；这是 L1 分组缺失，不是字号问题。
- 病灶一：行距 8 小于 18pt 的 1.4 倍（约 25pt），行与行粘连，12 条读起来像一段。
- 病灶二：主讲人、头衔、机构三行连续同貌，读者无法判断哪一行是人名。
- 病灶三：二维码与文字同层，没有「扫码」动作提示；报名方式被埋在最后一行。

**3 · 改稿**

| 改哪一笔 | 病稿 | 改后 |
|---|---|---|
| 结构 | 12 条平铺 | 4 块：主题 / 主讲人 / 时间地点 / 报名；主办协办置底 |
| 字号阶梯 | 全部 18 | 主题 96/92（两行）、副题 42/50、人名 42/50、头衔 28/36、信息值 28/36、标签 18/26、底部 12/18 |
| 间距 | 行距 8，无组距 | 组内 12；块间 40；页边距 40；底部信息与二维码同一基线 |
| 对齐 | 全部左对齐单列 | 主信息左对齐 x=40；时间 / 地点 / 报名做两列：标签列 56、值列 144，列间 12；二维码右对齐 |
| 颜色角色 | 全黑 | 黑加一个强调色，只给日期与「扫码报名」；主讲人姓名用 700 字重 |
| 顺序 | 主题→副题→人→机构→时间→地点→地址→主办→协办→报名 | 为什么来→谁讲→何时何地→怎么报名；主办协办降为页脚 |

**4 · 为什么更好**
12 条压成 4 组（工作记忆一次可握住 4±1 块），读者在 3 米外先读到 96pt 主题，走到 1 米内再读 28pt 的时间地点；行距与组距拉开后，「人名—头衔—机构」自然成团。

**5 · 代价与边界**

学术会议海报要求全部字段（摘要、方法、结论）时，不能靠删信息解决；改用两栏：左 2/3 内容、右 1/3 元数据，仍保持三级。赞助商 logo 必须单独设「赞助区」，不要混进主信息轴。二维码边长与说明文字要按扫描距离给足，50mm 只适合 1 米内。

## 三 · 演示文稿（4 组）

> 共同病灶：每页都在「放内容」，没有一页在「下判断」。
### 案例 13｜演示 · 汇报页｜每页 6 条等长 bullet，连续 10 页同构
**1 · 病稿**
- 16:9 1920×1080；标题 28pt 名词短语「项目进展」；正文 6 条 bullet，24pt，每条 1–2 行，占满左侧 2/3；右侧空白。
- 10 页全部同结构：标题加 6 条 bullet，无图、无数字、无强调；页脚 14pt。
- 每条 bullet 都是「主题词：一句描述」，如「用户增长：继续推进拉新」。

**2 · 诊断**
- **判据 J5（presentation-design.md §3.0）**：正文 24pt 刚过现场底线，但 6 条乘 2 行等于 12 行文字，观众读字速度高于讲者语速，注意力被文字抢走。
- 病灶一：标题是名词短语，不是结论；观众读完标题不知道这一页要证明什么。
- 病灶二：6 条等长、同字重、同缩进，没有主次；每条都是「主题」而不是「证据」。
- 病灶三：10 页同构，没有节奏；听众在第 4 页后进入「读稿—走神」循环。

**3 · 改稿**

| 改哪一笔 | 病稿 | 改后 |
|---|---|---|
| 标题 | 「项目进展」28pt 名词 | 完整句 32/44：「留存下降主要来自首次 7 天的引导缺口」 |
| 信息量 | 6 条 bullet | 3 条证据（24/36，每条 ≤1 行）；其余 3 条移入讲稿或附录 |
| 证据形态 | 纯文字 | 一条证据配一个 60pt 数字或一张图；图占版面 50–60% |
| 间距 | 行距默认，条目紧排 | 标题到正文 48；条目间 24；正文行距 36；页脚 16 |
| 版式 | 10 页同构 | 3 种页型：论断页 / 证据页（图为主）/ 行动页 |
| 颜色角色 | 全黑加蓝色项目符号 | 黑加品牌蓝，蓝只给关键数字与结论词；项目符号改 4px 方块，单色 |

**4 · 为什么更好**

标题承载结论，观众读一行就懂这一页在说什么；三条证据在 24pt 下可被扫读，细节由讲者口头补充——文字从「讲稿」退回「证据」。三种页型建立节奏，听众知道何时该看、何时该听。

**5 · 代价与边界**

需要讲者准备口头内容，不能照念；如果 deck 要独立阅读（slidedoc），不能删 bullet，应改为阅读型版式：18–20pt、分栏、每页一个完整小节。客户要求「信息全」时，把全量放附录，正文仍只留三条。
### 案例 14｜演示 · 整套 deck｜18 页 5 种版式、4 种字体、每页一个装饰色
**1 · 病稿**
- 封面居中、目录两栏、内容页左图右文、数据页满版表格、结尾页居中；每页左右边距在 48 / 64 / 80 之间跳。
- 字体：宋体标题、黑体正文、英文 Calibri、数字 Impact；主色蓝，另有 6 个「每页换一个」的装饰色。
- 图表各自带边框、渐变、图例位置不一；页码有时在右下、有时在左下。
**2 · 诊断**
- **判据 J3 + J6**：边距、页码、图表样式没有共同尺度，观众每翻一页都要重新学习版式；装饰色不携带信息，只是每页换个心情。
- 病灶一：4 种字体让「同级不同貌」；宋体标题与黑体正文的笔画重量不匹配，标题反而显轻。
- 病灶二：5 种版式没有共同栏格，图文比例每次重算；数据页的满版表与内容页的左图右文无法共享视线起点。
- 病灶三：每页一个装饰色，真正的强调色出现时已失效。

**3 · 改稿**

| 改哪一笔 | 病稿 | 改后 |
|---|---|---|
| 网格 | 边距 48 / 64 / 80 混用 | 12 栏 × 8 行：栏宽 122、gutter 24、边距 96；标题基线固定在 y=96 |
| 版式 | 5 种 | 3 种：封面 / 内容（左文右图或上文下图）/ 数据（一图一结论） |
| 字体 | 4 种 | 2 种：中文思源黑体加英文 Inter；标题 700、正文 400 |
| 字号阶梯 | 无统一 | 16 / 20 / 24 / 32 / 44 / 60；页脚 16，标题 32–44，封面 60 |
| 颜色角色 | 主色加 6 个装饰色 | 3 个 token：墨黑 #1A1A1A、品牌蓝 #1F5EFF、中性灰 #6B6B6B；每页最多 1 个强调色 |
| 图表 | 各自带框 / 渐变 / 图例 | 去边框、去渐变、统一色板（蓝加灰阶）、图例直接标注 |

**4 · 为什么更好**
母版把「每页重新排版」变成「往格子里填」，观众不需要在页间重新学习版式；字体与颜色收敛后，唯一的强调色才产生 Von Restorff 效应——它出现的那一页，观众知道「这页最重要」。

**5 · 代价与边界**

强叙事 deck（发布会、创意提案）需要破格页；规则应是「每 10 页允许 1 次破格」，破格只破版式，不破字体与色板。模板化过度会让内容趋同——母版管位置，不管观点。客户品牌字体必须保留时，用它做标题，正文换中性字体，仍限 2 款。
### 案例 15｜演示 · 数据页｜14×9 表格截图塞满一页，6 个红格
**1 · 病稿**
- 一页 1920×1080 放入 14 行 × 9 列表格截图，等效字号 12pt；带 UI 边框、滚动条、筛选器。
- 6 个单元格用红底标出；标题「三季度数据」28pt；无结论、无注释、无来源。

**2 · 诊断**
- **判据 J5**：12pt 远低于现场演示 24pt 底线，后排观众只能看到「有一张表」；截图里的滚动条与边框是纯噪音。
- 病灶一：14×9 超出工作记忆，观众既读不完也听不进；6 个红格等于 6 个重点，等于没有重点。
- 病灶二：标题是「三季度数据」而不是结论，观众不知道这张表要证明什么。
- 病灶三：表格截图不可缩放、不可高亮、不可访问，投影下最细的 1px 线直接消失。

**3 · 改稿**

| 改哪一笔 | 病稿 | 改后 |
|---|---|---|
| 结构 | 满版表格 | 一页一图一结论：标题加左图（60%）加右注 3 行 |
| 标题 | 「三季度数据」 | 「华东贡献 62% 增量，但退货率是均值 2.1 倍」32/44 |
| 图形 | 14×9 表 | 100% 堆叠条或散点，只编码一个关系；0 基线，去网格线 |
| 字号 | 等效 12pt | 图内标注 24/32；右注 24/36；附录表 20/28 |
| 颜色 | 6 个红格 | 品牌蓝加灰阶；红色只给 1 个异常点 |
| 顺序 | 表→读者自己找 | 结论→图→3 条注释→附录（全表 9 列） |

**4 · 为什么更好**
观众先得到结论，再验证据；一张图只编码一个关系，24pt 标注可读，右注替讲者说出「所以呢」。全表移到附录，满足「可查」而不牺牲「可讲」。

**5 · 代价与边界**

审计、评审场景需要逐格核对，图会丢精度——保留附录并给二维码或下载链接；如果会议本质是「读稿会」而非演讲，改用 slidedoc（20pt、分页表格）。异常点用红色时，同时加形状或标注，不能只靠颜色。
### 案例 16｜演示 · 封面｜居中大标题加 10% 水印 logo 加英文花体
**1 · 病稿**
- 1920×1080；白底，600px 宽公司 logo 以 10% 不透明度铺满中部；主标题 44pt 居中两行，压在 logo 上；副标 20pt 居中；日期 14pt 右下。

**2 · 诊断**
- **判据 J2**：花体英文与中文标题各自「最大」，两个第一层；水印 logo 在标题下方制造明度噪声，局部文字对比度降到 4.5:1 以下。
- 病灶一：10% logo 水印把整块背景从纯白变成浅灰网，文字边缘对比不稳定，投影后更糊。
- 病灶二：居中标题加右下日期加居中副标，没有任何一条共享轴；读者视线在三个点之间跳。

**3 · 改稿**

| 改哪一笔 | 病稿 | 改后 |
|---|---|---|
| 对齐 | 全部居中 | 左对齐到 x=96 一条轴；logo 左上 96×32 实色 |
| 字号阶梯 | 花体 28 / 主标 44 / 副标 20 / 日期 14 | kicker 16（2026 年度战略发布）/ 主标 60/72 / 副标 24/36 / 底部 16 |
| 结构 | 标题浮在水印上 | 信息块垂直居中偏上（top 300）；底部一条基线放演讲者与日期 |
| 颜色角色 | 白底加 10% 灰水印 | 纯色底；文字 #1A1A1A（17.4:1）；主色只给 kicker 的 4px 短线 |
| 装饰 | 水印、花体英文 | 全删；气质由字体与留白承担 |
| 背景图方案 | 无 | 若用图：满版图加 60–70% scrim，文字仍左对齐，最亮处白字 ≥4.5:1 |

**4 · 为什么更好**
一条左轴加三级字号让封面在 3 秒内给出「谁、讲什么、何时」；删掉水印后文字对比回到 17.4:1，投影可读；花体的「气质」由一款字体和留白承担，不再需要第二套字形来喊。

**5 · 代价与边界**

奢侈、创意品牌可能依赖居中对称的仪式感；此时保留居中，但删水印、只留一个标题层，日期与 logo 放同一条底轴。纯色封面在远距离不够醒目时，用满版图加 60–70% scrim，文字仍左对齐。封面标题必须能和内页标题区区分开，不能同字号。

## 四 · 表格与后台（4 组）

> 共同病灶：把工具当展示，密度与层级同时失控。
### 案例 17｜后台 · 列表页｜12 个筛选器平铺三行，结果表被推到首屏以下
**1 · 病稿**
- 筛选区 3 行 × 4 列等于 12 个控件：关键词、状态、负责人、日期、金额起、金额止、标签、来源、地区、渠道、是否归档、创建人。
- 控件高 32，gap 16；「查询 / 重置」在第三行最右；筛选区总高 240。
- 无「已选条件」提示；结果表从 y=240 开始，1440×900 下首屏只见表头。

```text
列表页顶部 240px
├ 控件 32 / gap 16 / 3 行 = 240
├ 无「已选条件」提示
├ 行1: [关键词][状态][负责人][日期]
├ 行2: [金额起][金额止][标签][来源]
├ 行3: [地区][渠道][是否归档][创建人]   [查询][重置]
├ 12 个控件等权，无主次
└ 结果表从 y=240 开始（首屏只见表头）
```

**2 · 诊断**
- **判据 J5（form-table.md §10）**：查询区一行 3–4 个字段，超过 4 个应折叠；12 个平铺让筛选器反客为主。
- 病灶一：首屏没有数据。用户打开列表页的第一任务是「看数据」，现在第一任务是「读 12 个控件」。
- 病灶二：12 个控件没有分组、没有优先级，每次筛选都要横竖扫两遍；低频条件与高频条件同权。
- 病灶三：已选条件不可见，用户无法确认「我筛了什么」；「查询」与筛选器不同轴，按钮找不到。

**3 · 改稿**

| 改哪一笔 | 病稿 | 改后 |
|---|---|---|
| 结构 | 12 个平铺 | 4 个常驻：关键词 240、状态 160、负责人 160、日期 240；其余 8 个进「更多筛选」抽屉 |
| 对齐 | 第三行右对齐按钮 | 查询区一行：4 控件加主「查询」在左加文字「重置」；控件底边对齐 |
| 间距 | 高 240 | 查询区 ≤96（32 控件加上下 32）；控件 gap 16；与结果区间距 24 |
| 抽屉 | 无 | 480 宽，4 组（归属 / 金额 / 时间 / 标签），底部「应用」；移动端全屏 |
| 状态 | 无已选提示 | 结果区上方 chips 24 高，可单个删除；「清除全部」文字链 |
| 颜色角色 | 无主次 | 主色只给「查询」；「重置」与「清除」为文字链；已选 chip 用表面色 |

**4 · 为什么更好**

首屏恢复「数据为主」，筛选从 12 个降到 4 个常驻，决策时间随之下降；抽屉用 4 组承载 8 个低频条件，把「12 个平铺」变成「4 加 4 组」；chips 让筛选状态可见，不再依赖记忆。

**5 · 代价与边界**

低频条件藏进抽屉会增加一次点击；如果某角色每天要用 8 个条件（财务对账），应保存为「视图」或默认展开该组，而不是每次点开。移动端抽屉改全屏面板，底部「应用」固定。筛选器数量本身是信息架构问题，12 个条件可能说明列表该拆成两个页面。
### 案例 18｜后台 · 数据表｜斑马纹加全边框加数字居中
**1 · 病稿**
- 8 列 × 20 行；行交替 #FFFFFF / #F5F5F5；所有单元格 1px #E0E0E0 全边框；数字居中；表头深蓝底白字 12px。
- 行高 36，单元格 padding 8；名称列 160，金额列 120，日期列 120；无固定列。
- 金额含千分位与两位小数，宋体数字宽度不一；状态列用彩色圆点加 12px 文字。

```text
+------+--------+--------+--------+
| 名称 | 状态   | 金额   | 日期   |  ← 1px 全边框
+------+--------+--------+--------+
| A    | 启用   | 12,300 | 10-01  |  ← 斑马纹 #F5F5F5
| B    | 停用   | 980    | 10-02  |
| C    | 启用   | 1,240  | 10-03  |
+------+--------+--------+--------+
仅示前 4 列；数字居中；行高 36；字号 12
```
**2 · 诊断**
- **判据 J3 + J5**：斑马纹与全边框同时编码行分组，是双重编码；8×20 的网格把数据切碎，视觉噪音压过数据本身。
- 病灶一：数字居中，小数点不对齐，无法纵向比较量级；宋体数字非等宽，1 与 7 宽度不同。
- 病灶二：12px 正文加 36 行高，点击目标与阅读密度都偏紧；表头深蓝底是页面上最重的块，抢了数据。
- 病灶三：状态用彩色圆点，色盲用户无法区分；颜色成了唯一编码。

**3 · 改稿**

| 改哪一笔 | 病稿 | 改后 |
|---|---|---|
| 分隔 | 斑马纹加全边框 | 去斑马纹；去竖线；只留 1px 横线 #EBEBEB；hover 行 #F7F7F7 |
| 对齐 | 数字居中 | 数字右对齐加 tabular-nums；文本左对齐；表头与数据同列对齐 |
| 行高 | 36 | 48（表头同高）；单元格 padding 上下 12、左右 16 |
| 字号 | 12 | 表头 14/22、中等字重；正文 14/22；数字 14/22 tabular |
| 列宽 | 名称 160 / 金额 120 | 名称 240、状态 96、金额 120、日期 120；其余 4 列 120–160；首列固定 |
| 颜色角色 | 表头深蓝加状态彩点 | 表头 #FAFAFA、底边 1px #D9D9D9；状态等于文字加图标，颜色只做辅助 |

**4 · 为什么更好**
横线已足够引导行，去掉竖线与斑马纹后对比度留给数据本身；数字右对齐加等宽数字让量级可纵向扫读；48 行高把点击目标做到 44 以上，表头不再与数据争重。

**5 · 代价与边界**

超宽表（超过 10 列）需要竖线或分组表头，否则列归属不清；只读报表没有 hover 时，斑马纹仍有价值——斑马纹与全边框二选一，不要并用。行高 48 会让单屏行数从 20 降到 12，需要分页或「紧凑」密度切换。
### 案例 19｜后台 · 数据看板｜12 个图各用 5–8 种颜色，两个 3D 饼图
**1 · 病稿**
- 一屏 4×3 网格 12 个图，每个图 5–8 种颜色（红黄绿蓝紫青）；2 个 3D 饼图，1 个双 Y 轴折线。
- 标题 12px，图例 10px；同一蓝色在 3 个图里表示不同类别；无筛选、无时间范围说明。
- 12 个图等大，没有主次；顶部无 KPI。
**2 · 诊断**
- **判据 J6（dataviz.md §3.6 / §10.1）**：颜色没有编码规则，同一蓝色在不同图里指不同类别；彩虹色表达顺序会让读者把「色相」误读成「高低」。
- 病灶一：12 个等大图没有第一眼落点，看板不回答「现在好不好」，只回答「这里有很多图」。
- 病灶二：3D 饼图让扇区面积失真，双 Y 轴让两条线的斜率可被任意解释。
- 病灶三：10px 图例在 1440 屏上不可读，颜色成为唯一区分手段。

**3 · 改稿**

| 改哪一笔 | 病稿 | 改后 |
|---|---|---|
| 结构 | 12 个等大图 | 3 层：顶部 3 个 KPI（数字 40 加同比 14）→ 主图 8 栏 → 辅助图 4 栏 → 底部 6 个 sparkline |
| 图形 | 3D 饼 / 双 Y 轴 | 100% 堆叠条 / 单轴折线；全部 0 基线；删 3D、渐变、阴影 |
| 颜色角色 | 每图 5–8 色 | 1 品牌色加 4 级灰阶加 1 语义红；分类 ≤5 用同色系明度阶，超过 5 用 Carbon 分类色板按序取 |
| 字号 | 标题 12 / 图例 10 | KPI 40/48、图标题 16/24、标注 12/18；图例改为直接标注 |
| 间距 | 网格 gap 16 | 区块间 32；KPI 带与主图 24；底部 sparkline 行 gap 24 |
| 顺序 | 无 | 好坏（KPI）→ 趋势（主图）→ 构成（辅助）→ 细节（sparkline） |

**4 · 为什么更好**
看板有了唯一的「最重」区域（KPI 带），读者 3 秒知道好坏；颜色从装饰变成编码，同一个蓝永远表示同一类别；统一 0 基线与等宽数字让跨图比较成立。

**5 · 代价与边界**

12 个指标都重要时（运营日报），分层会隐藏部分指标；用「可切换的二级看板」解决，不要把 12 个塞回首屏。分类超过 8 类时颜色不可辨，应改为排序条形图或小倍数图。双 Y 轴在极少数「两个量纲必须同屏」的场景可保留，但必须标注两条轴的量纲与来源。
### 案例 20｜后台 · 详情页｜20 个字段等宽两列，关键数字混在中间
**1 · 病稿**
- 详情页 20 个字段，两列各 50%，每列 10 行；label 左 96px、值右；行高 40，每行一条 1px 分隔线。
- 合同金额、到期日、客户名、状态与「创建人 / 更新时间 / 内部 ID」同级同字号 14px。
- 字段等宽：地址与状态同宽，地址换行 3 行，状态右侧空 200px。
**2 · 诊断**
- **判据 J4 + J5**：20 个字段没有分组，找「到期日」要扫 20 行；等宽两列让短字段浪费空间、长字段换行。
- 病灶一：关键数字（金额、到期日）淹没在配置项里，页面不回答「这份合同最要紧的是什么」。
- 病灶二：每行一条分隔线，把页面切成 20 条，扫读破碎；线本身比文字更显眼。
- 病灶三：字段宽度不按内容，地址与状态同宽，读者无法用宽度预期内容长度。

**3 · 改稿**

| 改哪一笔 | 病稿 | 改后 |
|---|---|---|
| 结构 | 20 字段平铺两列 | 三段：概要（4 个关键字段）/ 商务条款（10）/ 系统信息（6） |
| 重点 | 关键字段混在中间 | 顶部 2×2 摘要卡：金额 24/32 tabular、到期日 20/28、客户 20/28、状态 tag 14 |
| 对齐 / 宽度 | label 96 加值右，等宽 50% | definition list：标签 120 左对齐、值左对齐；地址通栏，状态 160，日期 200 |
| 行高 / 分隔 | 行高 40 加每行线 | 行高 40；删逐行线，只在组间用 1px #EBEBEB |
| 间距 | 无组距 | 组内行距 16；组间 48；摘要卡与详情 32 |
| 编辑态 | 同页展开 | 右侧 560 抽屉，按同三段分组、单列；保存与取消固定底部 |

**4 · 为什么更好**
关键数字从 20 行中提出来，成为「第一眼」；三段分组把 20 个字段压成 3 块，找「到期日」从扫 20 行变成扫 3 组；字段宽度传递内容长度，地址不再与状态同宽。

**5 · 代价与边界**

2×2 摘要卡会与下方详情重复字段，必须明确「摘要与全量」的分工或二选一；字段超过 40 个时应改为页签加锚点导航，而不是继续分组。编辑抽屉在窄屏改全屏，保存按钮固定底部，避免长表单滚失。

## 五 · 移动端（2 组）
### 案例 21｜移动 · 首屏｜整页 `transform: scale()` 把 1440 桌面版塞进 375
**1 · 病稿**
- 375 宽视口，根节点 `transform: scale(calc(100vw / 1440))`；桌面版原样渲染：H1 64→16.7，正文 16→4.2，按钮 160×48→41×12.5。
- 导航 6 项横排，下拉用 `:hover` 展开。
**2 · 诊断**
- **判据 J7**：正文 4.2px、热区 41×12.5，同时破「正文 ≥12」与「热区 ≥24×24」两条底线；触屏上 hover 菜单永不出现。

**3 · 改稿**

| 改哪一笔 | 病稿 | 改后 |
|---|---|---|
| 宽度策略 | 等比缩放 | 断点重排：单列，版心 = 视口 − 32 |
| 字号阶梯 | 按比例缩 | H1 32/40、正文 16/26、辅助 12/18 |
| 导航 | 6 项横排 + hover | 底部 4–5 项 + 二级页；触屏无 hover（responsive-layout §17.6） |

**4 · 为什么更好**
把「缩小后还能看」换成「重新决定先给谁看」：一屏只留一个主张与一个行动，字号回到可读区间。

**5 · 代价与边界**
重排要先做内容取舍（常删掉首屏三分之二的次要内容），成本在编辑决策不在 CSS；只作可读存档时可缩放 + 横滚，但要放弃触屏。

### 案例 22｜移动 · 结算页｜固定底栏没让出安全区，键盘弹起后「支付」在键盘后面
**1 · 病稿**
- 375×812，`viewport-fit=cover`；`.paybar{position:fixed;bottom:0;padding:0 16px 8px}`，主按钮高 40。
- 全面屏：指示条压住按钮下缘，最后 1/3 落在手势区，点按落空或触发上滑回桌面。
- 键盘弹起：底栏不动，被键盘整块盖住——金额与「支付」同时消失。

**2 · 诊断**
- **判据 J7**：固定元素必须让出系统手势区；按钮 40 < 44。
- 机制：`env()` 只在 `viewport-fit=cover` 之后、且只在该类设备上非 0，桌面读到就是 0。所以「不写 safe-area」在全面屏上错位，「写死 34px」在无手势条设备上多一条空带——两种都是猜。
- 键盘：`interactive-widget` 默认 `resizes-visual`，只缩视觉视口、布局视口不变，`fixed` 底栏仍在键盘后面（MDN viewport）。

**3 · 改稿**

| 改哪一笔 | 病稿 | 改后 |
|---|---|---|
| 底栏内边距 | `8px` | `calc(8px + env(safe-area-inset-bottom, 0px))`；横屏另补 left/right |
| 按钮 | 高 40、贴边 | 高 48，距指示条 ≥8，热区不与手势区重叠 |
| 键盘 | 靠 `fixed` 顶住 | 键盘出现时把支付按钮移入内容流；或 `overlaysContent` 后整栏上移 `env(keyboard-inset-height)` |

**4 · 为什么更好**
安全区是设备给的环境量，不是设计边距；交给 `env()` 后同一份 CSS 在全面屏、非全面屏、桌面都算对。键盘问题也不是 `z-index` 能修的——被盖住的部分不在布局视口里。

**5 · 代价与边界**
必须真机验证（指示条 + 弹键盘），Chrome 模拟器不带安全区；`calc()` 要给 `0px` 兜底，老 WebView 会整条失效；`fixed` 底栏还要给内容加等量 `padding-bottom`，否则末条被压住；横屏安全区在左右。

## 六 · 暗色（2 组）
### 案例 23｜暗色 · 全站｜`filter: invert(1) hue-rotate(180deg)` 一键出暗色
**1 · 病稿**
- 亮色站一行 CSS 反相：品牌红 `#E5484D` → `#1AB7B2`，白底 logo 变黑块，产品截图肤色发绿，暖灰底变冷蓝。

**2 · 诊断**
- **判据 J8**：反相保不住色相语义，品牌色、图像、状态色同时失真（dark-mode §2.1）；`#000` 底配 `#fff` 字还是 21:1 的晕光组合。

**3 · 改稿**

| 改哪一笔 | 病稿 | 改后 |
|---|---|---|
| 底色 | 反相白 | 独立暗色 token：底 tone 6（`#121212` 级），表面 4 档，层级跨度大于亮色（1.50 对 1.23） |
| 文字 | 反相黑 | 主文字 85% 白（不用 `#fff`）；三级文字实测 ≥4.5:1 |
| 品牌 / 语义色 | 反相 | tone 80 重映射；成功 / 警告 / 错误各出一套暗值 |

**4 · 为什么更好**
色相与语义保留，层级靠 tone 差与边框重建，用户不必重新学一套颜色含义。

**5 · 代价与边界**
两套 token 加一套暗色图片资源是真实成本；纯文字阅读场景可只做「深底 + 单色」，但依然不能反相。

### 案例 24｜暗色 · 表单｜输入框靠 `#424242` 描边，进了模态整块消失
**1 · 病稿**
- 页底 `#141414`，输入框 `1px solid #424242`、填充同页底（框 1.83:1）；模态面取 Ant `colorBgSpotlight` `#424242`，边框与面同色 = 1.0:1，输入区整块消失。
- focus 复用同一 `#424242`：键盘用户看不到焦点，也分不清当前字段。

**2 · 诊断**
- **判据 J8 + 1.4.11**：暗色填充差只有 1.6–1.8，占位符一输入就消失——框的「存在」只能由边框承担，≥3:1（反解表见 `dark-mode.md §4.3`）。病根不是边框而是模态面：`#424242` 面要 3:1 得 `#8d8d8d`，已与辅助文字同亮度。

**3 · 改稿**

| 改哪一笔 | 病稿 | 改后 |
|---|---|---|
| 模态面 | +26 `#424242` | +12 `#1f1f1f`，靠 scrim ≥60% + 阴影造「前」感 |
| 控件边界 | `#424242`（1.83 / 1.0） | 拆两个 token：`--border-strong:#6f6f6f`（对 `#1f1f1f` 3.28、对 `#141414` 3.67）；装饰线留 `--border-subtle` 1.5–2.1 |
| 焦点 | 同色边框（=没有焦点） | `:focus-visible` 2px 环 + 2px offset，与面及控件底色各 ≥3:1 |

**4 · 为什么更好**
识别信息从「看不见的框」变成「能按底色算出来的框」：同一份 token 落在每层都成立，不靠挑灰碰运气。

**5 · 代价与边界**
模态压到 +12 削弱「浮起」感，靠 scrim 与阴影补；`#6f6f6f` 到 `#303030` 只剩 2.63，**换面必须重算**；1px 线取 ≥3.3，设计值达标 ≠ 渲染达标。

## 附 · 复用这 24 组的方法

1. **先判层，再找对应案例；先读代价，再决定用不用。** 分组错看 2 / 12 / 17；顺序错看 1 / 9 / 13；负荷错看 3 / 11 / 15。别拿「字号案例」修分组问题；改法可借，数值按你的内容重定。
2. **一次只改一条主线，改完做灰度测试。** 眯眼只剩一个最重元素、3 秒内说得出「这是什么、下一步做什么」，才算改完。

**没有覆盖的**：动效与转场、原生移动端的系统级交互（手势返回、下拉刷新）、印刷工艺（专色、烫印、模切）。这些需要另一套判据，不能外推。
