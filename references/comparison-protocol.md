## 0. 立场：比较是取舍，不是判对错

**比较不是找「哪个对」，是找「在什么约束下哪个更好，代价是什么」。**

三条推论：

1. **没有代价的裁决是假的**：说「选 B，因为好看」却没写 B 牺牲了什么，等于没裁决。
2. **没有并置的比较是回忆**：凭印象比的是记忆里最鲜明的版本，不是画面；必须两案同屏。
3. **没有改选条件的裁决不可复评**：写不出改选 B 的条件，说明裁决依赖偏好而非证据。

本文件只管「方案之间」；「改稿前后」归 `before-after.md`（见该文件末「附 · 复用这 30 组的方法」）。两者都用 `taste-criteria.md` §8 的五轴，不许另立标准。

## 1. 三案：保守 / 主流 / 进取

任何比较至少两案并置，标准配置是三案。三案不是「三个风格」，是三种风险姿态：

| 案 | 定义 | 改动幅度 | 什么时候用它 | 最大风险 |
|---|---|---|---|---|
| **保守案** | 沿用当前版本或品类主流范式，只做工艺修正（对齐、间距、对比度），不改结构 | ≤20% | 现状可用、时间紧、合规敏感 | 容易被记成「没做设计」 |
| **主流案** | 当下同类产品的最优实践（样本见 §5） | 30%–60% | 大多数商业项目；评审最容易通过 | 与竞品同质，记忆点低 |
| **进取案** | 挑战一个具名默认假设，允许引入一个新机制 | ≥60% | 品牌重塑、发布页、需要被记住的场合 | 学习成本与转化风险 |

六条规则，缺一条则比较作废：

1. **至少两案并置**：只有一案是陈述，不是比较；只有一案时，先补一个「什么都不改」的保守案。
2. **保守案必选**：它是对照组。没有它，就无法说清「改的价值」，也无法在评审里回答「为什么不保持现状」。
3. **进取案必须写出被挑战的假设**：格式「如果……就……」，例：「如果首屏不需要 logo，就先给产品图」。写不出假设的「大胆方案」只是装饰。
4. **禁止折中案冒充第三案**：把 A 与 B 各取一半，不是新方案，是没做裁决；折中只能作为裁决后的微调。
5. **成本必须写进表**：工时、资产（要不要重拍/重画）、维护（多一套组件）三列至少写一列；不写成本，「最好看」永远赢。
6. **三案必须结构不同，不是配方不同**：把三案缩到 30%（或转灰度）再看一遍——去掉颜色、圆角、图标风格、插画后仍一眼可分辨，才算不同的案。只换配色/圆角/字号/风格的是同一案的两个版本，合并并注明「第三案缺」，不许拿它凑三案。补第三案时只改这三件事之一：首屏承载几件事、信息顺序、交互是否改变阅读路径。代价：缩到 30% 会丢掉小尺寸才成立的细节；它检验结构是否真不同，不检验细节质量。

三案命名禁用「方案 1/2/3」：要带姿态（保守/主流/进取），否则评审时记不住差异。

## 2. 五轴打分：并排、带证据

锚点引用 `taste-criteria.md` §8（0–3 分，越高越好），不另立，只规定怎么填。

| 轴（0–3） | 保守案 | 主流案 | 进取案 | 每轴一句证据（指到画面位置） |
|---|---|---|---|---|
| 层级清晰 | | | | |
| 节奏 | | | | |
| 一致性 | | | | |
| 记忆点 | | | | |
| 风险 | | | | |
| **合计 /15** | | | | |

**门槛（先于合计，任一轴触发即出局）**：层级 ≤1、一致性 ≤1、风险 ≤1，三轴任一落在 0–1，该案不进合计、不进修改轮，只写一行「触发【轴】+ 缺什么才能回到候选」。理由：这三轴的 1 分锚点本身就是不可交付状态（`taste-criteria.md` §8：层级 1 = 入口靠颜色硬拉；一致性 1 = 跨模块漂移；风险 1 = 有红线风险且未评估），总分制却允许「记忆点 3」把它们买回来——那是拿「被记住」换「不可用」。节奏与记忆点不设门槛：平淡、安全是缺点，不是出局。撞门槛案不进排序，也不许改名当「进取案」凑数。

三条填写规则（证据、禁半分、0 分否决见 `taste-criteria.md` §8，此处只补协议）：

1. **先独立、后合议**：每位评审先各自填完再讨论（流程见 §4）；当场商量着打分 = 互相锚定。
2. **最高分不等于必选**：若最高分案的代价不可接受（如进取案需要重拍全部素材），选次高分并写明改选条件。
3. **同分看代价**：两案同分时，回到 §1 的成本列与本案的 W 列，不许临时加第六个维度。

分数只在同一批比较里有效：跨项目不可比，不同品类的 12 分不是同一件事。

## 3. 强制裁决模板

每次裁决必须写满四个空，缺一个即视为未裁决：

```
选【A】；代价【W】；证据【E】；什么条件下改选【B】。
```

- **A**：案名（保守/主流/进取），不是「方案 2」。
- **W**：具体代价——删掉了什么、多花多少、牺牲了哪条轴；要指认到物件，「复杂度上升」不算；写「没有代价」视为没想清楚。
- **E**：五轴里的 1–3 条 + 可指认的画面证据，不是「综合更好」。
- **B**：具名条件（「如果首屏必须承载 ≥3 条价值主张」），不是「如果领导更喜欢」。

模板四行写完即止；三条完整记录（含成本表与五轴证据）见 §8。

## 4. 盲评流程

目的只有一个：让「谁做的」不影响「哪个更好」。去标识、同材料、先证据后分数、裁决记录模板的完整步骤见 `tests/golden/rubric.md`（盲评流程 7 步 + 强制裁决记录模板），本节只补协议侧三条：

1. **校准**：开评前一起看 1 个 §5 的锚样本，对齐「3 分长什么样」；不校准，两位评审会把两套标准带进同一张表。
2. **作者回避**：作者不参加盲评，只参加合议后的答疑；评审至少 1 位非作者。
3. **分歧 >1 分必须写理由**：差 1 分可保留各自证据、不强制裁决；差 ≥2 分写不出理由的一方改分，或该轴记「未定」并补看画面；两轮仍 ≥2 分引入第三位评审。

单人时：先独立打完存盘，**隔 24 小时不看原稿再打一次**；差异 >1 分的轴以第二次为准并写理由（第一次受沉没成本影响）。单人盲评上限是「去偏」，不是「客观」；裁决里写明「单人复看」，该案不进 §5 锚样本。

禁止评审前讨论方案、评审中互相看分数、用「我更懂这个行业」代替证据、把作者拉进盲评。

### 4.1 三个角色：产出者 / 评审 / 裁决人

盲评失效的第一原因不是标准不清，是**打分的人知道谁做的**，或者**打分的人就是做的人**。角色定死：

| 角色 | 能做 | 不能做 | 判据 |
|---|---|---|---|
| 产出者 | 同一 brief、同一素材产出 A/B | 不评自己、不进评审房间、文件里不留署名 | 差异只能来自执行，不能来自材料或版本 |
| 评审 | 只看去标识的 brief 与画面 | 不看来源、版本号、产出者自述 | 每轴先一句证据（指到元素/像素）再落 0–3 |
| 裁决人 | 分歧 >1 分按 §2 锚点定分 | 「整体更好」「我更懂这行」不算理由 | 走 `tests/golden/rubric.md` §4 模板 |

三条可验证的边界：

- **自评不是盲评**：产出者自评测的是「他记不记得自己为什么这样画」，不是画面；自评只能当修改清单，不得进 `baseline.md` 或 §5 锚样本。
- **一位评审只建「可复现性」，不建「质量水平」**：同 brief 两次产出 + 同一评审逐轴打分，答「两次差多少」（golden 验收：逐轴 ≤1）；答「够不够好」至少两位独立评审，否则写「单人复看」。
- **分歧 >1 分先改 brief 再改分**：分歧大通常意味硬约束没把选择逼窄——先找出那句两种读法都成立的歧义，再谈裁决。只调分数，等于把 brief 的毛病记在方案头上。

**代价**：一次盲评至少三人 × 两小时，多数项目不值得。只在**要拿分数当证据时**做（对外汇报、跨版本比较、golden 基线）；日常改稿用单案自评 + `before-after.md`。

## 5. 大众审美锚：怎么取、怎么用

「大众审美」不是「主流都这么做」，是**当期受众已经见过的合格线**。取法五步：①取样 20 个同品类、同市场、同期产品，来源与抓取日期写清；②每个样本标注它为什么合格——结构 / 材质 / 密度三选一或并列，禁只写「好看」；③至少留 3 个同期失败或被公开批评的案例，否则学到的是幸存者偏差；④季度更换，旧样本结论保留为「上一期基线」，用来区分「趋势变了」还是「我们变了」；⑤写清边界：锚只回答「受众见过什么」，不回答「什么更好」。

三种误用：当答案（都用大圆角＝照抄）、当选票（15/20 居中＝数量不是理由）、当上限（锚是基线不是天花板）。

## 6. 反模式

1. **只比数值不比画面**：4.6:1 对 4.8:1，评的是合规不是设计；数值只做门槛，不做裁判。
2. **用投票代替理由**：3:2 通过但没人说得清为什么——投票记录偏好分布，不是判断。
3. **把熟悉当好看**：「像 XX 就对了」只降低学习成本，不产生品味。
4. **把复杂当高级**：层数、动效、密度不等于深度。
5. **只比首屏不比状态**：hover、空态、错误态、暗色不看，等于只比了海报没比产品。
6. **拿旧锚比新案**：用上季度样本评本季度稿必偏保守；纯视觉潮流 12–24 个月就过载（`visual-style-taxonomy.md` §1）。

## 7. 与 `before-after.md` 的分工

| | `comparison-protocol.md`（本文件） | `before-after.md` |
|---|---|---|
| 比较对象 | 同一 brief 的 2–3 个不同方案 | 同一方案的改稿前 / 改稿后 |
| 回答的问题 | 在约束下选哪个，代价是什么 | 改哪一笔，为什么更好 |
| 产出 | 裁决记录（选 A / 代价 W / 证据 E / 改选 B） | 病稿 → 诊断 → 改稿 → 理由 |
| 使用时机 | 动手前（SKILL 第 3–4 步） | 改稿时与复盘（第 5–6 步） |
| 失败形态 | 比了但没裁决 | 改了但说不清为什么 |

两者可串联：先选案再改稿；`before-after.md` 里「为什么更好」的每一句都应能被五轴解释——解释不了的，要么是口味，要么没改对。

用 `tests/golden/` 现成 brief，书面方案、单人、无视觉稿；† = 结构代理分（按文字里的结构证据打，有稿须复评）。分数只证明协议可执行，不是设计质量证据。

**8.1 01-saas-landing**（首屏 ≤900px、禁假数据）
- 保守 11（2/2†/3/1†/3）：品类模板，首屏 3 个同级块（标题/双 CTA/logo 条）；零新资产。
- 主流 13（3/2†/3/2†/3）：一句可验收承诺 + 一张无假数据面板图 + 单 CTA，三卖点下移；社会证明改为「可申请核对 3 个匿名案例」；多一张截图。
- 进取 9 ✕险1（2/1†/2/3†/1）：可交互数据流首屏；brief 无真实切片，首屏 JS 与 LCP 未评估，390 需降级方案。

**8.2 05-poster**（A2、3mm 出血、3m 停步 / 30cm 读全）
- 保守 11（2/2†/3/1†/3）：字标 + 主色居中压阵；3m 处只剩「一张深色海报」。

- 保守 12（3/2†/3/1†/3）：默认图标 + 一句说明 + 一个按钮；收藏/通知两态几乎一样。
- 主流 14（3/3†/3/2†/3）：线性插画 +「做什么能得到内容」+ 主次两行动，与加载/错误态共用同一槽位（插图位、文案位、按钮位），深浅只换 token。
- 进取 9 ✕一1（2/2†/1/3†/1）：空态变内容预览（3 个模糊示例轮廓，点即操作）；轮廓与骨架屏同语言，brief 明令禁止；易被误认为加载失败。
- 选【主流】；W【放弃零新增组件（要定义跨态槽位）；预览即操作降为一个文字链接】；E【一致性 3 vs 1：骨架屏已占「模糊轮廓」这个符号】；B【若系统已有 skeleton 且能区分 loading/empty 语义（骨架带 shimmer、空态不带）→ 进取案回候选重评】。

**8.4 三条记录回写成了什么**
1. 三次撞门槛都在进取案（01/05 险1、10 一1）→ §2 门槛；05 进取 11 分本落在修改区间，被少花一轮。
2. 01 三案缩到 30% 后，进取与主流不可区分（交互件消失，都剩「一句大话 + 一张图」）→ 该进取案不合格，真第三案要改「首屏承载几件事」；§1 规则 6 由此出。
3. 01 初稿 W 写「复杂度上升」不成立，改成「多一张截图 + 一次前端工时 + 390 降级」才算 → §3 W 硬规则。
4. 载体与门槛（n=3，仅观察）：说服型进取案得 11；操作型撞一致性门槛。≥6 条再升级。
5. `rubric.md` 风险 1 已对齐 `taste-criteria.md` §8，否则同一案两套表一个出局一个过关。
