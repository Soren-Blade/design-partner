# 品牌视觉与 Logo 逻辑（Brand Identity）

> 快照 2026-11-01。所有数值取自官方规范原文 / 源码 / GitHub API 实测，出处见 §21。
> 本文件解决一件事：**从"三个形容词"走到"一套能交付、能验收、能注册的视觉识别"**，而不是给你一堆 logo 灵感图。

## 1. 一页速查：品牌视觉从零到交付

| 阶段 | 你要产出的东西 | 硬约束（做不到就是错的） | 去哪一节 |
|---|---|---|---|
| ① 定位 | 3 个形容词 + 3 个反义词 + 1 句"我们不是谁" | 形容词必须是**可视觉翻译**的（"专业"不可翻译，"克制"可） | §3 |
| ② 标志 | 1 个主标 + 3 个降级版（简化/符号/单色） | 主标必须在 **24px** 还认得出，否则构造有问题 | §4 §5 §7 |
| ③ 色彩 | 1 个种子色 → 10–12 档色阶 + 语义映射 | 种子色必须能生成**每档都过对比度**的色阶 | §8 §9 §10 |
| ④ 字体 | 1 套字族 2–3 字重（或 1 套系统栈） | 中文必须确认**商用授权**；不许出现 500 字重伪粗 | §12 |
| ⑤ 图形 | 图标网格 + 插画/纹理五参数 | 图标必须同网格、同笔画、同角半径 | §13 |
| ⑥ 声音 | 4 维语气坐标 + 3 个语气词 + 反语气词 | 同一个动作在全站只能是同一种说法 | §14 |
| ⑦ 交付 | 矢量源 + 位图套件 + 平台图标 + 手册 | 少一个平台尺寸 = 上线当天现补 | §15 §16 |
| ⑧ 合规 | 商标类别清单 + 素材授权链 | logo 版权 ≠ 商标权，两件事都要做 | §17 |

**最短路径（4 小时版）**：§3 三个词 → §4 选类型 → §5 用 24 网格画 → §6/§7 定清space与最小尺寸 → §8 选种子色 → §9 跑色阶 → §15 出交付包 → §20 自检。

## 2. 品牌视觉的四层结构（别从 logo 开始）

绝大多数"logo 做得挺好看但整个品牌立不住"的项目，都是跳过了第 1、2 层直接画图。

```
L1 定位层   我们是谁 / 为谁 / 不是什么          → 3 个形容词 + 3 个反义词
L2 语言层   视觉语法：形/色/字/图/动/声         → 6 个维度的取舍规则
L3 系统层   把语法固化成 token 与组件           → 色阶 / 字阶 / 网格 / 图标
L4 资产层   可交付的文件与手册                  → SVG / PNG / ico / 手册
```

**判断顺序**：先能说出 L1 的三句话，再动手 L2。L1 说不清时画出来的东西，评审时一定被"感觉不对"打回，而你说不出哪里不对——因为你没有判断依据。

**这层结构与你已有的其他文件的关系**：
- L3 的色阶/字阶/token → `design-tokens.md`（三层架构与 Ant 数值全量）
- L3 的网格与间距 → `editorial-layout.md` §3（12 栏与基线）
- L2 的"动" → `motion-system.md`（曲线与时长）
- L4 的社媒/印刷尺寸 → `editorial-layout.md` §10–§13
- 本文件负责 **L1→L2 的翻译**、**标志本身的构造与验收**、**品牌色的生成算法**、**资产清单与合规**。

## 3. 从三个词到视觉：定位翻译表

### 3.1 形容词必须"可翻译"

不可翻译的词（说了等于没说）：专业、高端、国际化、有温度、年轻化、科技感。
可翻译的词（能落到具体参数）：克制、锐利、圆润、厚重、通透、手工感、工业、植物性、档案感、夜间。

**检验法**：给这个词，你能不能立刻说出"所以圆角是 0 还是 12"？说不出就不是视觉词。

### 3.2 六维翻译表（把词变成参数）

| 维度 | 参数化落点 | 左端 | 右端 |
|---|---|---|---|
| 形 | 圆角半径 / 笔画粗细 / 曲直比 | 0px 直角、2px 细线、全直线 | 全圆角、8px 粗线、全曲线 |
| 色 | 明度 / 彩度 / 色相偏移 | 高明度低彩（通透） | 低明度高彩（厚重） |
| 字 | 字重档 / 字面宽窄 / 是否衬线 | Light + 窄字面（锐利） | Bold + 宽字面（稳固） |
| 图 | 视角 / 光源 / 材质 / 细节密度 | 正视平光、无质感 | 斜 45° 强侧光、强材质 |
| 动 | 时长 / 曲线 / 幅度 | 120ms 减速、位移 8px | 400ms 标准、位移 48px |
| 声 | 4 维语气（§14） | 正式·严肃·尊重·就事论事 | 随意·幽默·不恭·热情 |

### 3.3 三个词的组合纪律

- **最多 3 个词**，且必须**分属不同维度**（如"锐利（形）+ 冷静（色）+ 档案感（图）"）。三个词都在"形"维度上 = 只有一个词。
- **必须写 3 个反义词**。反义词不是修辞，是**排除法**：它告诉你哪些方案一定不能提交，评审时用它挡掉 80% 的争论。
- **一词一参数**：每个词在六维表里至少占 2 个维度，否则它只是口号。

> 例：「克制 + 精确 + 夜间」
> 形：直角 0–2px、线宽 1.5px｜色：低彩度、暗底、单强调色｜字：Regular/Medium 两档、无衬线窄字面｜图：平光、无纹理、几何｜动：120ms 减速、位移 ≤8px｜声：就事论事、不感叹号

## 4. 标志类型学：七型与选择决策

| 类型 | 英文 | 认得出靠什么 | 寿命 | 主要风险 | 适合 |
|---|---|---|---|---|---|
| 字标 | Wordmark | 独有的字形设计 | 长 | 换字体=换品牌，改造成本高 | 名字短（≤10 字符）、要长期沉淀 |
| 字母标 | Lettermark / Monogram | 1–3 个字母的独特结构 | 长 | 字母组合易撞车、易被记成别人 | 名字长、要缩写 |
| 图形标 | Pictorial mark | 一个具体物象 | 中 | 物象被品类绑死，转型即失效 | 品类稳定、要强识别 |
| 抽象标 | Abstract mark | 独有的几何构成 | 长 | 无含义=要靠长期投放喂出来 | 有预算做品牌教育 |
| 组合标 | Combination mark | 图形 + 字标 | 中长 | 两者风格不统一就散架 | 新品牌首选（兼顾识别与解释） |
| 徽章 | Emblem | 图文嵌在一个封闭轮廓里 | 长 | 小尺寸必糊、横向排版难 | 传统/机构/服饰/餐饮 |
| 动态标 | Dynamic mark | 一套可变规则而非单一图形 | 长 | 无规则=每次都不一样 | 数字原生、有技术团队 |

### 选择决策树

```
名字 ≤10 字符且要好记？ ── 是 ──→ 字标（最省认知成本）
        │
        否
        ↓
要缩写吗？ ── 是 ──→ 字母标
        │
        否
        ↓
有一个不可替代的物象？ ── 是 ──→ 图形标（+ 字标做组合）
        │
        否
        ↓
新品牌 / 需要同时被"认出"和"解释"？ ── 是 ──→ 组合标（默认答案）
        │
        否
        ↓
机构/服饰/线下为主？ ── 是 ──→ 徽章
        │
        否
        ↓
有技术团队做规则引擎？ ── 是 ──→ 动态标（必须同时给静态兜底版）
```

**三条硬立场**：
1. **新品牌默认做组合标**——图形负责"记住"，字标负责"念对"。只做图形的新品牌，前 18 个月基本靠投放硬砸。
2. **徽章不要用在小尺寸**。徽章的信息密度决定它在 24px 必糊；必须另配一个"仅符号"版本（§7）。
3. **动态标必须附带静态版**。没有静态兜底的动态标，在 favicon / 印刷 / 合作方物料上一定会翻车。

## 5. 标志几何构造：网格 / 基形 / 笔画 / 光学修正

### 5.1 用 24 网格画（与图标同源）

Material 的图标网格是目前最完整、可直接复用的几何体系（官方原文）：

| 项 | 数值 |
|---|---|
| 画布 | **24 × 24 dp**，100% 比例下绘制（不要放大到 1000% 再画，会引入非整数坐标） |
| live area（内容区） | **20 × 20 dp** |
| 四周 padding | **2 dp** |
| 方形基形 | **18 × 18 dp** |
| 圆形基形 | 直径 **20 dp** |
| 竖矩形基形 | 高 **20** × 宽 **16 dp** |
| 横矩形基形 | 高 **16** × 宽 **20 dp** |
| 默认圆角 | **2 dp**（描边宽度 ≤2dp 的形状不做圆角） |
| 描边权重 | **2 dp**（对应字重 400）；复杂形状可局部降到 **1.5 dp** |
| 光学尺寸 | **20 / 24 / 40 / 48 dp** 四档，各档单独调，不是等比缩放 |

**为什么基形是这四个**：方、圆、竖矩、横矩覆盖了绝大多数物象的外轮廓。先选基形，再把细节压进基形内——这样一组标志放在一起才有"同一家族"的感觉。

**logo 沿用同一套的理由**：品牌标志和界面图标在同一屏上并置（导航栏 logo + 菜单图标）。网格不同源，笔画粗细就会差 0.5px，肉眼立刻觉得"不搭"。**统一做法：标志用 24 网格的整数倍（48 / 96 / 192 画布），笔画 = 2 的整数倍（2 / 4 / 8）。**

### 5.2 光学修正四条（几何正确 ≠ 视觉正确）

1. **圆要溢出**：直径 20 的圆与 18 的方看起来才"一样大"。纯几何等宽会让圆显小。
2. **尖角要收**：锐角顶点在同样笔画下会显重、显脏，顶点处笔画应略细（约 −10%）。
3. **曲线交接要收口**：直线与曲线相接处不做等宽，曲线一侧略细 0.25–0.5dp，否则接点出现"疙瘩"。
4. **重心要压**：视觉重心略高于几何中心（约 1–2% 高度），否则看起来往下坠。

> 检验法：把标志缩到 **24px**、**16px**，各看一眼。24px 认不出主体 → 细节太多；16px 糊成一团 → 需要简化版，不是继续微调。

### 5.3 描边统一纪律

- 一个标志里**只允许两档笔画**：主笔画 + 细节笔画（主 ×0.5 或 ×0.75）。出现第三档就是没控制住。
- 端点风格全标志统一：要么全平头（butt/square），要么全圆头（round）。混用是最常见的"业余感"来源。
- 转角风格统一：外圆内方（Material outlined 的做法）或全圆，不要随机。

## 6. 标志清space（安全边距）三口径

"清space"= 标志四周不许放任何东西的最小距离。**手册里只写"留足空间"等于没写**，必须给一个可计算的单位。

### 6.1 三种主流口径（选一个，写死）

| 口径 | 单位定义 | 留白量 | 实例 |
|---|---|---|---|
| 字高口径 | **x** = 字标小写字母高度（无字标时用图形高度） | 0.5x–1x | 最常见，好算 |
| 半符号口径 | 符号圆/主形的**直径的一半** | 0.5 × 直径 | Royal Irish Academy 官方：clearspace = 符号圆直径的一半 |
| 高度折半 | 标志整体高度 ÷ 2 | 0.5h | 若干机构手册采用 |

**推荐**：有图形符号的用「半符号口径」（视觉上最稳，且和 co-branding 间距规则天然一致）；纯字标用「字高口径」。

### 6.2 落地写法（不要用 margin，用 padding）

```css
.brand-logo {
  --clear: 0.5em;              /* 1 单位 = 当前 logo 高度的一半，随尺寸缩放 */
  padding: var(--clear);
  display: inline-block;
  line-height: 0;              /* 去掉行高带来的额外空隙，否则清space 会被撑大 */
}
.brand-logo > svg { display: block; height: 100%; }
```

**四个必须写进手册的数值**：top / right / bottom / left 各多少 px（按最小尺寸算一次、按主尺寸算一次）。

### 6.3 联合品牌（co-branding）间距

RIA 官方口径可直接借用：**两个 logo 之间 ≥ 各自清space（= 50% 符号直径），理想值 = 1 个符号直径**。
另外两条：**视觉面积相等**（不是高度相等——一个高瘦标和一个矮宽标按高度对齐会显得后者小）、**中间放分隔线时线宽 = 两标笔画平均值**。

## 7. 最小尺寸与响应式标志四档（多小算太小 / 缩小到什么时候换版）

### 7.1 最小尺寸（有官方实测值，别再凭感觉）

| 场景 | 下限 | 依据 |
|---|---|---|
| 数字端主标 | **40 px 宽/高** | RIA 官方：digital 最小 40px |
| 印刷主标 | **10 mm** | RIA 官方：print 最小 10mm |
| 小尺寸版切换区间 | **40–80 px（数字）/ 9–18 mm（印刷）** | RIA 官方：此区间改用 small logo version |
| favicon | **≥48×48**（最小可用 8×8，但推荐 >48） | Google Search 官方 |
| 界面内符号位 | **24 dp** | 与 Material 图标网格同源 |
| 烫金/丝印/刺绣 | **≥15 mm**（建议值） | 工艺精度限制，非官方标准 |

**判定公式（比记数字更可靠）**：`最小可用尺寸 = 最细笔画宽度 ÷ 0.75 px`。最细笔画 1.5px 的标志，缩小到笔画不足 0.75px 就开始虚——这时候该换简化版，不是继续缩小。

### 7.2 响应式标志四档（一套系统，不是一张图）

```
① 主组合标   图形 + 全称（+ 可选标语）   ≥ 160px
② 简化组合   图形 + 全称，去掉标语/副标  80–160px
③ 仅符号     只有图形                    24–80px（favicon / 头像 / 应用图标）
④ 仅字标     只有文字                    横向窄条（导航栏、页脚署名）
```

**切换纪律**：
- 切换阈值写进手册，且**只按尺寸切，不按"我觉得挤"切**。
- 四档必须是**同一几何体系**（同基形、同笔画比），不能是四个不同设计。
- 每档都要单独过 §5.2 的 24px / 16px 检验——**"仅符号"这一档最常被漏做，最后拿主标硬缩，糊掉**。

## 8. 品牌色：主色怎么定（不是"选个好看的颜色"）

### 8.1 选色四问（顺序不能反）

1. **对比度余量**：这个色做按钮底、白字压上去，能过 **4.5:1** 吗？过不了 → 它只能做装饰色，不能做 primary。
2. **色阶可生成性**：从这个色能不能生成 10–12 档、且第 9 档（实心底）与第 11 档（文字）都成立？生成出来中段发灰、末段发脏 → 换色。
3. **印刷可复制**：CMYK 转换后是否严重偏色？是否需要专色（Pantone）？预算里有没有专色？
4. **行业反差**：同品类前 5 名是不是都用同一个色相？如果是，**要么彻底避开，要么做到极致**（中间态最没有记忆点）。

**核心立场**：主色是**种子色（seed）**，不是最终色。最终色是"种子色 + 生成算法"的产物。选色时先跑色阶，色阶崩了立刻换种子——不要靠手调 12 个色值硬凑。

### 8.2 品牌色配额

| 角色 | 数量 | 说明 |
|---|---|---|
| 主色（Primary） | 1 | 只用于可交互/需强调。占屏面积 ≤10% |
| 辅助色（Secondary） | 1–2 | 用于分类、图表、次级强调 |
| 语义色 | 4 | success / warning / error / info，**不得与主色同色相** |
| 中性色阶 | 9–12 档 | 承载 90% 面积 |

**60-30-10 的准确含义**：60% 中性底、30% 次级中性/辅助、10% 主色。**主色超过 15% 就不再是强调，而是噪音。**

## 9. 色阶生成三条路线（选一条，别混）

### 路线 A · 等感知明度（HCT tone）——最适合"要一套能跑双主题的系统"

Material 的色彩工具链用 **HCT**（Hue / Chroma / Tone）：
- **Tone 0–100**，与感知亮度（L\*）对齐——**tone 差 = 感知差**，这是它比 HSL 好用的唯一理由（HSL 的 L=50 在黄和蓝上是完全不同的亮度）。
- **色调板（Tonal Palette）= 固定 hue + 固定 chroma，只变 tone**。所以一条色阶"看起来是同一个颜色在明暗变化"，不会中途变色相。
- 官方参考实现的做法：从一个种子色取 hue/chroma，生成整条 tone 阶，再按语义角色取 tone 值。

**适用**：需要亮/暗双主题、需要"同一品牌色在不同明度下都可读"。

### 路线 B · 12 步语义色阶（Radix 口径）——最适合"要给工程一套不会用错的变量"

Radix 每一步**对应唯一用途**（官方原文，逐条照抄）：

| 步 | 用途 |
|---|---|
| 1 | App 背景 |
| 2 | 次级背景（卡片/条纹/代码块） |
| 3 | UI 元素背景（常态） |
| 4 | UI 元素背景（hover） |
| 5 | UI 元素背景（按下/选中） |
| 6 | 弱边框与分隔线（非交互） |
| 7 | 交互组件边框 |
| 8 | 更强的交互边框 / **焦点环** |
| 9 | **实心背景**（色阶中彩度最高、最纯的一档；用于图形/Logo/强调块） |
| 10 | 实心背景 hover |
| 11 | 低对比文字 |
| 12 | 高对比文字 |

补充事实：**11 / 12 步在同色阶第 2 步背景上分别保证 APCA Lc 60 / Lc 90**；多数第 9 步设计给**白字**，Sky/Mint/Lime/Yellow/Amber 五个色系设计给**深色字**。

**这条路线最大的价值**：工程侧只记"背景用 1/2、按钮用 3-4-5、边框 6-7-8、实心 9-10、文字 11-12"，就不会出现"用第 4 档做文字导致看不清"。

### 路线 C · 对比度优先（Leonardo 口径）——最适合"必须过无障碍验收"

Adobe Leonardo 的核心思想：**以目标对比度为输入，反解颜色**，而不是"先选色再审计"。
- 输入：种子色 + 一组目标对比度（swatches）；输出：满足或**略高于**目标的色值。
- 为什么"略高"：RGB 空间离散，目标 8.58 可能只能取到 8.59；WCAG 是**最低要求**，略高可接受。
- 底层用 D3 线性色阶 + CIE CAM02 等现代色貌模型。

**适用**：政府/金融/医疗等必须过 WCAG 的项目；或需要"用户可调对比度"的产品。

**三条路线不许混**：混了会出现"第 9 档比第 10 档更亮"这类不可解释的错序。

## 10. 品牌色双主题：M3 官方 tone 映射表（亮色/暗色精确值，可直接抄进 token）

Material 参考实现（`scheme.ts`）里亮/暗主题的角色取值，是**现成的、经过验证的"品牌色→语义角色"映射**：

| 角色 | 亮色主题 tone | 暗色主题 tone |
|---|---|---|
| primary | **40** | **80** |
| onPrimary | 100 | 20 |
| primaryContainer | 90 | 30 |
| onPrimaryContainer | 10 | 90 |
| secondary | 40 | 80 |
| onSecondary | 100 | 20 |
| secondaryContainer | 90 | 30 |
| onSecondaryContainer | 10 | 90 |
| tertiary | 40 | 80 |
| onTertiary | 100 | 20 |
| tertiaryContainer | 90 | 30 |
| onTertiaryContainer | 10 | 90 |
| error | 40 | 80 |
| onError | 100 | 20 |
| errorContainer | 90 | 30 |
| onErrorContainer | 10 | 80 |
| background / surface | 99 | 10 |
| onBackground / onSurface | 10 | 90 |
| surfaceVariant | 90 | 30 |
| onSurfaceVariant | 30 | 80 |
| outline | 50 | 60 |
| outlineVariant | 80 | 30 |
| shadow / scrim | 0 | 0 |
| inverseSurface | 20 | 90 |
| inverseOnSurface | 95 | 20 |
| inversePrimary | 80 | 40 |

**读法（比背表重要）**：
- **亮→暗不是反色，是 tone 重映射**：主色 40 → 80（提亮），容器 90 → 30（压暗），文字 10 → 90（反相但走的是同一条色阶）。
- **outline 在暗色主题反而更亮**（50 → 60）——因为暗底上"边界"需要更强的分离度，不是简单反色。
- **error 的 onErrorContainer 亮色是 10、暗色是 80**（不对称，这是官方实现里的实际差异，别自作聪明"对称化"）。

**与 `design-tokens.md` 的关系**：那边讲三层架构与 Ant 数值，这里给的是**"品牌种子色 → 双主题语义角色"的算法级映射**。两者叠加使用：用本节算色值，用 `design-tokens.md` 的命名规范落地。

## 11. 品牌色的边界：图表 / 大屏 / 印刷 / 多品牌

### 11.1 主色不能当图表分类色

主色是"强调"，分类色是"区分"。用主色做图表分类色会出两个问题：① 与界面强调色抢注意力；② 单色阶无法区分 5 类以上。

**正确做法**：图表分类色**另起一套**（见 `dataviz.md` §3 的 Carbon/AntV 分类色板），主色只在"当前选中系列"或"目标值参考线"上出现。

### 11.2 大屏（暗底远看）

- 暗底上品牌色要**提亮 1–2 档**（tone +10~20），否则在投影/拼接屏上直接变黑。
- 大屏文字用**纯白或 tone 95**，不要用 tone 80 的"柔和白"——远距离会灰掉。
- 主色面积在大屏上可以放大到 15–20%（观看距离远，色彩衰减），但**仍不超过 25%**。

### 11.3 印刷

- **CMYK 先转再看**：屏幕上鲜艳的蓝/绿转 CMYK 后普遍发灰（尤其 RGB 蓝紫），品牌主色必须**在 CMYK 里重新校一次**。
- **专色判断**：主色若在 CMYK 下 ΔE 偏差明显，且品牌露出频次高 → 上 Pantone 专色；否则接受四色近似。
- 深色底反白标志：**细笔画要加粗 10–15%**，否则印刷时断线（与 `editorial-layout.md` §13 的 0.25pt 细线下限一起看）。

### 11.4 多品牌 / 子品牌

| 结构 | 做法 | 何时用 |
|---|---|---|
| 品牌屋（Branded house） | 全部共用主标 + 后缀 | 子业务强依赖母品牌信任 |
| 背书品牌（Endorsed） | 子品牌自有标 + "by 母品牌" | 子品牌要独立人格 |
| 多品牌（House of brands） | 各自独立，仅共享设计语法 | 客群互相排斥 |

**纪律**：无论哪种结构，**图标网格、色阶生成算法、字体授权**必须共用一套——共用这三样，视觉上自然像一家人，比强行统一 logo 有效。

## 12. 字体系统：品牌字体与系统栈

### 12.1 三档配置（按预算选）

| 配置 | 组成 | 成本 | 风险 |
|---|---|---|---|
| A · 单一家族 3 字重 | Light/Regular/Bold | 最低 | 大标题缺"个性" |
| B · Display + Text 两族 | 展示族（标题）+ 正文族 | 中 | 两族 x-height 不匹配会显脏 |
| C · Display + Text + Mono | 再加等宽（数字/代码） | 高 | 三族混排需要严格规则 |

**两族搭配的唯一硬指标**：**x-height 接近**（差 ≤8%）。x-height 差太多，同一行混排时小写字母会"高低不平"。其次看字重档位是否互补（一族有 Light，另一族至少有 Regular）。

### 12.2 品牌字体 vs 系统栈

- **品牌字体只用于"品牌露出位"**：logo 字标、大标题、封面、海报主张。**正文用系统栈**——加载成本、中文覆盖率、渲染一致性都更优。
- 中文品牌字体必须**确认商用授权范围**（桌面/网页/嵌入 App/商标图样是不同授权，logo 里用了字体 = 商标图样使用，通常需单独授权）。
- 开源可用：思源黑体/思源宋体（SIL OFL）、霞鹜文楷。**开源 ≠ 可以做 logo**：OFL 允许，但要保留许可声明，且部分字族保留字体名（Reserved Font Name）。

### 12.3 中文品牌字的三个坑

1. **不要用 500 字重**：多数中文字体没有 Medium，浏览器合成伪粗 → 笔画粘连。
2. **不要给中文加大字距冒充高级感**：方块结构一散就散架（`editorial-layout.md` §15 已列）。
3. **不要用斜体**：中文无真斜体，一律伪斜。

### 12.4 数字必须等宽

价格、统计、表格、倒计时里的数字用 `font-variant-numeric: tabular-nums`，否则数字列会左右跳动（`form-table.md` §13 已强调，品牌侧同样适用）。

## 13. 图形语言：图标网格三体系 + 插画五参数

### 13.1 图标网格对照（笔画粗细 / 对齐 / 两套已验证体系）

| 项 | Material Symbols | Carbon（IBM） |
|---|---|---|
| 主画布 | 24 × 24 dp | **16 px**（组件最常用），另有 20 / 24 / 32 |
| 内容区 | live area 20×20，四周 padding 2 | 按画布整数栅格对齐 |
| 基形 | 方 18 / 圆 20 / 竖矩 20×16 / 横矩 16×20 | — |
| 圆角 | 默认 2 dp；≤2dp 宽的描边不圆角 | — |
| 笔画 | 2 dp（weight 400），可 100–700 变重 | 与 16/20 画布匹配，配 14/16px 正文 |
| 光学尺寸 | 20 / 24 / 40 / 48 | 16 / 20 / 24 / 32 |
| 与文字配对 | — | **16/20 配 14/16px**，24/32 用于大图标 |
| 对齐 | 落在整数像素上 | **与文字居中对齐**（不要基线对齐） |
| 颜色 | — | 单色，**与文字同色**，对比度 **4.5:1** |
| 触控热区 | — | **≥44 px**（用 CSS padding 撑，不要画大图标） |

**落地纪律**：
- **一个产品只用一套图标**。混两套 = 笔画 2dp 与 1.5px 并置，一眼看出不统一。
- 图标与文字并排时**居中对齐**（Carbon 明确：不要基线对齐）。
- 图标颜色**跟文字同色**，不要给图标单独上色（Carbon 明确禁止）。
- 交互图标热区 **≥44×44**，视觉 16px 的图标用 padding 撑（与 `accessibility.md` 目标尺寸三档一致）。

### 13.2 插画/纹理/摄影五参数（把"风格"写成可验收的规格）

任何视觉素材（插画、3D、摄影、纹理）都按这五项定义，缺一项就会出现"这次和上次不像"：

| 参数 | 要写清什么 | 例 |
|---|---|---|
| 视角 | 正视 / 等轴测 / 斜 45° / 俯视 | 等轴测 30° |
| 光源 | 方向 + 软硬 + 是否投影 | 左上 45° 硬光，投影偏移 4px 无模糊 |
| 材质 | 无质感 / 纸纹 / 金属 / 玻璃 | 无质感平涂 |
| 细节密度 | 单图形元素数量上限 | ≤7 个形状 |
| 色域 | 只用品牌色阶的哪几档 | 只用 3/5/9 三档 + 中性 1/2 |

**这条最容易被跳过，但收益最大**：把五参数写进手册，外包插画师返工率会直接下降——因为争议从"感觉不对"变成"光源方向错了"。

## 14. 品牌声音与文案语气（NN/g 四维）

### 14.1 四个维度（各是一条光谱）

| 维度 | 一极 | 另一极 |
|---|---|---|
| 正式度 | 正式（Formal） | 随意（Casual） |
| 严肃度 | 严肃（Serious） | 幽默（Funny） |
| 尊重度 | 尊重（Respectful） | 不恭（Irreverent） |
| 热情度 | 就事论事（Matter-of-fact） | 热情（Enthusiastic） |

**用法（NN/g 原文口径）**：
1. 先用四维定位整体语气；
2. 再挑**少量**具体语气词（playful / quirky / dry…）——"避免选超过一小把，否则守不住"；
3. **同时选反语气词（anti-tone words）**：例如"权威但不说教"，"专业但不冷漠"。
4. **人格保持一致，语气随场景变**：财报和校招页不该一个调子。

### 14.2 落地到界面文案

- 同一动作在全站只能一种说法：保存 / 提交 / 确认 三选一，不许混。
- 错误文案的语气跟品牌走，但**结构固定**（发生了什么 + 为什么 + 怎么办，≤30 字，见 `feedback-states.md` §6）。
- **幽默只用在"用户没损失"的地方**（空态、彩蛋、加载文案）；错误、支付、删除一律不用幽默。
- 中文品牌的语气最容易翻车在**感叹号密度**：一屏超过 1 个感叹号，语气就从"热情"滑向"推销"。

## 15. 资产交付清单与文件格式

### 15.1 矢量源（一切的基础）

| 文件 | 要求 |
|---|---|
| `logo-primary.svg` | viewBox 归一（如 `0 0 240 64`）、**路径已转曲**（不依赖字体）、无外部引用、无 `<style>` 内联 |
| `logo-mono.svg` | 单色版，`fill="currentColor"`，可被 CSS 着色 |
| `logo-reverse.svg` | 反白版（深底用），单独调过笔画（+10%） |
| `logo-symbol.svg` | 仅符号版（§7 第③档） |
| `logo-horizontal.svg` / `logo-stacked.svg` | 横排 / 竖排两种锁版 |
| `logo.ai` / `.eps` / `.pdf` | 印刷用，CMYK，字体转曲 |

**SVG 三条硬要求**：① 转曲（否则换机器字体就变形）；② 不用 `text` 元素；③ 跑一遍 SVGO 压体积（logo 通常能压 40–60%，且不损视觉）。

### 15.2 位图与平台图标

| 用途 | 尺寸 | 依据 |
|---|---|---|
| favicon | 16 / 32 / 48（`.ico` 多尺寸）+ `favicon.svg` | Google：≥8×8 可识别，推荐 >48×48 |
| Apple 触屏图标 | **180×180**（`apple-touch-icon`） | 平台惯例 |
| PWA / Android | **192×192 + 512×512** | manifest `icons`；SVG 可写 `sizes:"any"` |
| maskable 图标 | 512×512，**内容压在中心半径 40% 的圆内** | W3C：安全区 = 半径 2/5 的圆，圆外像素不保证可见；留在安全区内自然获得约 10% 四周留白 |
| iOS / macOS App 图标 | **1024×1024**（正方形、**不要自己切圆角**，系统统一遮罩） | Apple HIG |
| watchOS | 1088×1088（系统裁圆） | Apple HIG |
| tvOS | 800×480（横向，2–5 层） | Apple HIG |
| OG / 分享图 | **1200×630** | Open Graph 惯例（详见 `editorial-layout.md` §12） |

**Apple HIG 的三条明确要求**：图层必须是**未遮罩**的正方形（自己切圆角会破坏高光效果并产生锯齿）；**文字只在必要时代替**（不支持无障碍与本地化，不要重复 App 名，禁止 "Watch/Play/New" 这类指令或情境词）；iOS 需考虑 **default / dark / clear / tinted** 四种外观，未提供的由系统自动生成，但**各外观的核心视觉特征必须一致**。

### 15.3 品牌手册（两种体量）

**一页式（One-pager）**：标志 + 清space + 最小尺寸 + 色值表 + 字体 + 3 条 do/don't。适合小团队、外包对接。
**完整版（九章）**：① 品牌定位 ② 标志系统 ③ 色彩 ④ 字体 ⑤ 图形语言 ⑥ 图标 ⑦ 影像 ⑧ 语气 ⑨ 应用示例。骨架与 `design-md-format.md` 的九章 DESIGN.md 对齐，可复用同一套章节名。

## 16. 品牌一致性的十条检查（交付前逐条过）

1. 主色在**亮/暗两个主题**下都过对比度（文字 4.5:1、非文本 3:1）。
2. 标志在 **24px / 40px / 160px** 三档都成立（不够就启用降级版）。
3. 所有标志版本的**笔画比一致**（主标 4px → 符号版 4px，不是 3.5px）。
4. 图标与标志**同网格同笔画**（并排看不出粗细差）。
5. 色阶**无错序**（第 9 档不比第 10 档亮）。
6. 语义色**不与主色同色相**（否则"错误"看起来像"强调"）。
7. 字体只有 1–2 族、字重 ≤3 档，中文无伪粗无伪斜。
8. 语气：同一动作全站**一种说法**，感叹号密度 ≤1/屏。
9. 所有素材的**授权链完整**（字体/图标/摄影/3D）。
10. 交付包**无缺件**：SVG 全档 + ico + 192/512 + 180 + 1024 + OG + 手册。

## 17. 商标与授权合规（不做这步，前面全白做）

### 17.1 商标 ≠ 版权（两件事）

| | 版权（著作权） | 商标权 |
|---|---|---|
| 产生方式 | 创作完成**自动产生** | 必须**申请注册**并经核准 |
| 保护对象 | 图形的"表达" | 特定类别上的"识别来源"功能 |
| 期限 | 一般作者终生 + 50 年（法人作品另计） | 每次注册 10 年，可续展 |
| 谁需要做 | 设计方与委托方约定归属 | 品牌方按类别申请 |

**最容易踩的坑**：以为"我画的 logo 就是我的商标"。**不注册 = 没有商标权**，别人在同类上注册了，你可能要改标。

### 17.2 类别（尼斯分类 1–45 类）

- **1–34 类 = 商品**，**35–45 类 = 服务**。
- 互联网产品通常至少覆盖：**第 9 类**（软件/APP）、**第 35 类**（广告/电商/商业管理）、**第 42 类**（技术服务/SaaS/设计开发）；内容/传媒加 **第 41 类**；餐饮加 **43 类**。
- **注册前必做近似检索**（图形要素 + 文字），否则驳回率很高。
- 周期：受理 → 实质审查 → 初审公告（3 个月异议期）→ 核准发证。常见总时长 6–12 个月；官方近年多次压减审查周期，**具体以 CNIPA 当期公告为准，不要引用旧口径**。

### 17.3 素材授权链（四项必查）

| 素材 | 要查什么 |
|---|---|
| 字体 | 商用范围（桌面/网页/嵌入/商标图样），logo 用字通常需"商标图样"授权 |
| 图标 | 许可类型：CC0（simple-icons）可商用免署名；MIT/Apache 需保留声明；**品牌 logo 类图标不得作为自己的商标** |
| 摄影 | 肖像权 + 物权（建筑/艺术品）+ 授权地域与期限 |
| 3D / 插画 | 是否允许修改、是否允许用于商标 |

## 19. 反模式 20 条

1. 从 logo 开始做品牌，定位一句话说不出来。
2. 用"高端/专业/科技感"当视觉方向（不可翻译）。
3. 三个形容词全在同一个维度上（等于只有一个词）。
4. 不写反义词，评审全靠"感觉不对"。
5. 新品牌只做图形标，没有字标（前 18 个月靠投放硬砸）。
6. 徽章标直接缩到 24px 用（必糊）。
7. 动态标没有静态兜底版。
8. 标志不用网格，靠手调贝塞尔（换个尺寸就歪）。
9. 标志里出现三档以上笔画。
10. 端点风格混用（一半平头一半圆头）。
11. 自己给 App 图标切圆角（Apple 明确禁止，会破坏高光）。
12. 主色先定死，再手调 12 个色值凑色阶（必然错序）。
13. 主色直接当图表分类色（抢注意力且分不清类别）。
14. 语义色与主色同色相（"错误"看起来像"强调"）。
15. 暗色模式直接把品牌色反相（应该 tone 重映射）。
16. 中文用 500 字重（伪粗，笔画粘连）。
17. 中文 logo 加大字距冒充高级感。
18. 图标混用两套（2dp 与 1.5px 并置）。
19. 只交付 PNG，没有转曲的 SVG / AI（合作方永远改不动）。
20. 没做商标检索就大规模投放（可能被迫改标）。

## 20. 自检 18 项（交付前逐条打勾）

1. 能说出 3 个形容词 + 3 个反义词，且每个词能落到 §3.2 六维表的 ≥2 个维度？
2. 标志类型是主动选的（§4 决策树），不是"画着画着变成这样"？
3. 标志画在 24 网格上，基形取自方/圆/竖矩/横矩之一？
4. 笔画只有两档，端点与转角风格统一？
5. 做过光学修正（圆溢出、尖角收、接点收口、重心上压）？
6. 清space 有明确单位与四个方向的数值（不是"留足空间"）？
7. 有 40px / 10mm 最小尺寸，且知道小尺寸从哪一档开始换版？
8. 响应式四档齐全（主组合 / 简化 / 仅符号 / 仅字标），每档都过 24px 检验？
9. 种子色跑过色阶，第 9 档与第 11 档都成立？
10. 主色做按钮底 + 白字过 4.5:1？非文本（边框/图标）过 3:1？
11. 色阶无错序（9 不比 10 亮，11 不比 12 亮）？
12. 亮/暗双主题走的是 tone 映射，不是反色？
13. 语义色四档与主色不同色相？
14. 字体 ≤2 族、字重 ≤3 档，中文无伪粗伪斜，数字开了 `tabular-nums`？
15. 图标与标志同网格同笔画，交互图标热区 ≥44×44？
16. 插画/影像的五参数（视角/光源/材质/密度/色域）写清了吗？
17. 语气四维定位 + 3 个语气词 + 反语气词，且错误文案不用幽默？
18. 交付包无缺件（SVG 全档 / ico / 180 / 192 / 512 / maskable / 1024 / OG / 手册）？商标类别与素材授权链查过？
