# 数据可视化规范 · Data Visualization

> 快照 2026-10-31 ｜ 取源：FT Visual Vocabulary（九类关系）、IBM Carbon 数据可视化色板（精确 hex）、AntV G2 源码（色板与坐标轴数值，v5 master 实测）、Ant Design 可视化规范、Datawrapper 双轴指南（2018 旧文 + 2026-07 新指南）、W3C WCAG 2.2 SC 1.4.11
> 用法：**先读 §1 判关系 → §2 选图形 → §3 取色 → §4~§6 定参数**。数值均可追溯，标「建议值」的可按项目调整。

---

## 0. 四条总原则（AntV 官方，可直接引用）

| 原则 | 含义 | 落地动作 |
|---|---|---|
| **准确** | 从数据到视觉不歪曲、不误导、不遗漏 | 柱状图必须 0 基线；不用面积/角度表达需要精确比较的量 |
| **有效** | 克制不冗余，最大化 data-ink ratio（Tufte） | 删网格、删边框、删图例（能直标就直标）、删背景色 |
| **清晰** | 最少时间获取最多信息 | 一图一结论；标题写结论不写"XX 趋势图" |
| **美** | 合理利用视觉元素，不过度修饰 | 一套色板贯穿；不加阴影/3D/渐变装饰 |

**交互三层**（AntV）：数据获取 → 信息加工 → 知识流转；口诀「**概览第一，聚焦过滤，再按需查看详情**」。做仪表盘时按这个顺序设计，不要一上来就给明细表。

## 1. 先判关系，再选图形（FT Visual Vocabulary 九类）

FT 的核心主张：**按"你要表达什么关系"组织，而不是按"你会画什么图"组织**。选图前先回答"我想让读者看到什么关系"。

| 关系 | 读者要问的问题 | 首选图形 | 备选 | 慎用 |
|---|---|---|---|---|
| **偏差 Deviation** | 比参照点高了还是低了？ | 分歧条形图（正负分列） | 分歧堆叠条形（Likert 量表）、脊线图、盈余/赤字填充折线 | 双轴 |
| **相关 Correlation** | 两个变量一起变吗？ | 散点图 | 气泡图（第三变量用大小）、连线散点（随时间演化）、XY 热力图 | 折线（会被误读为时间） |
| **排名 Ranking** | 谁在前谁在后？ | 有序条形图（降序） | 点带图、斜率图（排名变化）、棒棒糖图 | 无序柱状图 |
| **分布 Distribution** | 值集中在哪、有多不均？ | 直方图 | 箱线图、小提琴图、人口金字塔、累积曲线 | 只用平均值概括 |
| **随时间变化** | 趋势往哪走？ | 折线图 | 柱形（单一序列）、面积（总量）、扇形预测图、日历热力图 | 面积图（各部分细微变化看不出） |
| **部分与整体** | 各成分占多少？ | 堆叠柱（≤3 成分） | 比例堆叠条形、环形图（中心放总计）、矩形树图（层级）、瀑布图（有负项） | 饼图（难比较相邻扇区） |
| **数量 Magnitude** | 谁大谁小？ | 柱形 / 条形（**必须 0 基线**） | 成对柱、比例符号、象形图（**仅整数**）、雷达图（≤6 维） | 截断轴 |
| **空间 Spatial** | 地理模式重要吗？ | 分级统计地图（**用比率不用总量**） | 比例符号（用总量）、流向图、等值线图、点密度 | 只当地理真的重要时才用 |
| **流向 Flow** | 从哪流到哪、多少？ | 桑基图 | 瀑布图（顺序过程）、和弦图（双向）、网络图 | 用它表达"占比" |

**判断顺序**：① 有没有时间维度？有 → 折线优先。② 有没有地理维度且地理是主角？是 → 地图。③ 是不是部分与整体？是 → 先问"读者只关心各成分大小吗"，是则改用条形（Magnitude）。④ 其余按上表。

**反直觉的一条**：**排序是免费的洞察**。任何类别比较，先降序排列再画——读者 0 成本获得排名信息。

## 2. 图表选型决策树（30 秒版）

```
数据里有几个变量？
├─ 1 个数值 + 1 个类别
│   ├─ 类别 ≤ 12  → 条形图（横向，降序）
│   └─ 类别 > 12  → Top N + "其他"，或小倍数分面
├─ 1 个数值 + 1 个时间
│   ├─ 序列 ≤ 5   → 折线图
│   └─ 序列 > 5   → 高亮 1–2 条 + 其余灰（不是 10 种颜色！）
├─ 2 个数值        → 散点图（>200 点加透明度 0.4–0.6 或六边形分箱）
├─ 1 个数值 + 时间 + 类别
│   ├─ 类别 ≤ 3   → 分组柱 / 多条折线
│   └─ 类别 > 3   → 小倍数（small multiples），每格独立 Y 轴
└─ 部分与整体
    ├─ 成分 ≤ 3   → 堆叠柱 / 环形
    ├─ 成分 4–5   → 环形（中心放总计）
    └─ 成分 > 5   → 条形图 + 百分比（放弃饼）
```

**硬上限（超过就换图形，不要硬塞）**：

| 元素 | 上限 | 超限怎么办 |
|---|---|---|
| 饼图/环形扇区 | **5** | 改条形；或 Top4 + 其他 |
| 折线序列 | **5** | 小倍数；或高亮 1–2 条其余 30% 灰 |
| 颜色编码类别 | **7**（可到 10，见 §3.4） | 直接标注替代颜色编码 |
| 横向条形类目 | **12**（一屏内） | 滚动或分面 |
| 雷达图维度 | **6** | 改平行坐标或条形矩阵 |
| 一屏图表数 | **5** | 拆页签 / 分层下钻 |

## 3. 色板：三类用途，不许混用

**这是数据可视化里最容易翻车的一环。** 三类色板解决三个不同问题，混用等于撒谎：

| 类型 | 用于 | 数量 | 关键约束 |
|---|---|---|---|
| **分类 Categorical** | 无序的离散类别（产品线、地区） | 3–14 | 相邻色必须高对比；**按固定顺序取用** |
| **顺序 Sequential** | 有大小顺序的连续值（销售额、温度） | 3–9 阶 | 单一色相，明度单调递进 |
| **发散 Diverging** | 有中点且中点有意义（同比增减、偏离均值） | 7–9 阶 | **必须对称**，中点必须是对应 0 的浅色/中性色 |

### 3.1 分类色板 · Carbon 14 色（IBM，精确值，**必须按序取用**）

原文规定：`"The colors of this palette should be applied in sequence strictly as described below."` —— 顺序经专门编排以最大化相邻色对比度。**不要自己挑颜色、不要按品牌色重排。**

| # | 色名 | Hex | | # | 色名 | Hex |
|---|---|---|---|---|---|---|
| 01 | Purple 70 | `#6929c4` | | 08 | Blue 80 | `#002d9c` |
| 02 | Cyan 50 | `#1192e8` | | 09 | Magenta 50 | `#ee538b` |
| 03 | Teal 70 | `#005d5d` | | 10 | Yellow 50 | `#b28600` |
| 04 | Magenta 70 | `#9f1853` | | 11 | Teal 50 | `#009d9a` |
| 05 | Red 50 | `#fa4d56` | | 12 | Cyan 90 | `#012749` |
| 06 | Red 90 | `#570408` | | 13 | Orange 70 | `#8a3800` |
| 07 | Green 60 | `#198038` | | 14 | Purple 50 | `#a56eff` |

若类别数已知且少（≤4），Carbon 提供单色组方案（同一色相族，靠明度区分）：`#6929c4` → `#002d9c` → `#1192e8` → `#005d5d`。

### 3.2 分类色板 · AntV 默认 10 色（中文项目常用，G2 v5 源码实测）

```
#5B8FF9  #5AD8A6  #5D7092  #F6BD16  #6F5EF9
#6DC8EC  #945FB9  #FF9845  #1E9493  #FF99C3
```

配套语义色（状态用，**不要当分类色**）：危险 `#F4664A`｜成功 `#30BF78`｜警告 `#FAAD14`。
G2 另有 20 色版（10 主色 + 10 同族浅色 `#CDDDFD #CDF3E4 #CED4DE #FCEBB9 #D3CEFD #D3EEF9 #DECFEA #FFE0C7 #BBDEDE #FFE0ED`），仅在类别 >10 时使用。

**两套色板选一套用到底**，不要在一个产品里混用 Carbon 与 AntV。

### 3.3 顺序色板（连续值 / 热力 / 地图）

**规则（Carbon 原文）**：浅色主题下**最深 = 最大**；深色主题下**最浅 = 最大**。这条搞反是热力图最常见的错误。

Carbon Blue 10 阶：`#edf5ff #d0e2ff #a6c8ff #78a9ff #4589ff #0f62fe #0043ce #002d9c #001d6c #001141`
Carbon Purple 10 阶：`#f6f2ff #e8daff #d4bbff #be95ff #a56eff #8a3ffc #6929c4 #491d8b #31135e #1c0f30`
Carbon Teal 10 阶：`#d9fbfb #9ef0f0 #3ddbd9 #08bdba #009d9a #007d79 #005d5d #004144 #022b30 #081a1c`

AntV 单色顺序 9 阶（蓝）：`#B8E1FF #9AC5FF #7DAAFF #5B8FF9 #3D76DD #085EC0 #0047A5 #00318A #001D70`

**分级数**：离散分级 **5–7 档**最易读；超过 9 档人眼分不清，改用连续渐变。等距分箱会让偏态数据全部挤在一档——偏态数据用分位数分箱（每档样本数相近）。

### 3.4 发散色板（同比增减、偏离基准）

**铁律**：中点必须是中性色或极浅色，两侧必须**阶数对称、明度对称**。中点不对称 = 暗示偏移不存在。

Carbon 发散方案 1（红-青，有冷热语义）：红端 `#fff1f1 #ffd7d9 #ffb3b8 #ff8389 #fa4d56 #da1e28 #a2191f #750e13` ｜ 青端 `#e5f6ff #bae6ff #82cfff #33b1ff #1192e8 #0072c3 #00539a #003a6d`
Carbon 发散方案 2（紫-青绿，**无冷热语义**，用于性能/销售/变化率）：紫端 `#f6f2ff #e8daff #d4bbff #be95ff #a56eff #8a3ffc #6929c4 #491d8b` ｜ 青绿端 `#d9fbfb #9ef0f0 #3ddbd9 #08bdba #009d9a #007d79 #005d5d #004144`

**选择规则**：数据本身有"好/坏"或"热/冷"语义（增减、温度、风险）→ 红青；没有语义（只是偏离均值）→ 紫青绿。**不要用红绿发散**——色盲读者完全无法区分。

### 3.5 状态色（警报）

`#da1e28` 错误/危险 ｜ `#ff832b` 严重警告 ｜ `#f1c21b` 常规警告 ｜ `#198038` 正常/成功（Carbon 精确值）

**状态色不进分类色板**：一个分类序列里出现红色，读者会以为那一类"有问题"。

### 3.6 选色纪律（六条）

1. **先问有几个类别**，再决定用哪种色板；不要先选好看的颜色再套数据。
2. **类别 ≤ 2 时不要图例**——直接在线末端/柱末端标注，省一次视线跳跃。
3. **不要用渐变装饰**。Carbon 明确：渐变不得替代顺序色板、不得表达递进或发散。
4. **品牌色只能占一个位置**：把品牌色放在分类色板第 1 位（最重要类别），其余按规范顺序取。
5. **深色模式不是反色**：提高明度、降低饱和；分类色在深底上需提亮约 10–15%，否则对比不足（见 §9）。
6. **颜色必须能通过 §9 的对比度检查**——线宽 1px 的细线尤其容易被低估。

## 4. 坐标轴铁律（含 G2 精确数值）

### 4.1 三条不可违反的

1. **柱状图 / 面积图 / 堆叠图必须从 0 开始**。截断基线等于用长度撒谎。折线图可以截断（趋势比绝对值重要），但**必须**在轴上留截断符号或直接标注首末值。
2. **刻度值必须"整"**：取 1 / 2 / 2.5 / 5 × 10ⁿ（0、25、50、75、100；不要 0、3、6、9、12）。
3. **刻度数量 4–6 条（含 0）**。超过 7 条网格线就变成背景噪声。

### 4.2 数值规格（AntV G2 v5 light 主题，源码实测，可直接抄）

| 元素 | 规格 |
|---|---|
| 轴线 | 1px `#BFBFBF`（BLACK_COLORS[25]） |
| 刻度线 | 长 4px、1px `#BFBFBF`；次刻度长 2px、`#D9D9D9` |
| 轴标签 | **12px**、`#8C8C8C`、行高 12px、距轴线 **8px**、常规字重 |
| 轴标题 | 12px、`#595959`、距轴标签 12px |
| 网格线 | 1px `#D9D9D9`、**不加虚线**（`lineDash: null`） |
| 图例项文字 | 12px、`#595959`；marker 半径 4px；项间距 24px；与绘图区间距 8px |
| Tooltip | 12px、值加粗；白底 95% 不透明、圆角 3px、阴影 `0 0 10px #aeaeae`；十字准线 1px |
| 数据标签 | 12px、`#595959` |

### 4.3 布局规则

- **网格线只保留横向**（柱状/折线）。纵向网格线删掉——它和柱子重复。
- **类别 > 8 个改用横向条形图**，不要旋转 45° 标签。旋转标签是最后手段；优先级：改横向 > 缩写 > 换行 > 旋转。
- **Y 轴单位放轴标题**（「销售额（万元）」），**不要**在每个刻度重复"万"。
- **双 Y 轴默认禁用**（见 §10.2）。
- 图表四周留白 ≥ 16px，防轴标签被卡片裁切。
- 轴标题不是必需的：如果标题已经说清单位（"2026 年营收（亿元）"），删掉轴标题。

## 5. 图例、标签、注释

**信息优先级：直接标注 > 图例 > Tooltip**。每往下一级，读者多一次视线跳跃。

| 场景 | 做法 |
|---|---|
| 1–2 条序列 | **不要图例**，线末端直接写序列名（末端留 8px 空隙，字色同线色） |
| 3–5 条序列 | 图例放顶部左对齐（不要放右侧，中文标签会挤压绘图区）；图例顺序 = 数据顺序，不按字母 |
| 类别型条形图 | 不要图例、不要 Y 轴标签，**类目名直接写在柱左侧** |
| 需要强调某点 | 用**注释**（annotation）：一个点 + 一条引线 + 一句话，比加粗颜色有效 10 倍 |
| 数据来源 | 图表下方 12px 灰字，格式「数据来源：XX，2026 年 10 月」。**没有来源的图表不可信** |

**标题写结论，不写描述**：
- ❌「各渠道销售额趋势图」 ✅「直播渠道 3 个月翻了 4 倍，超过搜索成为第一」
- 副标题补口径：「单位：万元｜不含退款」

**Tooltip 规则**：必须含**单位**；多序列时按值降序排列；数值右对齐便于纵向比较；触摸端点击即显示（不要只做 hover）。

## 6. 中文数字与单位（中文项目必做）

| 场景 | 规则 | 示例 |
|---|---|---|
| 大数（≥1 万） | 用「万」「亿」「万亿」，**不写全数字** | `1.2亿`、`3456万`、`1.8万亿` |
| 大数精度 | 保留 **1 位小数**；≥100 时可取整 | `1.2亿`、`1234万` |
| 千分位 | 仅用于**明细/金额/非中文语境**；图表轴标签不用 | `1,234,567` |
| 百分比 | **1 位小数**；<0.1% 写 `<0.1%`，不写 `0.0%` | `23.4%` |
| 增减 | 带符号 + 颜色（红涨绿跌，**中国习惯**） | `+12.3%`（红）、`-4.1%`（绿） |
| 单位位置 | 放轴标题或图表副标题，**刻度上不重复** | 「销售额（万元）」 |
| 时间轴 | 中文用「1月」不用「Jan」；跨年标年份 | `1月 2月 … 12月` |
| 货币 | `¥` 在前，`元` 在后不重复 | `¥1,280` 或 `1280元` |

**中文图表字号比英文 +1px**：轴标签 12px 在中文里偏小，**建议 12–13px，下限 11px**；数据标签 13–14px。中文字宽等宽，同样的 12px 中文比英文"重"，行高需 1.4–1.5（英文 1.2 即可）。

**中文排版联动**：图表内的长类目名遵循 `chinese-design.md` §1.6 行长规则，横向条形图类目列宽建议 ≤ 12 字，超长截断 + Tooltip 全文。

## 7. 仪表盘布局

**结构顺序按读者的决策路径，不按数据表顺序**：结论（KPI）→ 趋势（折线）→ 结构（占比/排名）→ 明细（表格）。

| 层级 | 内容 | 规格（建议值） |
|---|---|---|
| **L1 KPI 卡** | 核心指标数值 + 同比 | 数值 **28–32px / 600 字重**；标签 12–14px 灰；同比 12px 带箭头；一屏 **≤ 6 张** |
| **L2 趋势图** | 主指标折线/面积 | 卡片高 **240–320px**；一屏 ≤ 3 张 |
| **L3 结构图** | 排名条形、环形占比 | 高 240px；环形直径 ≤ 200px |
| **L4 明细表** | 可下钻列表 | 行高 40–48px；斑马纹或 1px 分隔线（二选一） |

- **栅格**：12 列，间距 16/24px（与 `design-tokens.md` 的 8 倍数体系一致）；卡片内边距 16–24px。
- **一屏 ≤ 5 张图表**。超过就分页签或下钻，不要靠缩小尺寸塞进去。
- **KPI 卡的数值要能一眼比大小**——用等宽数字（`font-variant-numeric: tabular-nums`），否则数字位数变化时宽度跳动。
- **空状态必须有**：无数据时显示"暂无数据"占位，不要留空白坐标系。
- **加载态用骨架屏**，不要用转圈（图表区域尺寸已知，骨架能避免布局跳动）。

## 8. 图表动效（与 `motion-system.md` 的关系）

图表是**唯一被允许突破 400ms 上限**的场景——因为它不阻塞用户输入，且数据过渡需要可读时间。但这条豁免仅限"图表入场与数据更新"。

**AntV G2 默认值（源码实测，可直接用）**：

| 阶段 | 时长 | 曲线 |
|---|---|---|
| 首次入场 appear | **450ms** | `easeQuadOut`（减速，符合 motion-system §2 语义） |
| 数据更新 update | **400ms** | `easeQuadInOut`（标准） |
| 新增元素 enter | **400ms** | `easeQuadInOut` |
| 移除元素 leave | **350ms** | `easeQuadIn`（加速） |

**规则**：
- 图表入场用**减速**曲线，与 `motion-system.md` 的"入场减速"完全一致；离场 = 入场 × 0.78，接近 §2 的 ×0.7 规则。
- **悬停高亮、Tooltip 出现 ≤120ms**——这条**不豁免**，它属于交互反馈。
- 数据更新时**只动位置/高度/透明度**，不要重播整张图的入场动画（会让用户以为数据重置了）。
- 柱状图增长用 `scaleY`，不要动 `height`（触发布局）。
- 实时数据（每秒刷新）**关掉动画**，否则永远在动。
- `prefers-reduced-motion: reduce` 下：入场动画改 0ms 直接呈现，保留 Tooltip 的颜色反馈。

## 9. 可访问性（图表最容易漏的一节）

**WCAG 2.2 SC 1.4.11 非文本对比度**：理解内容所必需的图形对象，与相邻颜色对比 **≥ 3:1**。原文强调 3:1 是**阈值**，`2.999:1` 不通过，**不可四舍五入**。

| 元素 | 要求 |
|---|---|
| 数据折线 / 柱子 | 与**背景**（含网格线）≥ 3:1 |
| 背景网格线、刻度线 | 与背景 ≥ 3:1（它们承载数值信息） |
| 饼图扇区 | 相邻扇区之间、与背景都要能分辨（≥ 3:1） |
| 相邻折线之间 | 通常不要求（重叠少）；但若紧密缠绕则需 ≥ 3:1 |
| 纯装饰图形 | 不要求 |

**实操警告**：1px 细线经抗锯齿后实际对比度远低于名义值。**折线建议 2px 起**，浅色系（如 `#a6c8ff`）在细线上几乎不可见——要么加粗，要么换深阶。

**不只靠颜色传达**（约 8% 男性有红绿色觉障碍，通行估计约 1/12）：
- 多序列时叠加**形状标记**（实心圆/方/三角）或**线型**（实线/虚线/点线）。
- 红绿**不能**作为唯一区分手段；红绿发散色板禁用。
- 关键结论用**直接文字标注**，不要只靠颜色暗示"这条最高"。
- 深色模式下重新校验对比度，不要沿用浅色模式色值。

**替代方案**：给图表配 `aria-label` 概述结论；复杂图表提供"数据表"切换（这也是色盲与读屏用户的唯一可靠路径）。

## 10. 反模式清单（逐条给改法）

### 10.1 图形与比例
1. **柱状图不从 0 开始** → 改回 0 基线；若差异确实小，改用点图/棒棒糖图（可不从 0）。
2. **用半径而非面积编码数值**（气泡图）→ 半径按 `√value` 缩放，否则面积误差达平方级。
3. **3D 柱、阴影、渐变填充** → 全部删除。3D 让前柱遮挡后柱，比例完全失真。
4. **饼图 > 5 片 / 多个饼图横向比较** → 改条形图或 100% 堆叠条形。
5. **彩虹色表达顺序**（红黄绿蓝紫表示低到高）→ 改单色相顺序色板（§3.3）。
6. **折线连接非时间类别**（如"北京-上海-广州"连线）→ 改条形图；折线的斜率只在时间轴上意味着"速率"。

### 10.2 双 Y 轴（有立场，但要说清条件）

**默认禁用**。Datawrapper 2018 原文的核心论证仍然成立：两个轴的比例是任意的，读者会默认按单轴折线图去读，从而得出"两条线同速增长"这类错误结论（研究：Isenberg et al. 2011 对 15 人的实验显示双轴图在准确率与耗时上全面最差）。

**但 2026-07 有修正**：Datawrapper 自己改口——对**受过训练的受众**（金融、投研），双轴图是展示"同一时点两个指标如何互动"的高效工具。所以判定标准不是图形本身，而是**受众**。

**允许的条件（全部满足才可用）**：
1. 受众是专业读者，且明确知道这是双轴图；
2. 两侧是**不同单位**（元 vs %、℃ vs mm）——单位相同却分轴，读者必然误读；
3. 同一度量的**两种单位**（℃/℉、元/美元）——这是最安全的用法；
4. 帕累托图（柱=频次，线=累计占比）——行业惯例。

**必须做的四件事**：① **对齐两轴的刻度增长率**（等价于索引图，让斜率可比）；② 若一轴从 0 起，另一轴也从 0 起；③ 轴标签与刻度用**与对应序列相同的颜色**；④ 图例写清单位（「销售额（$）」而非「销售额」）。

**更优替代**（按推荐度）：索引图（都设为 100，比增长率）> 并排两图 > 小倍数 > 只画重要的一条 + 注释另一条 > 连线散点图。

### 10.3 表达与标注
7. **Y 轴刻度不整或跳变**（0、3、6、9）→ 改 0、25、50、75、100。
8. **图例离图形太远 / 靠颜色猜对应关系** → 改直接标注。
9. **无单位、无数据来源、无时间口径** → 三者缺一即不可交付。
10. **标题写"XX 趋势图"** → 改写结论式标题。
11. **网格+刻度+标签+图例+注释全开** → 至少删两项；信息密度不等于信息量。
12. **用颜色编码 6 个以上类别** → 改直接标注或小倍数（见 §3.4 上限表）。

## 12. 自检 12 项（图表交付前逐条过）

1. **关系对了吗**：图形是否匹配 §1 的关系类型？（不是"我觉得好看"）
2. **0 基线**：柱/面积是否从 0 起？折线若截断是否标注？
3. **刻度整、少**：4–6 条？值是否 1/2/2.5/5 × 10ⁿ？
4. **色板类型对**：分类/顺序/发散是否用对？有没有拿顺序色板当分类用？
5. **分类顺序**：是否按 §3.1 固定顺序取色？类别数是否超上限？
6. **颜色不超载**：同屏 ≤ 7 种语义色？图例能删吗（能直标就直标）？
7. **对比度**：数据线/柱与背景 ≥ 3:1？细线是否够粗（≥2px）？
8. **不只靠颜色**：色盲读者能否区分（形状/线型/直标）？
9. **中文数字**：万/亿用对？百分比 1 位小数？单位是否只在轴标题出现一次？
10. **标题与来源**：标题是结论吗？单位、口径、数据来源齐吗？
11. **动效克制**：入场 450ms 减速？悬停 ≤120ms？实时数据关动画？
12. **状态齐全**：空数据、加载中、异常、数据量放大 10 倍——四种情况都成立吗？
