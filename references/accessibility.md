# 可访问性实操（Accessibility in Practice）

> 快照 2026-11-01 · 依据 WCAG 2.2 正式推荐标准（W3C，2023-10-05）、WAI-ARIA APG、GOV.UK / Carbon / Ant Design 官方实现、GB/T 37668-2019 与工信部适老化规范。

> 与其它文件的边界：表单侧细节在 `form-table.md` §11，图表对比度在 `dataviz.md` §9，动效降级在 `motion-system.md` §8，本文件负责**界面侧的全量落地**。

## §1 先定判定口径（否则后面全是空谈）

### 1.1 WCAG 2.2 的结构

- WCAG 2.1 有 78 条成功标准；2.2 **新增 9 条、废弃 1 条**（4.1.1 Parsing）→ 合计 **86 条**。
- 四级原则：**可感知（Perceivable）/ 可操作（Operable）/ 可理解（Understandable）/ 健壮（Robust）**。
- 等级是**累积**的：声称 AA，意味着同时满足全部 A + 全部 AA。**不存在"部分符合 AA"**——要么整站符合，要么写"部分符合，未覆盖 X 页面"。

### 1.2 2.2 新增的 9 条（这轮升级的主要增量）

| 编号 | 名称 | 级别 | 一句话判定 |
|---|---|---|---|
| 2.4.11 | Focus Not Obscured (Minimum) | AA | 键盘聚焦的元素**不得被作者内容完全遮住** |
| 2.4.12 | Focus Not Obscured (Enhanced) | AAA | 一点都不许遮 |
| 2.4.13 | Focus Appearance | AAA | 焦点框面积 ≥ 2px 周长面积，且状态变化对比 ≥ 3:1 |
| 2.5.7 | Dragging Movements | AA | 拖动操作必须有单指/单击替代路径 |
| 2.5.8 | Target Size (Minimum) | AA | 目标 ≥ **24×24 CSS px**（或满足间距例外） |
| 3.2.6 | Consistent Help | A | 帮助入口在多个页面的**相对顺序一致** |
| 3.3.7 | Redundant Entry | A | 同一流程内不重复索要已填信息 |
| 3.3.8 | Accessible Authentication (Minimum) | AA | 认证不得强制认知功能测试（含禁阻粘贴） |
| 3.3.9 | Accessible Authentication (Enhanced) | AAA | 连对象识别也不许 |

### 1.3 本技能的默认目标线

- **默认 AA**：这是法律与采购的实际门槛（欧盟 EAA、美国 ADA 判例、国内适老化评测均以 AA 为基线）。
- **AAA 只挑三条做**：2.4.13 焦点外观、1.4.6 正文对比 7:1、2.4.12 焦点不遮挡。这三条成本低、收益高。其余 AAA（如手语视频、1.4.8 视觉呈现）成本高，按项目预算决定，**不要口头承诺"我们做 AAA"**。

## §2 对比度：四个阈值、一条铁律、一个中文陷阱

### 2.1 四个阈值（精确值，不许记错）

| 场景 | 条款 | 阈值 |
|---|---|---|
| 正文文本（AA） | 1.4.3 | **4.5:1** |
| 大文本（AA） | 1.4.3 | **3:1** |
| 正文文本（AAA） | 1.4.6 | **7:1** |
| 非文本（图标、边框、图表元素、焦点框）（AA） | 1.4.11 | **3:1** |
| 焦点**状态变化**对比（AAA） | 2.4.13 | **3:1** |

**大文本的精确边界**（W3C 原文）：`≥ 18pt`（≈ **24px**）或 `≥ 14pt 粗体`（≈ **18.5px**）。换算 `1pt = 1.333px`。
→ 中文正文 16px **不算大文本**，必须按 4.5:1 判。很多团队把 18px 当大文本放过，是错的。

### 2.2 铁律：**不可四舍五入**

W3C 原文：`4.499:1` **不满足** 4.5:1。工具显示 "4.5" 时要看三位小数。设计交付前把色值代进公式自己算一遍：
`(L1 + 0.05) / (L2 + 0.05)`，L 为相对亮度，取值域 1:1 ~ 21:1。

### 2.3 灰阶速查（省去每次开工具）

以纯白 `#FFFFFF` 为背景，正文需 4.5:1 → 文字不得浅于 **#767676**（约 4.54:1）。
黑底 `#000000` 上正文需 4.5:1 → 文字不得深于 **#767676** 同档（对称）。

常用安全值（白底）：

| 用途 | 安全色 | 约对比度 |
|---|---|---|
| 正文主色 | `#1F1F1F` | 15.9:1 |
| 正文次级 | `#595959` | 7.0:1 |
| 正文下限（仍达标） | `#767676` | 4.54:1 |
| 禁用/占位（**不达标**，仅装饰） | `#BFBFBF` | 1.85:1 |
| 链接（可辨且达标） | `#0B57D0` | 7.3:1 |
| 分隔线（非文本，需 3:1） | `#949494` | 3.03:1 |
| 分隔线（**不达标**，常见错误） | `#E5E5E5` | 1.26:1 |

> **`#E5E5E5` 分隔线是中文后台第一号对比度事故**：视觉上"很干净"，但对低视力用户等于没有。要么加深到 `#949494`，要么承认它只是装饰、不承担"分隔"语义。

### 2.4 中文特有的对比度陷阱

拉丁字母笔画细、字腔大；汉字笔画密度高、字腔小。**同样的对比度，中文的可读性明显更差**，尤其是 12–14px 的细体。

三条修正（本技能立场，非 WCAG 条文）：

1. **中文正文按 +1 档判**：想写 4.5:1 的地方，实际做到 **≥ 5.5:1**；想写 3:1 的大字标题，做到 **≥ 4:1**。
2. **12px 中文不要用 `#8C8C8C` 以下**：这是中文界面最常见的"浅灰辅助文字"，4.5:1 勉强过线但实际读不动。改 `#595959`。
3. **不要用 `font-weight: 300` 承载正文**：中文字体多数无 Light 字重，浏览器会**伪细体**（算法描边），笔画断裂后对比度名义达标、实际崩坏。

## §3 焦点可见：三层标准叠着用

焦点是键盘用户的"鼠标指针"。三层标准必须**同时**满足：

| 层 | 条款 | 要求 | 级别 |
|---|---|---|---|
| 有 | 2.4.7 Focus Visible | 必须存在可见焦点指示 | AA |
| 够显眼 | 2.4.13 Focus Appearance | 面积 ≥ 2px 周长面积；状态变化对比 ≥ 3:1 | AAA |
| 与周围分得开 | 1.4.11 Non-text Contrast | 焦点框与**相邻颜色** ≥ 3:1 | AA |

**关键区别**（最容易搞混）：2.4.13 管"聚焦前后同一像素的变化对比"，1.4.11 管"焦点框与旁边背景的相邻对比"。两个都过才算合格。文档给了两个互补反例：浅灰焦点框在白底上过了变化对比、但过不了相邻对比；深灰框在黑色边框旁过了相邻对比、但过不了变化对比。

### 3.1 面积怎么算（2.4.13 的唯一硬指标）

- 贴边实心框：**2px 粗**即达标。
- **内嵌（inset）框：2px 不够，要 ≥ 3px**（因为内嵌不占外缘面积）。这是最常踩的坑。
- 面积公式：矩形 `4h + 4w`；圆形 `4πr`；圆角矩形 `4h + 4w − (16 − 4π)r`。
- 例：90×30 按钮的最小面积 = (92×32) − (88×28) = **480 px²**。
- 只计算**达到 3:1 的那部分**。渐变/半透明焦点框按达标部分算面积。

### 3.2 可直接抄的焦点样式（三选一，全站统一）

**A. GOV.UK 方案（最稳，任何背景都能过）** —— 官方功能色：`focus` = `#FFDD00`，`focus-text` = `#0B0C0C`。

```css
/* 文本型可聚焦元素（链接、纯文字按钮） */
:where(a, button.link-like):focus-visible {
  outline: 3px solid transparent;      /* 为强制色彩模式留位 */
  background-color: #FFDD00;
  color: #0B0C0C;
  box-shadow: 0 -2px #FFDD00, 0 4px #0B0C0C;  /* 黄底 + 下方粗黑线 */
  text-decoration: none;
}
/* 有边框/底色的控件（输入框、复选、卡片按钮） */
:where(input, select, textarea, .control):focus-visible {
  outline: 3px solid #FFDD00;
  outline-offset: 0;
  box-shadow: 0 0 0 6px #FFDD00 inset;  /* 内部也铺黄，避免被深色填充吃掉 */
}
```

黄 `#FFDD00` 对深底高对比、黑 `#0B0C0C` 对浅底高对比——**双色**是它能在任意背景上通过 1.4.11 的原因。单一颜色的焦点框在"同色系背景"上必然翻车。

**B. 双环方案（现代 SaaS 常用，浅深通吃）**

```css
:where(a, button, input, select, textarea, [tabindex]):focus-visible {
  outline: 2px solid #FFFFFF;          /* 内环：与深色元素分开 */
  outline-offset: 2px;
  box-shadow: 0 0 0 4px #0B57D0;       /* 外环：与浅色背景分开 */
}
```
必须**两个环**：内环解决"焦点框贴在深色按钮上看不见"，外环解决"焦点框贴在白底上看不见"。

**C. 只在深色界面用**：`outline: 2px solid #7CC4FF; outline-offset: 2px;` —— `#7CC4FF` 在 `#1A1A1A` 上约 8:1，在 `#2D2D2D` 上约 5.9:1。

### 3.3 `:focus-visible` 的纪律

- **只用 `:focus-visible`，不用 `:focus`** 做视觉样式。`:focus` 会让鼠标点击也出现焦点框（用户觉得丑）→ 团队就会 `outline: none` → 键盘用户彻底失去焦点。
- **永远不要写 `outline: none` / `outline: 0` 而不给替代**。这是 2.4.7 的第一号失败原因。
- 需要"点了不显示、Tab 才显示"时，用 `:focus-visible` 而非 JS 判断（浏览器已内置启发式：键盘触发显示、指针触发隐藏）。
- **自定义组件（div/li 当按钮）必须自己加 `:focus-visible`**——原生控件有 UA 默认样式，div 没有。

### 3.4 焦点反模式（逐条对照）

1. `outline: none` 且无替代 → 直接失败 2.4.7。
2. 只在 `:hover` 里加视觉变化、`:focus` 无变化 → 键盘用户看不到位置。
3. 焦点框 `1px` → 面积不足，2.4.13 失败。
4. 内嵌焦点框 `2px` → 面积不足（内嵌要 ≥3px）。
5. 焦点框颜色 = 主色 → 在品牌色按钮上完全隐形。**焦点框与主色必须是两种颜色**。
6. 用 `box-shadow` 做焦点框但被 `overflow: hidden` 裁掉 → 上下两边的框消失。
7. 卡片整体 `overflow: hidden` + 内部元素焦点框外扩 → 同上。

## §4 键盘：顺序、陷阱、返回

### 4.1 Tab 顺序

- 顺序 = **DOM 顺序**。视觉顺序必须与 DOM 顺序一致；用 `order` / `grid-area` / `flex-direction: row-reverse` 改视觉顺序会造成焦点跳跃。
- `tabindex` 只允许两个值：**`0`**（加入 Tab 序列）和 **`-1`**（可编程聚焦、不进 Tab 序列）。
- **`tabindex > 0` 一律禁止**——它会插队，产生不可预测的顺序。全站搜 `tabindex="1"` 到 `tabindex="9"`，有就改。

### 4.2 跳转链接（Skip link）

每个页面第一个可聚焦元素应是"跳到主内容"：

```html
<a class="skip" href="#main">跳到主要内容</a>
<main id="main" tabindex="-1">…</main>
```
```css
.skip{position:absolute;left:-9999px}
.skip:focus-visible{left:8px;top:8px;z-index:9999;background:#fff;padding:8px 16px;outline:3px solid #0B57D0}
```
`tabindex="-1"` 让 `<main>` 能被聚焦（否则点击跳转后焦点丢失在 body 上，下次 Tab 从页首重新开始）。中文文案写「跳到主要内容」，不要写「Skip to content」。

### 4.3 模态：焦点必须被管住

按 WAI-ARIA APG Dialog (Modal) 的硬要求：

1. 打开时**焦点移入对话框内**（第一个可聚焦元素；内容复杂时给标题加 `tabindex="-1"` 先聚焦标题，避免一进来就落在"关闭"上）。
2. `Tab` / `Shift+Tab` **在框内循环**，不得跑到背景。
3. `Escape` 关闭。
4. 关闭后**焦点回到触发元素**（触发元素已不存在时，回到逻辑上的下一步）。
5. 容器 `role="dialog"` + `aria-modal="true"` + `aria-labelledby` 指向可见标题。
6. **`aria-modal="true"` 只在真的模态时用**：必须同时满足"代码阻止所有人操作背景"+"视觉遮住背景"。否则屏幕阅读器用户会被困在假模态里。
7. 背景禁用优先用 **`inert`**（原生、自动处理焦点与辅助技术），不要手写 `aria-hidden` + `tabindex="-1"` 遍历（易漏、易与焦点管理打架）。

```html
<div role="dialog" aria-modal="true" aria-labelledby="dlg-title">
  <h2 id="dlg-title" tabindex="-1">删除这条记录？</h2>
  …
</div>
```
```js
// 打开：背景 inert，焦点入框
bg.inert = true; title.focus();
// 关闭：还原
bg.inert = false; trigger.focus();
```

**Drawer / 气泡卡片 / 下拉菜单**同理，但非模态的**不要** `aria-modal`、**不要** `inert` 背景——它们允许用户同时看背景。

### 4.4 焦点可见性之外：焦点不能丢

- 删除列表项后，焦点会掉到 `body`。必须手动把焦点移到**逻辑邻居**（下一项，或空态的"新建"按钮）。
- 路由切换（SPA）后，焦点要移到新页面 `<h1>`（`tabindex="-1"`），否则读屏用户不知道页面变了。
- 异步加载"更多"后，焦点保持在触发按钮上，并用 `aria-live` 播报"已加载 20 条"。

## §5 焦点不被遮挡（2.4.11）：粘性栏的账要还

判定是**二值**的：组件被作者内容**完全**遮住 → 失败（F110）；哪怕露一条边 → AA 通过。

但"露一条边"仍然难用。工程解法只有三个：

1. **`scroll-padding`**（充分技术 C43）：给滚动容器留出粘性栏的高度。

```css
html { scroll-padding-top: 80px; }        /* 吸顶导航 64px + 16 余量 */
.sticky-footer ~ main { scroll-padding-bottom: 72px; }
```

2. **位移式**：展开时把内容推下去（accordion 的正确做法），而不是盖上去。
3. **失焦自动收起**：非必要常驻的浮层（客服气泡、通知条）在焦点离开时收起。

**Cookie 横幅 / 公告条**：要么做成模态（必须先处理）、要么用 `scroll-padding` 让开、要么在失焦时自动关闭。三者选一，不能"就让它盖着"。

## §6 目标尺寸：24 是底线，44 是好用，48/60 是适老

### 6.1 2.5.8（AA）的精确判定

- 目标区域必须能完整容纳一个 **24×24 CSS px 的轴对齐正方形**。圆角、裁剪、异形都会导致装不下 → 判定"undersized"。
- **与缩放无关**：用户放大页面时 CSS px 不变，不能用"放大后就够大"辩解。

**间距例外（唯一豁免路径）**：对每个 <24×24 的目标，以其**最小边界框中心**为圆心画 **直径 24px 的圆**（半径 12px），该圆**不得与任何其它目标、或其它 undersized 目标的圆相交**。

→ 实操含义：**图标按钮 16×16 可以，但相邻两个之间至少留 8px 空隙**（两个半径 12 的圆不相交）。这是"小图标密集排布"的唯一合法姿势。

**另外三个豁免**：内联文本中的链接（受行高约束）、UA 决定且作者未改的控件（如默认滚动条）、同页存在等效控件。

### 6.2 本技能的三档目标尺寸

| 场景 | 尺寸 | 依据 |
|---|---|---|
| 桌面端图标按钮（最低） | **24×24**，间距 ≥8px | WCAG 2.5.8 AA |
| 触屏 / 移动端（默认） | **44×44** | WCAG 2.5.5 AAA + Apple HIG 44pt + 适老化"其他页面" |
| 适老版界面主组件 | **60×60 dp/pt** | 工信部《APP 适老化通用设计规范》 |
| 独立适老版 APP 首页主组件 | **48×48 dp/pt** | 同上 |
| 中文移动端表单控件 | 高度 **≥44px** | 与 `form-table.md` §4 的 Carbon 48 档对齐 |

**视觉尺寸 ≠ 点击尺寸**：图标画 16px，热区用 padding 撑到 44×44。不要靠"图标画大"来解决。

```css
.icon-btn{width:44px;height:44px;display:grid;place-items:center}
.icon-btn svg{width:20px;height:20px}
```

## §7 拖动必须有替代（2.5.7）

条文：所有用拖动完成的功能，必须能用**单指针不拖动**完成（除非拖动是 essential，或功能由 UA 决定且作者未改）。

| 常见拖动交互 | 合规替代（必须提供其一） |
|---|---|
| 滑块调值（音量/价格区间） | 可聚焦 + `←/→` 每次 1、`PgUp/PgDn` 每次 10；或用原生 `<input type=range>`（自带键盘） |
| 拖拽排序列表 | 每项提供"上移/下移"按钮；或用 `↑/↓` 键 + `aria-live` 播报新位置 |
| 拖拽上传文件 | 同时提供"选择文件"按钮（必须，不是可选） |
| 拖拽画布/看板 | 提供"移动到…"菜单 |
| 拖动裁剪图片 | 提供数值输入框（X/Y/缩放） |
| 拖动调整表格列宽 | 提供"重置列宽" + 双击自动适配 |

**最省事的判断**：凡是"必须按住并移动"才能完成的操作，都要问一句"键盘用户怎么办"。答不上来就是不合规。

## §8 语义与 ARIA：原生优先，ARIA 是补丁不是方案

### 8.1 第一原则

> **No ARIA is better than Bad ARIA.**（APG 原文）

原生元素自带角色、状态、键盘行为、焦点管理、强制色彩模式适配。用 `<button>` 能得到 5 件事，用 `<div role="button">` 能得到 0 件。

| 需求 | 正确 | 错误 |
|---|---|---|
| 按钮 | `<button>` | `<div onclick>` |
| 链接（跳转） | `<a href>` | `<span onclick>` |
| 折叠面板 | `<button aria-expanded>` + 区域 | `<div class="toggle">` |
| 选项卡 | `role="tablist"/"tab"/"tabpanel"` + 方向键 | 一排 `<a>` 换 class |
| 开关 | `<input type="checkbox" role="switch">` | 两个 span 换颜色 |
| 弹窗 | `<dialog>` 或 `role="dialog" aria-modal` | 绝对定位 div |
| 进度 | `<progress>` | 会动的 div |

### 8.2 四条最容易犯的 ARIA 错误

1. **`aria-label` 覆盖可见文本**：`<button aria-label="关闭对话框">×</button>` 尚可；但 `<button aria-label="提交订单">提交</button>` 会让语音控制用户说"提交订单"点不到——**可见文本必须包含在可访问名称里**（WCAG 2.5.3 Label in Name）。
2. **给装饰图标加 `aria-label`**：装饰性图标应 `aria-hidden="true"`，否则读屏会念一堆无意义的"图标 图标 图标"。
3. **`role="presentation"` 用在可交互元素上**：会把焦点语义抹掉。
4. **`aria-hidden="true"` 包住了可聚焦元素**：焦点进得去、读屏读不到，成为"幽灵焦点"。要么移除 `aria-hidden`，要么把里面的可聚焦元素也 `tabindex="-1"`。

### 8.3 可访问名称的优先级（从高到低）

`aria-labelledby` → `aria-label` → 原生 `<label for>` → 元素内含文本 → `title` → `placeholder`（**最弱，不能当标签**）。

`placeholder` 当标签的三个后果：输入后消失、对比度通常不达标、读屏支持不一致。这是 `form-table.md` §5 的"占位符三宗罪"，此处不重复。

### 8.4 图标按钮必须有名称

```html
<button class="icon-btn" aria-label="搜索"><svg aria-hidden="true">…</svg></button>
```
只有图标、没有可访问名称的按钮，读屏会念"按钮"——用户完全不知道它干什么。

## §9 表单无障碍：只补 `form-table.md` 没说的

`form-table.md` §11 已给 10 条表单可访问性要点。这里补**结构层**的四件事：

### 9.1 错误与帮助的关联（ARIA 侧）

```html
<label for="phone">手机号</label>
<input id="phone" name="phone" type="tel" inputmode="numeric"
       autocomplete="tel-national"
       aria-describedby="phone-hint phone-err"
       aria-invalid="true">
<p id="phone-hint">11 位，不含空格</p>
<p id="phone-err" role="alert">手机号应为 11 位数字，当前 9 位</p>
```

- `aria-describedby` 同时挂**帮助**和**错误**，读屏聚焦时会一起念。
- `aria-invalid="true"` 是状态，不只是红边框。**只变红不给 `aria-invalid`，读屏用户不知道有错**。
- 错误消息用 `role="alert"`（隐式 `aria-live="assertive"`）→ 出现即播报。

### 9.2 错误摘要（多字段表单必做）

提交失败时，在表单顶部放一个可聚焦的错误摘要，列出全部错误并**链接到对应字段**：

```html
<div role="alert" tabindex="-1" class="error-summary">
  <h2>有 3 个问题需要修改</h2>
  <ul>
    <li><a href="#phone">手机号应为 11 位数字</a></li>
    <li><a href="#code">验证码已过期，请重新获取</a></li>
    <li><a href="#agree">需勾选同意条款</a></li>
  </ul>
</div>
```
提交后把焦点移到这个摘要（`tabindex="-1"` + `.focus()`）。这是 GOV.UK Error summary 的标准做法，也是"提交失败后用户不知道错在哪"的正解。

### 9.3 `autocomplete` 是 AA 要求，不是优化项

WCAG 1.3.5 Identify Input Purpose（AA）要求表单字段能**程序化识别用途**。落地就是 `autocomplete`。中文场景高频值：

| 字段 | autocomplete |
|---|---|
| 姓名 | `name` |
| 手机号 | `tel-national`（国内号码）/ `tel` |
| 邮箱 | `email` |
| 验证码（短信） | `one-time-code` ← **最关键**，让 iOS/Android 自动填充 |
| 地址-省 | `address-level1` |
| 地址-市 | `address-level2` |
| 详细地址 | `street-address` |
| 邮编 | `postal-code` |
| 当前密码 | `current-password` |
| 新密码 | `new-password` |

`one-time-code` 漏掉 = 用户必须切 App 抄 6 位数字 = 直接撞 3.3.8。

### 9.4 3.3.7 冗余录入：多步流程必须回填

同一流程内已填信息不得再要一遍，除非：回填会让流程失效（记忆游戏）、安全需要（密码确认）、原信息已失效（验证码过期）。

合规做法：**自动填充** 或 **可选中**（下拉选、勾选"同收货地址"、页面上可见可复制）。浏览器自动填充**不算**——条文明确要求由站点提供。

## §10 动态内容播报：`aria-live` 用对了才有用

| 角色 | 隐式 live | 适用 |
|---|---|---|
| `role="status"` | `polite` | 保存成功、已加载 N 条、筛选结果数变化 |
| `role="alert"` | `assertive` | 表单错误、会话即将过期、操作失败 |
| `aria-live="polite"` | — | 自定义容器（同 status） |
| `aria-live="off"` | — | 默认，不播报 |

四条纪律：

1. **容器必须先存在于 DOM，再改内容**。渲染时才插入的节点不会被播报。做法：页面加载时就有空的 `<div role="status" class="sr-only"></div>`。
2. **`assertive` 要少用**：它会打断用户当前朗读。一屏同时出现 3 个 alert = 读屏灾难。
3. **播报增量，不播报整块**：写"已加载 20 条，共 57 条"，不要重播整个列表。
4. **去抖**：连续输入触发的实时校验不要每次都播报，等 500–800ms 停顿或失焦再播。

```css
.sr-only{position:absolute;width:1px;height:1px;padding:0;margin:-1px;overflow:hidden;
  clip:rect(0 0 0 0);white-space:nowrap;border:0}
```

**加载态**：`aria-busy="true"` 标在更新区域上，完成后置 `false` 并播报结果。骨架屏本身对读屏无意义，必须有文字状态。

## §11 图片、图标、图表的替代文本

### 11.1 alt 决策树（四选一，不许空着）

1. **纯装饰** → `alt=""`（空字符串，明确告诉读屏跳过）。**不要省略 `alt` 属性**，省略会让读屏念文件名。
2. **承载信息** → 写"这张图说了什么"，不写"这是一张图"。❌ `alt="团队合影"` ✅ `alt="2026 年设计团队 12 人在会议室庆祝产品上线"`。
3. **功能性图片**（图片按钮/图片链接）→ 写**动作**：`alt="搜索"`，不是 `alt="放大镜图标"`。
4. **复杂图（图表/流程图/信息图）** → 短 `alt` 给结论 + 正文或 `aria-describedby` 给数据明细。

### 11.2 图表的具体写法

```html
<figure>
  <img src="q3.svg" alt="第三季度营收 1.2 亿元，环比增长 18%">
  <figcaption>数据来源：财务部，2026-10</figcaption>
</figure>
<!-- 或内联 SVG：role="img" + <title> -->
<svg role="img" aria-labelledby="t1"><title id="t1">第三季度营收 1.2 亿元，环比增长 18%</title>…</svg>
```
内联 SVG 若含可聚焦元素或大量 `<path>`，加 `aria-hidden="true"` 并把文字说明放在外部。`dataviz.md` §9 的对比度要求与此处并行：**视觉可读**与**语义可读**是两件事。

### 11.3 图标字体

图标字体（iconfont）的字符读屏会念成乱码。必须：
- 用 `<span aria-hidden="true">&#xe600;</span>` 包住字形；
- 旁边配可见文字或 `aria-label`；
- 更好的做法：改用 SVG symbol。

## §12 不靠颜色单独传达（1.4.1）

条文：颜色不得是传达信息、指示动作、区分元素的**唯一**视觉手段。

| 场景 | 只靠颜色（失败） | 加第二通道（通过） |
|---|---|---|
| 表单错误 | 红边框 | 红边框 + 图标 + 文案 |
| 必填 | 红色 `*` | `*` + "带 * 为必填"说明 |
| 图表序列 | 5 种颜色 | 颜色 + 线型/标记形状/直标 |
| 状态标签 | 绿/黄/红底 | 颜色 + 文字（"正常/预警/故障"） |
| 链接（正文中） | 只有蓝色 | 蓝色 + 下划线 |
| 选中项 | 只有底色变化 | 底色 + 勾选图标/加粗 |
| 涨跌 | 红/绿数字 | 颜色 + `+/−` 符号 + 箭头 |

### 12.1 色觉障碍的实际比例

- 红绿色觉异常（deuteranopia/protanopia）在**男性约 8%**、女性约 0.5%。中文 B 端产品一个 200 人团队里通常有 6–10 人。
- 蓝黄色觉异常罕见（<0.01%），但**蓝色与紫色混淆**在红绿型里也常见。

### 12.2 色盲友好色板：Okabe–Ito 8 色（R `grDevices` 内置值，逐字核对）

| 顺序 | 名称 | hex |
|---|---|---|
| 1 | black | `#000000` |
| 2 | orange | `#E69F00` |
| 3 | skyblue | `#56B4E9` |
| 4 | bluishgreen | `#009E73` |
| 5 | yellow | `#F0E442` |
| 6 | blue | `#0072B2` |
| 7 | vermillion | `#D55E00` |
| 8 | reddishpurple | `#CC79A7` |
| — | gray（备用） | `#999999` |

**用法**：需要 ≤8 类无序分类且必须色盲可辨时优先用它（论文/科研图、公共信息图）。日常产品界面仍用品牌色板（`dataviz.md` §3），但**必须补第二通道**。
**注意**：`#F0E442`（黄）与 `#56B4E9`（天蓝）对白底对比不足 3:1，做线条/小图形时要加深或加描边。

### 12.3 检查方法

- 浏览器 DevTools → Rendering → **Emulate vision deficiencies**（Deuteranopia/Protanopia/Tritanopia/Achromatopsia）。
- 灰度打印/截图：把界面转灰度，若信息全丢 → 只靠颜色。

## §13 用户偏好媒体查询（三条，别只做第一条）

```css
/* 1. 减少动效 —— 详见 motion-system.md §8 */
@media (prefers-reduced-motion: reduce){ … }

/* 2. 更高对比度 */
@media (prefers-contrast: more){
  :root{ --text-secondary:#333; --border:#767676; }
  .btn{ border-width:2px }
}

/* 3. 强制色彩模式（Windows 高对比度） */
@media (forced-colors: active){
  .card{ border:1px solid CanvasText }        /* 阴影会被抹掉，必须有边框 */
  .icon{ fill: CanvasText }                   /* 背景图/渐变会消失，图标用 currentColor */
  :focus-visible{ outline:2px solid Highlight }
}
```

`forced-colors` 是最容易被忽略的一条：Windows 高对比度模式下，`box-shadow`、`background-image`、`linear-gradient` **全部被抹掉**。凡是"靠阴影表达层级""靠渐变区分按钮"的界面，在这个模式下会变成一片白。

自检：Windows 设置 → 辅助功能 → 对比度主题 → 选"黄昏/夜空"，看界面还剩什么。

## §14 读屏实测：不做实测等于没做

自动化工具只能发现约三分之一的问题（结构性、可判定的）。**焦点顺序、播报质量、语义是否通顺，必须人耳听。**

### 14.1 组合矩阵（各平台各选一个，不必全装）

| 平台 | 读屏 | 浏览器 | 备注 |
|---|---|---|---|
| Windows | **NVDA**（免费） | Firefox / Chrome | 国内最常用的免费组合 |
| Windows | JAWS（付费） | Chrome | 企业采购常见 |
| Windows | 争渡读屏 | Chrome | 国内商业读屏，中文场景真实用户多 |
| macOS | VoiceOver（内置） | Safari | `Cmd+F5` 开关，VO 键 = `Ctrl+Option` |
| iOS | VoiceOver（内置） | Safari | 真实移动端主力 |
| Android | TalkBack（内置） | Chrome | 中文播报质量弱于 iOS，需实测 |
| 鸿蒙 | 屏幕朗读（内置） | 系统浏览器 | 国内新增场景，覆盖度有限 |

### 14.2 十五分钟最小实测脚本（每次交付前跑一遍）

1. **只用 Tab**：能否到达全部可交互元素？顺序是否与视觉一致？焦点是否始终可见？
2. **只用 Enter/Space**：按钮能触发？链接能跳转？自定义组件响应正确键？
3. **只用方向键**：选项卡/菜单/单选组能切换？（这是 APG 的键盘约定）
4. **Esc**：弹层能关？关闭后焦点回到触发处？
5. **读屏顺序**：关掉显示器（或用 `sr-only` 眼罩），从头听到尾，能否理解页面结构？标题层级是否 1→2→3 不跳级？
6. **表单**：每个字段读出的名称 + 类型 + 帮助 + 错误是否完整？错误出现时是否自动播报？
7. **图片**：装饰图是否被跳过？信息图是否读出结论？
8. **放大 200%**：`Ctrl +` 到 200%，内容是否横向滚动？（1.4.10 Reflow 要求 320px 宽不横向滚动）
9. **放大 400%**：是否仍可操作？
10. **强制色彩模式**：还剩什么？

## §16 中文场景：法规、国标、适老化（国外规范不管的部分）

### 16.1 法规与标准三层

| 层 | 名称 | 生效 | 对设计的意义 |
|---|---|---|---|
| 法律 | 《中华人民共和国无障碍环境建设法》 | **2023-09-01** 施行，共 8 章，含"无障碍信息交流"专章 | 公共服务类网站/App 有法定无障碍义务，不再是"做好事" |
| 国标 | **GB/T 37668-2019**《信息技术 互联网内容无障碍可访问性技术要求与测试方法》 | 2019-08-30 发布，**2020-03-01** 实施 | 58 项具体指标，覆盖可感知/可操作/可理解/兼容四方面，每项配测试方法 |
| 行业规范 | 工信部《互联网网站适老化通用设计规范》《移动互联网应用（APP）适老化通用设计规范》 | 2021-04 发布 | 适老版界面的硬指标（见下） |

**GB/T 37668 与 WCAG 的关系**：框架对应（四原则），但**不是逐条等同**，且多了"兼容性"的国产浏览器/读屏要求。做政府、金融、医疗项目时，验收口径常是"GB/T 37668 + WCAG 2.1 AA 双达标"。

### 16.2 适老化的硬数字（工信部 APP 规范）

- 主要组件可点击焦点区域：**适老版界面 ≥ 60×60 dp/pt**；其他页面 **≥ 44×44 dp/pt**。
- 单独适老版 APP：首页主组件 **≥ 48×48 dp/pt**；其他页面 **≥ 44×44 dp/pt**。
- 段落内文字行距 **≥ 1.3 倍**，段落间距 **≥ 行距 × 1.3**。
- 必须可调整字号（随系统或应用内设置）。
- 适老版页面**严禁广告、插件、随机弹窗、诱导下载/付款**。

→ 与 WCAG 的差异：WCAG 只要求 24（AA）/44（AAA），**适老化要求 60**。做银发产品时按 60 做，不要按 24 交差。

### 16.3 中文界面三个专属坑

1. **字号下限**：WCAG 没有最小字号（靠缩放），但中文 12px 在 1080p 上已接近不可读。中文正文 **16px 起**，辅助文字 **≥12px 且必须 ≥4.5:1**（`chinese-design.md` §1）。
2. **行高**：中文字面率高，行高 1.5 会显得拥挤。正文 **1.6–1.8**，适老化 **≥1.3 倍**（规范值）+ 段落间距再放大。
3. **读屏中文分词**：中文读屏按词切分，`<span>` 拆字会导致念错（"验证"+"码" 可能念成"验证 码"）。**不要把中文词拆进多个行内元素**，需要样式变化时用 `letter-spacing` 或整词包裹。

## §17 上线前自检：25 条（按可判定性排序）

**A 级（必过，8 条）**
1. 每张 `<img>` 有 `alt`（装饰用 `alt=""`，不是省略）？
2. 每个表单控件有可见 `<label for>`（不是只有 placeholder）？
3. `<html lang="zh-CN">` 正确？
4. 标题层级 1→2→3 不跳级，且只有一个 `<h1>`？
5. 所有功能可只用键盘完成？
6. 没有 `tabindex > 0`？
7. 语义元素用对（button/a/ul/table 而非 div 堆叠）？
8. 多步流程不重复索要已填信息（3.3.7）？

**AA 级（目标线，12 条）**
9. 正文对比 ≥ 4.5:1，大文本 ≥ 3:1（**不四舍五入**）？
10. 图标/边框/图表元素 ≥ 3:1（1.4.11）？
11. 焦点框存在、≥2px、与相邻色 ≥3:1？
12. 焦点不被粘性栏完全遮挡（2.4.11）？
13. 目标 ≥24×24 或满足 24px 圆不相交（2.5.8）？
14. 拖动操作有单击/键盘替代（2.5.7）？
15. 信息不只靠颜色（错误/必填/状态/涨跌）？
16. 错误用 `aria-invalid` + `role="alert"` 播报？
17. 认证不禁粘贴、不禁密码管理器、验证码单框（3.3.8）？
18. `autocomplete` 齐（尤其 `one-time-code`）？
19. 动态更新有 `aria-live` 播报且容器预先存在？
20. 帮助入口跨页面顺序一致（3.2.6）？

**AAA 选做（3 条，本技能默认做）**
21. 焦点框面积达 2px 周长、状态变化 ≥3:1（2.4.13）？
22. 正文 7:1、大文本 4.5:1（1.4.6）？
23. 焦点完全不被遮挡（2.4.12）？

**工程项（2 条）**
24. 200% 缩放下不横向滚动（1.4.10）；400% 仍可操作（1.4.10 AA 只要求 400% 重排）？
25. 强制色彩模式下仍有边框/图标/焦点（`forced-colors`）？

## §18 反模式 18 条（评审时逐条对照）

1. `outline: none` 全局重置，无替代焦点样式。
2. 焦点框颜色 = 品牌主色，在按钮上隐形。
3. 用 `:hover` 做唯一的状态提示。
4. `tabindex="1..9"` 插队。
5. 模态弹窗不锁焦点、不返回焦点。
6. `aria-modal="true"` 但背景仍可点击（假模态）。
7. 用 `aria-hidden` 藏起含可聚焦元素的容器（幽灵焦点）。
8. 图标按钮无 `aria-label`，读屏只念"按钮"。
9. `aria-label` 与可见文本不一致（语音控制点不到）。
10. 装饰图标不加 `aria-hidden`，读屏念一串"图标"。
11. 错误只变红，不给 `aria-invalid`、不播报。
12. `role="alert"` 一屏用 5 次，互相打断。
13. `aria-live` 容器在内容出现时才创建（永不播报）。
14. 验证码拆 6 个框（粘贴失效，违反 3.3.8）。
15. 手机号 `type="number"`（能滚轮误改、丢失前导 0、`inputmode` 才是正解）。
16. 禁用按钮只靠浅灰（对比不足且无说明为什么不能点）。
17. 分隔线用 `#E5E5E5`、占位符用 `#BFBFBF`，宣称"现代极简"。
18. 用 `overflow: hidden` 裁掉外扩焦点框。

## §19 三个常见争议，本技能给立场

**Q1：APCA 能不能用？**
**立场：不能作为唯一依据。** APCA 是 WCAG 3 的**候选**算法，仍在开发中，暗色模式参数标注为初步。做法：**以 WCAG 2.2 的 4.5:1 为合规基线**，APCA 的 Lc 值作为**设计参考**（正文 Lc 90 首选、Lc 75 最低；非正文 Lc 60；大标题 Lc 45；绝对下限 Lc 30）。对外承诺合规时只说 WCAG 数值。

**Q2：要不要冲 AAA？**
**立场：只冲三条。** 2.4.13 焦点外观、1.4.6 正文 7:1、2.4.12 焦点不遮挡——三条都是纯 CSS 成本。其余 AAA（1.2.6 手语、1.4.8 视觉呈现、3.1.5 阅读级别）成本高且常与产品目标冲突，**不要整体承诺**。对外说"符合 WCAG 2.2 AA，关键项达 AAA"。

**Q3：禁用态要不要满足对比度？**
**立场：不满足也不违规，但必须给理由。** 1.4.3/1.4.11 的"inactive user interface component"豁免禁用态。但实践中"灰到看不见"会让用户不知道有这个功能。做法：禁用态保持 **≥3:1** 的文字对比（比正文低但不消失），并**用文案说明为什么不能点**（"需先选择至少一项"）。这比调色更有用。
