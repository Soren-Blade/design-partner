# 内容设计与 UX 文案 — UX Writing & Content Design（深度蒸馏）

> 本文件解决「**界面上的文字怎么写才算专业**」。不是写作文，是给用户**减少决策成本**。
> 蒸馏自：Apple HIG Writing（2025-12-16 修订版）、NN/g Error-Message Guidelines（2023-05）、NN/g UI Copy（2019-03）、NN/g Tone of Voice 4 Dimensions（2016-07, reviewed 2023-08）、NN/g UX Copy Sizes（2025-05）、NN/g 3 C's / 3 I's of Microcopy（2025-03 / 2025-08）、Microsoft Writing Style Guide Top 10 Tips、GOV.UK Style Guide A–Z（全量逐条）、Ant Design 反馈规范原文、优设 B 类产品文案体验设计规范（2023-05，元尧/长弓小子）。
> 快照 2026-11-05
> 使用时机：任何界面上的文字——按钮、标签、错误提示、空态文案、引导、设置项、对话框、通知、tooltip、导航菜单——都应先查本文件。

## 一、总则：文字是界面的一部分，不是装饰

界面文字的唯一目标是**帮用户高效完成任务**。不是展示文采，不是表现幽默，不是"写得短"。判断标准只有一条：**用户读完之后知道该干什么吗？**

### 1.1 三级文案尺寸（NN/g 2025-05 定义）

| 级别 | 定义 | 用在哪 | 何时选 |
|---|---|---|---|
| **Long-form** | ≥3 段，连续成文 | 政策页、技术文档、帮助中心、案例报告、产品详情、关于我们 | 用户需要**完整理解复杂信息**时；SEO 需要；不可用微文案替代 |
| **Short-form** | 2–3 段，传达**一个**要点 | 引导教程、摘要、产品描述、使命陈述 | 比 long 快、比 micro 全；用于"扫一眼要拿走一个结论" |
| **Microcopy** | <3 句 | 按钮、链接、表单字段、标签、页面标题、错误消息、tooltip | 界面文字的**绝大多数**；目标是"扫一眼就懂" |

**关键**：microcopy 占界面文字的 80% 以上，但它不能独自构成完整体验。三层互相嵌套：long 里用 short 和 micro 来分段，short 里用 micro 做标题和按钮。

### 1.2 五条不可商量原则

| # | 原则 | 出处 | 一句话判据 |
|---|---|---|---|
| 1 | **动词开头** | Apple HIG + Microsoft + NN/g | 按钮和操作类文案第一个词必须是动词（Save / Delete / Continue）；名词或形容词只在状态切换时用（Bold / Italic / Regular） |
| 2 | **说会发生什么，不说当前状态** | NN/g UI Copy | 视频在播时按钮写"Pause"不写"Playing"——标签描述的是**点击后进入的状态** |
| 3 | **不加冠词** | NN/g UI Copy | 删掉 "a / an / the" 加快扫描（英文）；中文无冠词问题但要删多余修饰 |
| 4 | **禁用 OK** | NN/g UI Copy + Microsoft | 确认对话框按钮**禁用 "OK"**——用户会不看正文直接点。写具体动作：Delete / Discard / Save changes |
| 5 | **保留用户输入** | NN/g Error + WCAG 3.3.7 | 校验失败后**绝不清空**已填内容；用户只需修改不需要重填 |

### 1.3 扫描行为数据（设计文案的数据基础）

| 发现 | 数值 | 来源 |
|---|---|---|
| 用户在线阅读量 | 平均只读 **20%** 的文字 | NN/g "How Little Do Users Read" |
| 前 2 个词是信号 | 前 **11 个字符**决定用户是否继续读 | NN/g "First 2 Words" |
| 4 种扫描模式 | F 型 / 层饼型 / 详尽审查型 / 第 4 型 | NN/g 眼动追踪 |
| 倒金字塔 | 最重要的信息放最前面 | NN/g 在线写作黄金法则 |
| 数字用数字 | 在线场景一律用 `3` 不用 `three` | NN/g + GOV.UK |
| 句首大写 | UI 文案默认 **sentence case** | Apple HIG + Microsoft + GOV.UK + M3 |

**推论**：标题和按钮的关键词放前 2 个词。不是"Learn more about our new features"，是"New features — learn more"。

## 二、按钮与操作文案（UI Copy）

### 2.1 按钮文案规则

| 规则 | 正确 | 错误 | 出处 |
|---|---|---|---|
| 动词开头，2–4 词 | `Save changes` / `Delete file` / `Continue to billing` | `OK` / `Submit` / `Click here` / `Let's do it!` | NN/g UI Copy + Apple HIG |
| 描述结果状态 | `Pause`（视频正在播放时） | `Playing` | NN/g UI Copy |
| 禁用通用词 | `Discard` / `Save` / `Cancel` | `OK` / `Confirm` / `Go` | NN/g |
| 禁品牌词 | `Export to CSV` | `Export to SuperTool™` | NN/g |
| 加省略号表示需更多信息 | `Save As…`（弹出对话框） | `Save As`（直接执行） | NN/g UI Copy + macOS 规范 |
| 通用词不需加动词 | `Back` / `Next` / `Undo` / `Settings` | `Go Back` / `Move to Next` | NN/g |
| 但尽量用具体动词替代通用词 | `Continue to Billing` | `Next` | NN/g |

### 2.2 主次按钮文案配对

| 场景 | 主按钮 | 次按钮 | 注意 |
|---|---|---|---|
| 创建/保存 | `Save` / `Create` | `Cancel` | Cancel 在左、主在右（macOS）；Windows 主在左 |
| 删除确认 | `Delete` | `Cancel` | 主按钮**用红色**标危险；正文写清删什么 |
| 表单提交 | `Submit` → 改为 `Send email` / `Create account` | `Cancel` | 禁用 "Submit"——太抽象 |
| 多步流程 | `Continue` / `Next` | `Back` | 最后一步用 `Done` / `Finish` |
| 不可逆操作 | `Delete permanently` | `Cancel` | 永远给 Cancel 出路 |

### 2.3 中文按钮文案（B 端特有）

中文按钮**2–4 字**最佳，动词开头，不加"请"字。

| 场景 | 正确 | 错误 | 原因 |
|---|---|---|---|
| 保存 | `保存` / `保存修改` | `请保存` / `点击保存` | "请"增加多余字，降低效率 |
| 删除 | `删除` | `确认删除` | 动作已由对话框标题说明，按钮只写动作 |
| 提交 | `提交` / `发送` | `提交表单` / `提交申请` | 名词多余（除非有歧义） |
| 新建 | `新建` / `新建项目` | `添加一个新的` | 冗余 |
| 导出 | `导出` / `导出 CSV` | `导出数据` | 格式比"数据"更具体 |
| 取消 | `取消` | `返回` / `关闭` | 取消=放弃变更；返回=不变更离开；关闭=无变更 |

**优设 B 端规范**：操作文案用祈使句或动宾短语，不用否定句（"不要删除"→"保留"），不用极端语气（"绝对""一定"）。

### 2.4 省略号规则（…）

| 场景 | 加省略号 | 不加 |
|---|---|---|
| 点击后弹出对话框/需要更多输入 | `Save As…` / `Export…` | — |
| 直接执行不需额外输入 | `Save` / `Export` | — |
| macOS 菜单项 | 需要更多信息的命令加 `…` | 立即执行的不加 |

**注意**：中文省略号是 `……`（6 点），英文是 `…`（3 点 U+2026）。不要用三个句点 `...`。

## 三、错误文案（最高频的文案翻车点）

### 3.1 错误文案结构（NN/g 三层）

每条错误文案必须包含三层，缺一不可：

```
[发生了什么] + [为什么] + [怎么修]
```

| 层 | 正确 | 错误 |
|---|---|---|
| 发生了什么 | "密码太短" / "This password is too short" | "格式不正确" / "Invalid input" / "Error" |
| 为什么 | "密码需要至少 8 个字符" / "Must be at least 8 characters" | （省略 = 用户不知道为什么错） |
| 怎么修 | "请输入 8 位以上的密码" / "Choose a password with at least 8 characters" | "请重新输入" / "Please try again" |

**NN/g 原话**："That password is too short" 不如 "Choose a password with at least 8 characters"——后者把"发生了什么"和"怎么修"合并成一条指令。

### 3.2 禁用词表

| 禁用 | 原因 | 替代 |
|---|---|---|
| `Invalid` / `非法` | 责怪用户 | "不符合格式要求" |
| `Illegal` / `违法` | 法律术语误用 | "不支持" |
| `Incorrect` / `不正确` | 不告诉哪里不对 | 说具体哪里不对 |
| `Error` / `错误` 单独使用 | 不提供信息 | 说具体什么错 |
| `Please try again` / `请重新输入` | 不说怎么改 | 给具体修正指令 |
| `Oops!` / `Uh-oh!` / `哎呀` | 频繁遇到时显得不真诚 | 直接说问题 |
| `Something went wrong` / `出错了` | 太笼统 | 说具体哪出错了 |
| `Format not correct` / `格式不正确` | 不说什么格式 | "请输入 xxx 格式的 xxx" |
| `We're having trouble` / `我们遇到了问题` | "we" 指代不明（Apple HIG 明确禁用） | "Unable to load content" / "无法加载内容" |

### 3.3 错误文案位置与时机

| 规则 | 数值 | 出处 |
|---|---|---|
| 位置 | 紧贴出错字段**下方** 4–8px | NN/g Error + Ant Design |
| 不在顶部汇总唯一位置 | 长表单可顶部汇总 + 字段内联双重提示 | NN/g |
| 时机 | **失焦**报格式错误 + **提交**兜底；不一进来就红 | NN/g Error "Avoid prematurely displaying errors" |
| 高错误率字段例外 | 密码强度可实时检测（键入时） | NN/g |
| 视觉 | 红字 + 图标 + 边框（不只靠颜色） | NN/g + WCAG 1.4.1 |
| 动画 | 可加但温和（边框闪一次），不要持续闪 | NN/g |
| 严重度分级 | 阻断型用对话框；非阻断型用 inline / toast | NN/g "Design errors based on their impact" |
| 保留输入 | 校验失败后**不清空**已填内容 | NN/g + WCAG 3.3.7 |

### 3.4 中文错误文案模板

| 场景 | 模板 | 示例 |
|---|---|---|
| 必填为空 | `[字段名]不能为空` | "邮箱不能为空" |
| 格式错误 | `请输入正确的[字段名]，如[示例]` | "请输入正确的邮箱，如 name@example.com" |
| 长度不足 | `[字段名]至少[ N ]个字符` | "密码至少 8 个字符" |
| 长度超限 | `[字段名]不能超过[ N ]个字符` | "昵称不能超过 20 个字符" |
| 值超出范围 | `[字段名]应在[ min ]到[ max ]之间` | "年龄应在 18 到 120 之间" |
| 已存在 | `该[字段名]已被使用，请换一个` | "该用户名已被使用" |
| 不匹配 | `[A]与[B]不一致` | "两次输入的密码不一致" |
| 网络错误 | `网络连接失败，请检查网络后重试` | — |
| 权限不足 | `你没有[操作]的权限，请联系管理员` | "你没有删除的权限" |
| 系统错误 | `系统繁忙，请稍后重试`（不暴露堆栈/错误码给用户） | — |
| 操作失败（产品原因） | `抱歉，[操作]失败。[原因]。[建议]` | "抱歉，保存失败。文件超过 10MB，请压缩后重试" |

**优设 B 端句式**：
- 产品/系统原因：`表达歉意 + 问题描述 + 给出建议（可选）`
- 用户操作错误：`问题描述 + 给出建议`（不道歉、不责怪）

### 3.5 错误文案字数

| 类型 | 英文上限 | 中文上限 | 出处 |
|---|---|---|---|
| 字段级错误 | ≤60 字符 | ≤30 字 | 本技能 form-table.md §7 + NN/g |
| Toast 错误 | ≤80 字符 | ≤40 字 | 本技能 feedback-states.md §3 |
| 对话框错误正文 | ≤2 行 | ≤2 行 | NN/g + Apple HIG |
| 系统级错误页 | ≤3 句 | ≤3 句 | NN/g + GOV.UK 404 规则 |

## 四、空态文案（Empty State Copy）

### 4.1 空态文案五件套

| # | 要素 | 示例 |
|---|---|---|
| 1 | **标题**：说"这是什么" | "还没有项目" / "No projects yet" |
| 2 | **说明**：说"为什么会空" | "创建你的第一个项目来开始协作" / "Create your first project to start collaborating" |
| 3 | **行动按钮**：给一个明确的下一步 | `新建项目` / `Create project` |
| 4 | **次要链接**（可选）：帮助或替代路径 | `了解如何使用 →` / `Learn how →` |
| 5 | **视觉**：插画或图标（不喧宾夺主） | — |

### 4.2 五种空态（区分文案策略）

| 类型 | 标题策略 | 按钮 | 注意 |
|---|---|---|---|
| **首次使用**（无任何数据） | 欢迎语 + 引导 | `新建` / `开始` | 展示产品价值 |
| **搜索无结果** | "没有找到匹配的结果" | `清除筛选` / `修改搜索词` | 不用插画；给搜索建议 |
| **筛选无结果** | "当前筛选条件下没有数据" | `清除筛选` | 区分于搜索无结果 |
| **错误导致的空** | "加载失败" | `重试` | 不是真的空，是出错 |
| **完成后的空**（如待办清空） | "全部完成！" | 不需要按钮 | 可展示庆祝感 |

### 4.3 空态文案禁令

- **禁用俏皮话**（NN/g + Apple HIG）：空态是暂时的，别让用户每次都看同一个笑话
- **禁用 "No data"**：不提供信息也不给行动路径
- **禁用纯插画**：插画不告诉用户"该干什么"
- **搜索无结果禁用双关**（NN/g 原话批评 Disney 用 pun 替代清晰说明）

## 五、语气与语调（Tone of Voice）

### 5.1 四维度模型（NN/g）

语气不是"什么调子"，是**四个正交轴上的位置**：

| 维度 | 一端 | 另一端 | UI 默认位置 |
|---|---|---|---|
| **正式度** | Formal | Casual | **偏 Casual**（用缩约词、短句） |
| **幽默感** | Serious | Funny | **Serious**（错误文案尤其禁幽默） |
| **尊重度** | Respectful | Irreverent | **Respectful** |
| **热情度** | Matter-of-fact | Enthusiastic | **Matter-of-fact**（事实优先） |

**NN/g 研究结论**：
- 四维度变化**用户能感知到**（50 人问卷，p < 0.05 显著）
- 但感知差异**很小**（0.5–1 分 / 5 分量表）——不需要夸张，微妙变化就够了
- 品牌人格决定基线，**场景决定偏移**：错误时降幽默、降热情；成功时可升热情

### 5.2 场景 × 语气矩阵

| 场景 | 正式度 | 幽默 | 尊重 | 热情 | 示例 |
|---|---|---|---|---|---|
| 成功反馈 | Casual | — | Respectful | ↑Enthusiastic | "已保存！" |
| 错误提示 | — | **禁** | Respectful | — | "密码至少 8 个字符" |
| 空态（首次） | Casual | 微 | Respectful | ↑ | "还没有项目，创建第一个吧" |
| 危险操作确认 | ↑Formal | **禁** | Respectful | — | "确定要删除？此操作不可撤销" |
| 加载中 | — | **禁** | — | — | "加载中…" |
| 设置说明 | Casual | **禁** | Respectful | — | "开启后，收到消息会响铃" |
| Onboarding | Casual | 微 | Respectful | ↑ | "先来创建你的第一个任务" |
| 404 页 | — | **禁** | Respectful | — | "页面不存在，回到首页" |

### 5.3 语调校准方法（NN/g 三步）

1. **定品牌基线**：在四维度上标出品牌默认位置（如：Casual + Serious + Respectful + Matter-of-fact）
2. **选 3–5 个语气词**（tone words）：如 "warm / clear / confident"，避免选太多
3. **选反语气词**（anti-tone words）：如 "not cold / not playful / not sarcastic"

### 5.4 禁用语气

| 禁用 | 原因 | 出处 |
|---|---|---|
| 责怪用户（"You entered..."） | 系统的责任不是用户的 | NN/g Error |
| 道歉过多（"We're sorry..."） | 频繁道歉降低可信度 | Apple HIG（"oops/uh-oh" typically unnecessary） |
| "We" 指代不明 | "We're having trouble" 不知道 "we" 是谁 | Apple HIG 明确禁用 |
| 过度承诺（"绝对""一定"） | B 端产品禁止 | 优设 B 端规范 |
| 网络流行语 | 专业度降低，过时快 | 优设 B 端规范 |
| 强迫语气（"必须""请立即"） | 冰冷苛刻 | 优设 B 端规范 |

## 六、表单文案

### 6.1 标签（Label）

| 规则 | 正确 | 错误 | 出处 |
|---|---|---|---|
| 名词或名词短语 | `邮箱` / `Email` | `请输入邮箱` / `Your email address` | Ant Design + Apple HIG |
| ≤8 字（中文）/ ≤3 词（英文） | `手机号` | `请输入您的手机号码` | 本技能 form-table.md |
| 不加冒号（顶对齐时） | `邮箱` | `邮箱：` | Ant Design |
| 加冒号（右对齐时） | `邮箱：` | `邮箱` | Ant Design |
| 不加句号 | `邮箱` | `邮箱。` | Microsoft + GOV.UK |
| 必填只标少数派 | 多数必填→只标 `（选填）` | 全标 `*` | 本技能 form-table.md |

### 6.2 占位符 vs 标签

| | 标签 | 占位符 | 出处 |
|---|---|---|---|
| 作用 | 说"这是什么字段" | 说"怎么填"或给示例 | Apple HIG |
| 可见性 | 始终可见 | 输入后消失 | — |
| **禁用占位符替代标签** | — | 输入后占位符消失，用户不知道在填什么 | WCAG 3.3.2 + NN/g |
| 占位符写示例 | `name@example.com` | `请输入邮箱`（标签已说了） | Apple HIG |
| 占位符对比度 | — | ≥4.5:1（WCAG 1.4.3） | WCAG |

### 6.3 帮助文案（Helper Text）

| 规则 | 正确 | 错误 |
|---|---|---|
| 说"怎么填"或"为什么填" | `用于接收验证码` | `填写邮箱`（标签已说了） |
| 放在控件下方 | 标签 → 控件 → 帮助 → 错误 | 放在标签旁边 |
| 与错误共用位置 | 有错时错误**替换**帮助 | 帮助和错误并排两行 |
| ≤16 字（中文） | `8-20位字母和数字` | `请输入8到20位的字母和数字组合作为您的密码` |
| 不加句号 | `8-20位字母和数字` | `8-20位字母和数字。` |

### 6.4 设置项文案（Apple HIG + GOV.UK）

| 规则 | 正确 | 错误 |
|---|---|---|
| 标签说"开启后做什么" | `消息提醒` | `通知设置`（太笼统） |
| 帮助说"开启后的效果" | `开启后，收到消息会响铃` | `开启后将允许系统发送通知`（双重否定） |
| 用户可推断关闭效果 | 开启=响铃 → 关闭=不响铃 | 不要写"关闭后不会响铃" |
| 直接给链接不描述路径 | `[打开设置 →]` | `在设置 > 通知中开启` |

## 七、对话框与通知文案

### 7.1 对话框（Dialog / Modal）

| 部分 | 规则 | 正确 | 错误 |
|---|---|---|---|
| **标题** | 说"发生了什么"，≤1 行 | `删除项目？` | `提示` / `警告` / `注意` |
| **正文** | 说"会怎样" + 不可撤销提示 | `项目"设计稿"及其所有文件将被永久删除，此操作不可撤销。` | `确定要执行此操作吗？` |
| **主按钮** | 具体动作 | `删除` | `确认` / `OK` |
| **次按钮** | `取消` | — | `关闭`（有歧义） |
| **危险操作** | 主按钮红色 + 正文写清对象 | `删除"设计稿.v1"？` | `删除文件？`（不说哪个文件） |
| **不用"是否"** | 标题用陈述句 | `删除项目？` | `是否删除项目？` |

### 7.2 Toast / Message / Snackbar

| 规则 | 数值 | 出处 |
|---|---|---|
| 成功类时长 | 3s（Ant）/ 4–10s（M3）/ 5s（Carbon） | 本技能 feedback-states.md §3 |
| 错误类时长 | 不可自动消失（或 ≥5s） | NN/g + Ant Design |
| 宽度 | ≤384px（Ant）/ ≤2 行 | 本技能 feedback-states.md |
| 字数 | 中文 ≤20 字 / 英文 ≤60 字符 | 本技能 |
| 内容 | 动作 + 结果 | `已保存` / `已复制到剪贴板` |
| 不含操作按钮（除非可撤销） | `已删除 撤销` | `已删除 [查看] [关闭]` |

### 7.3 Notification（右上角通知）

| 规则 | 数值 |
|---|---|
| 标题 | ≤1 行，说"什么变了" |
| 正文 | ≤2 行，说"意味着什么" |
| 操作 | ≤2 个按钮 |
| 关闭 | 可手动关闭 |
| Ant Design 规则 | 重要的失败信息**不用** message（3s 消失），改用对话框 |

### 7.4 Tooltip

| 规则 | 正确 | 错误 |
|---|---|---|
| 精确描述指向对象 | `复制`（指向复制图标） | `点击此处复制内容到剪贴板` |
| ≤1 句 | `仅支持 JPG/PNG` | `此上传功能仅支持JPG和PNG格式的图片文件，其他格式不被支持` |
| 不承载操作 | 纯文字 | 放按钮（用 Popover） |
| 鼠标移入显示，移出消失 | — | 点击触发（用 Popover） |

## 八、引导与 Onboarding 文案

### 8.1 Onboarding 文案原则

| 原则 | 出处 | 说明 |
|---|---|---|
| **价值优先** | NN/g Onboarding | 第一屏说"产品能帮你做什么"，不说"产品有什么功能" |
| **做中学** | NN/g + Apple HIG | 引导嵌入操作流，不要孤立的教学页 |
| **可跳过** | NN/g | 必须有 `跳过` 按钮，不强制看完 |
| **持续引导** | NN/g | 不是一次性事件；新功能用 tooltip 适时提示 |
| **扫描友好** | NN/g 2024 研究 | 用户不逐字读；关键信息加粗、分条 |

### 8.2 Onboarding 文案结构

| 步骤 | 文案 | 注意 |
|---|---|---|
| 1. 欢迎 | `欢迎使用[产品]` + 一句话价值 | ≤1 句话 |
| 2. 价值 | `[产品]帮你[做X]，[好处Y]` | 说"帮你做什么"不是"我们有什么" |
| 3. 行动 | `创建你的第一个[项目]` | 用具体名词，不写"开始使用" |
| 4. 完成 | `一切就绪！` + `进入[产品]` | 给明确入口 |

### 8.3 Onboarding 禁令

- **禁用功能清单**：不列"功能 1/2/3"，用户不关心你的功能列表
- **禁用"开始使用"**：太抽象，应说具体做什么（"创建第一个项目"）
- **禁用不可跳过的全屏遮罩教程**：用户想跳过时找不到出口会直接离开
- **禁用一次性信息轰炸**：分步引导，每次只教一件事

## 十、术语管理与一致性

### 10.1 为什么需要术语表

同一产品里把"项目"叫成"项目""工程""workspace""空间"——用户不知道这些是不是同一个东西。**术语表是文案一致性的基础设施**。

### 10.2 术语表结构

| 术语 | 定义 | 禁用别名 | 场景 |
|---|---|---|---|
| 项目 | 用户创建的工作单元 | 工程、空间、workspace | 全局 |
| 任务 | 项目下的工作项 | 工单、item、ticket | 项目内 |
| 团队 | 多人协作组 | 组织、group、workspace | 设置页 |
| 设置 | 全局配置入口 | 偏好、配置、preference | 导航 |
| 导出 | 将数据下载为文件 | 下载、保存、download | 数据操作 |

### 10.3 一致性规则

| 规则 | 说明 | 出处 |
|---|---|---|
| **同一概念同一词** | 全产品统一 | Apple HIG "Build language patterns" |
| **同义操作统一** | "删除"不混用"移除""清除""去掉" | 优设 B 端 |
| **操作 vs 状态不混** | "发布"是操作（动词），"已发布"是状态（形容词） | — |
| **新建 vs 创建** | "新建"=从模板创建；"创建"=从零创建——选一个 | 优设 B 端 |
| **导入 vs 上传** | "导入"=带解析的数据加载；"上传"=文件传输——不混用 | — |

## 十一、大小写与标点

### 11.1 大小写（英文）

| 规则 | 用在哪 | 出处 |
|---|---|---|
| **Sentence case**（默认） | 按钮、标题、标签、菜单、对话框标题、导航 | Apple HIG + Microsoft + GOV.UK + M3 |
| **Title case** | 仅限正式文档标题、品牌名 | Apple HIG（"reflects your app's voice"） |
| **全大写禁用** | 大段文本不可全大写（难读） | GOV.UK |
| **首字母大写** | 句子首字母、专有名词、品牌名 | Microsoft |

**为什么 sentence case**：
- 更容易扫描（全大写/标题大写强制大脑逐字母读）
- 更 casual（符合多数数字产品的语气）
- Microsoft 官方立场："When in doubt, don't capitalize"

### 11.2 中文标点（优设 B 端规范）

| 规则 | 正确 | 错误 |

| 纯中文用全角标点 | `保存成功。` | `保存成功.` |

| 中英混排整句英文用英文标点 | `已保存到 Drafts.` | `已保存到 Drafts。` |

## 十三、国际化文案注意事项

### 13.1 文案膨胀

| 语言对 | 膨胀率 | 含义 |
|---|---|---|
| 英文 → 德文 | +30% | 德文复合词更长 |
| 英文 → 中文 | -20% 到 -40% | 中文更短 |
| 英文 → 法文/西语 | +15–25% | — |
| 英文 → 俄文 | +30% | — |

**设计含义（v20 修正，冲突时以 `i18n-localization.md` §2 为准）**：上表是**段落/中长文案**的经验膨胀率，**不能套到按钮、标签、tab、导航等 microcopy 上**。W3C 转引 IBM 官方表：英文 **≤10 字符平均膨胀 200–300%**（Flickr `views` 实测意语 **3.0×**），11–20 为 180–200%、21–30 为 160–180%、31–50 为 140–160%、51–70 为 151–170%、>70 为 130%。→ **microcopy 按 2–3×、短文案 1.6–2.0×、段落 1.3× 做弹性**；Microsoft 的 `+40%` 只是伪本地化测试串的加长量，不是设计余量。余量做成**能伸缩**（`min-inline-size` + `max-inline-size` + 允许换行/省略并有 tooltip 兜底），而不是把按钮做宽。另注意四类「不只是变长」的因素（德语复合词不换行 / 片假名少一字更宽 / 泰文·Nastaliq 需更高行高 / 缩写不可跨语言复制）→ 完整表与工程实现见 **`i18n-localization.md` §2**。

### 13.2 国际化禁忌

| 禁忌 | 原因 | 替代 |
|---|---|---|
| 拼接字符串 | `"Welcome " + name + "!"` 在德文语序不同 | 用模板变量：`Welcome, {name}!` |
| 复数硬编码 | `"1 file" / "{n} files"`——有些语言有 3+ 种复数 | 用 ICU MessageFormat |
| 假设字面方向 | 阿拉伯语/希伯来语 RTL | 用 CSS `direction` / `dir` |
| 日期格式硬编码 | `MM/DD/YYYY` 只在美国通用 | 用 `toLocaleDateString()` |
| 颜色含义文化差异 | 白色=婚礼（西方）vs 白色=丧礼（东亚） | 调研目标市场 |

## 十五、内容设计系统化

### 15.1 文案 token（Content Tokens）

像设计 token 一样，把文案做成可复用的变量：

```json
{
  "button.save": "保存",
  "button.cancel": "取消",
  "button.delete": "删除",
  "error.required": "{field}不能为空",
  "error.format.email": "请输入正确的邮箱，如 name@example.com",
  "error.length.min": "{field}至少{min}个字符",
  "empty.first_use.project": "还没有项目，创建第一个吧",
  "toast.saved": "已保存",
  "confirm.delete.title": "删除{type}？",
  "confirm.delete.body": "{name}及其所有内容将被永久删除，此操作不可撤销。"
}
```

**好处**：
- 一致性：同一操作全产品只有一种说法
- 可维护：改一个 token 全站生效
- 可国际化：一个 key 对应 N 种语言

### 15.2 文案评审清单（快速 PR 检查）

| # | 检查项 | 是/否 |
|---|---|---|
| 1 | 按钮是动词开头、禁用 OK/Submit？ | |
| 2 | 错误文案有"发生了什么+怎么修"？ | |
| 3 | 字数在限制内（字段 ≤30 字 / toast ≤20 字）？ | |
| 4 | 术语与术语表一致？ | |
| 5 | 大小写统一 sentence case？ | |
| 6 | 中文标点用全角、中英之间有空格？ | |
| 7 | 有 aria-label 且与可见文案一致？ | |
| 8 | 可翻译（无拼接字符串、有 ICU 复数）？ | |

## 十七、20 条反模式

| # | 反模式 | 正确做法 |
|---|---|---|
| 1 | 按钮用 "OK" / "确认" / "提交" | 写具体动作：删除 / 保存 / 发送 |
| 2 | 错误只说"格式不正确" | 说什么格式 + 给示例 |
| 3 | 错误说"请重新输入" | 说怎么改，不只是重试 |
| 4 | 用 "Oops!" / "哎呀" 开头错误 | 直接说问题 |
| 5 | 标签用占位符替代 | 标签始终可见，占位符只给示例 |
| 6 | 对话框标题写"提示"/"警告" | 写发生了什么：删除项目？ |
| 7 | 对话框正文写"确定要执行此操作吗" | 写具体操作和后果 |
| 8 | 空态写 "No data" | 五件套：标题+说明+按钮 |
| 9 | 空态用俏皮话 | 空态是暂时的，别让用户反复看同一个笑话 |
| 10 | Toast 用 "操作成功" | 写具体什么成功：已保存 / 已复制 |
| 11 | 导航标签混用动词名词 | 统一用名词 |
| 12 | 同一概念用不同词（项目/工程/空间） | 建术语表统一 |
| 13 | 英文标题用 Title Case | UI 默认 sentence case |
| 14 | 中文不加中英空格 | `使用 React 框架` |
| 15 | 数字拼写出来（three files） | 在线一律用数字（3 files） |
| 16 | 链接文字用 "Click here" / "了解更多" | 写具体去哪：下载报告 / 新功能说明 |
| 17 | 责怪用户（"You entered wrong"） | 系统视角：密码需要 8 个字符 |

### 19.6 链接文案检查脚本

```javascript
// 扫描页面中所有 <a>，检查是否包含无意义文字
const BAD_LINK_TEXT = [
  'click here', 'learn more', 'read more', 'more',
  'here', 'this link', '点击这里', '了解更多', '查看更多', '更多'
];

document.querySelectorAll('a').forEach(a => {
  const text = a.textContent.trim().toLowerCase();
  if (BAD_LINK_TEXT.includes(text)) {
    console.warn('无意义链接文字:', a.textContent, a.href);
  }
});
```

> **本文件核心立场**：界面文案不是"写得短"或"写得好"，是**让用户读完知道该干什么**。判断标准不是字数，是**信息是否完整 + 行动是否明确 + 术语是否一致**。宁可多 5 个字说清楚，不要少 3 个字让用户猜。
