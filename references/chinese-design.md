# 中文设计场景 — Chinese Design（排版规范 + 生态地图）

> 本文件解决两件事：**① 中文界面为什么不能照抄英文规范；② 中文设计资源该去哪找、怎么用、哪里有坑。**
> 使用时机：任何面向中文用户的界面**开工前必读**；做中文排版判断时逐条对照。
> 规范依据：[W3C clreq（中文排版需求）](https://www.w3.org/TR/clreq/)、Ant Design 中文规范、国内一线产品实测。
> 快照 2026-10-29

---

## 一、中文排版：为什么不是"英文换字"

### 1.1 三个根本差异

| 差异 | 英文 | 中文 | 后果 |
|---|---|---|---|
| **字面率** | 小写字母只占字身 60–70%，有升部降部 | 汉字占满字身（近 100% 方块） | 中文**视觉密度显著更高**，同样字号更"重"、更挤 |
| **词边界** | 空格分词，可任意断行 | 无空格，断行靠规则 | 需要避头尾、需要按语义断行 |
| **字重梯度** | 同族常有 9 档（Thin→Black） | 多数中文字体只有 3–4 档（Light/Regular/Medium/Bold） | 中文字重对比手段少，**不能靠字重拉层级** |

### 1.2 字号与行高（关键差异表）

| 场景 | 正文字号 | 行高 | 说明 |
|---|---|---|---|
| **中文正文（内容/官网）** | **16–18px** | **1.7–1.8** | 汉字密度高，比英文大 1–2px 才等舒适 |
| **中文正文（中后台）** | **14px** | **22px（≈1.57）** | Ant Design 标准，信息密度优先 |
| **中文辅助文字** | 12–13px | 1.6 | 再小则笔画糊 |
| **中文标题** | 20 / 24 / 30 / 38 / 48 | 1.3–1.4 | 标题行高要收，否则松散 |
| **中文大屏展示** | 48–72px | 1.2 | 需加 `letter-spacing: 0.02em` 才不粘 |

**对照英文**：英文正文 16px / 1.5 就够；中文同样 16px 需要 1.7–1.8 才不压抑。**直接沿用英文行高是中文排版最常见的错误。**

### 1.3 中文字体族栈（可直接用）

```css
/* 中文优先栈：先中文字体，再西文兜底 */
font-family: -apple-system, BlinkMacSystemFont, 'PingFang SC',
  'Hiragino Sans GB', 'Microsoft YaHei', 'Source Han Sans SC',
  'Noto Sans SC', 'Segoe UI', Roboto, 'Helvetica Neue', Arial, sans-serif;
```

| 字体 | 平台 | 说明 |
|---|---|---|
| **PingFang SC** | macOS / iOS | 苹方，屏显中文首选，字形现代 |
| **Hiragino Sans GB** | 旧版 macOS | 冬青黑，苹方的前代 |
| **Microsoft YaHei** | Windows | 微软雅黑，Windows 事实标准；字重偏细需注意 |
| **Source Han Sans SC / Noto Sans SC** | 跨平台开源 | 思源黑体，**可商用免费**，做品牌字体替代最稳 |
| **Source Han Serif SC** | 跨平台开源 | 思源宋体，正文长文/文化调性 |

**衬线 vs 无衬线**：中文正文用无衬线（黑体）更清晰；宋体适合长文阅读、文化/出版调性、大标题。**混用两套中文衬线/无衬线是灾难**，最多 1 套中文 + 1 套西文。

**开源可商用中文字体**（避免版权风险）：
- 思源黑体 / 思源宋体（SIL OFL）
- 站酷系列（站酷高端黑、站酷快乐体等，免费商用）
- 阿里巴巴普惠体（免费商用）
- 得意黑 Smiley Sans（开源，适合标题/展示）

### 1.4 字重陷阱（中文特有）

- 中文字体普遍缺 500（Medium）档，`font-weight: 500` 会被渲染成 400 或**伪粗体（faux bold）**——笔画糊、边缘脏。
- **正确做法**：需要强调时优先用**字号 + 颜色**拉开差距，而非字重。必须用字重时确认该字体真的有该档。
- 中文**不要用斜体**（`font-style: italic`）——汉字倾斜是机械变换，非常难看。要强调用加粗、变色、加下划线或背景色。
- 中文**不要用 `text-transform: uppercase`**（对汉字无效，只影响混排的西文，容易造成不一致）。

### 1.5 标点与避头尾（clreq 核心规则）

**全角标点**：中文标点占一个汉字宽（全角）。`，。；：？！「」『』（）《》` 等。

**行首禁则（不能出现在行首）**：
```
。 ， 、 ； ： ？ ！ ） 」 』 》 〉 】 ％ ℃
```
**行尾禁则（不能出现在行尾）**：
```
（ 「 『 《 〈 【
```

**实现方式**：
```css
/* 现代浏览器原生支持（推荐） */
p { line-break: strict; }
/* 或 */
p { word-break: normal; overflow-wrap: break-word; }
```
> `line-break: strict` 在 Chrome/Safari/Firefox 均已支持，是避头尾的标准解。不要用手动 `<br>` 硬调。

**其他标点细节**：
- 中文用**全角引号**「」或""，不要用英文 `""` 直接套（`""` 是弯引号，中文场景可用但需统一）
- 省略号用 **`……`（六点，两个 U+2026）**，不是 `...`
- 破折号用 **`——`（两个全角破折号）**，不是 `-`
- 数字与单位之间留**半角空格**：`16 px` 在中文里通常写 `16px`（紧凑），但 `2026 年`、`第 3 章` 需空格
- 中文与西文/数字之间加 **1/4 em 空隙**（约 0.25em）：`使用 React 开发` 而非 `使用React开发`

**中英混排间距的实现**：
```css
/* 方案 A：text-spacing-trim（较新，支持度有限） */
p { text-spacing-trim: space-first; }
/* 方案 B：手工加空格（最稳，内容层解决） */
/* 方案 C：CSS 伪元素（不推荐，易出错） */
```
> 生产环境**优先在内容层加空格**（写作规范），CSS 方案只作补充。

### 1.6 行长（中文按字数算）

| 媒介 | 英文行长 | 中文行长 |
|---|---|---|
| 正文（舒适） | 60–75 字符 | **25–40 字** |
| 正文（上限） | 90 字符 | **45 字** |
| 移动端 | 35–45 字符 | **15–20 字** |

**换算**：中文 1 字 ≈ 2 个西文字符宽，所以 `max-width: 36em`（英文标准）对中文约等于 36 字，**在舒适区间内**。但中文正文用 `max-width: 40em` 时行长约 40 字，已接近上限。

### 1.7 竖排（了解即可）

`writing-mode: vertical-rl` 支持中文竖排，但：
- 标点需 `text-orientation: upright` 或字体自带竖排标点
- 数字/西文在竖排中需旋转（`text-combine-upright` 处理两位数字）
- **实际项目极少用**，除非文化/出版调性。不要为了"有特色"上竖排。

## 二、中文设计生态地图（平台怎么用、哪里有坑）

### 2.1 六个核心平台（用户指定清单）

| 平台 | 定位 | **适合找什么** | **不适合找什么 / 坑** |
|---|---|---|---|
| **[Pinterest](https://www.pinterest.com/)** | 全球视觉灵感瀑布流 | **氛围、色彩、情绪板（moodboard）**、摄影风格、材质肌理 | ❌ UI 结构参考（大量概念图/摄影，非真实产品）；❌ 需要登录且国内访问不稳 |
| **[iconfont](https://www.iconfont.cn/)**（阿里巴巴矢量图标库） | 国内最大图标库 + 图标项目管理 | **中文场景图标**（含大量中国特色图标）、SVG 下载、字体图标、团队图标库 | ⚠️ **版权需逐个确认**（多数免费商用但作者可设限）；⚠️ 图标风格杂，需自己统一线宽/圆角 |
| **[Ant Design](https://ant.design/components/overview-cn/)** | 中文企业级设计体系 + 组件库 | **中后台一切**：组件、设计规范、设计模式、色彩/字体/布局数值 | ❌ 消费级/品牌向设计（它的语言是"效率"，不是"感染"）；❌ 直接套用会做出"标准后台脸" |
| **[站酷 ZCOOL](https://www.zcool.com.cn/)** | 国内设计师社区 + 免费商用字体 | **中文视觉设计**：海报、品牌、包装、字体设计；站酷字体**免费商用** | ❌ 界面/产品设计（偏平面）；⚠️ 作品质量方差大 |
| **[Dribbble](https://dribbble.com/)** | 全球设计师作品展示（shot 制） | **视觉风格、色彩搭配、图标/插画风格**、趋势感知 | ⚠️ **"Dribbble 化"陷阱**：为好看而牺牲可用性（假数据、无空状态、无错误态、动效过度）。**只能取视觉，不能取结构** |
| **[Designeer](https://designeer.xyz/)** | 人工策展设计目录（craft/utility/clarity/relevance 四标准） | **经过筛选的真实站点**：灵感、资源、工具、作品集（本技能 references 的主要数据源） | ⚠️ 英文为主，中文资源少；更新有滞后（本技能用脚本自动刷新） |

### 2.3 检索策略（按需求类型直接跳）

| 需求 | 首选 | 次选 | 不要用 |
|---|---|---|---|
| 中后台组件/规范 | Ant Design | Semi / Arco | Dribbble |
| 中文图标 | iconfont（确认版权） | IconPark（易统一） | Pinterest |
| 中文海报/品牌视觉 | 站酷 | 花瓣 | Ant Design |
| 氛围/色彩情绪板 | Pinterest | 花瓣、Cosmos | iconfont |
| 真实产品流程参考 | Mobbin | Screenlane | Dribbble（概念图） |
| 视觉趋势/风格 | Dribbble（只取视觉） | Behance | — |
| 中文免费商用字体 | 站酷字体、思源、普惠体 | — | 随机下载站 |
| 策展级真实站点 | Designeer | Awwwards、SiteInspire | — |

**Dribbble 使用纪律（重要）**：看到喜欢的 shot，问三个问题再决定要不要借鉴——
1. 它有**空状态**吗？（概念图几乎都没有）
2. 它的**错误态/加载态**在哪？（没有 = 不可实现）
3. 数据量放大 10 倍还成立吗？（假数据撑不起真实场景）
三问都过，才可取用。

## 三、中文产品形态的四个特征（影响设计决策）

| 特征 | 表现 | 设计应对 |
|---|---|---|
| **高信息密度** | 表格列多（10+ 列常见）、筛选条件多、单页信息量大 | 优先密度而非留白；用小字号 14/12 + 紧凑行高；提供列显隐/密度切换 |
| **长审批流** | 多级审批、会签、加签、驳回重提 | 流程状态必须可视化（步骤条 + 当前节点 + 历史）；异常路径（驳回/撤回）要设计 |
| **多角色权限** | 同一页面不同角色看到不同内容 | 权限态要设计（无权限提示而非隐藏）；不要用"隐藏"掩盖"没设计" |
| **移动端超级 App 形态** | 小程序 / 公众号 H5 / App 内嵌页 | 底部 Tab ≤5；首屏不放大图；考虑微信导航栏与胶囊按钮占位 |

**中后台 vs 消费级的分野**：
- **中后台**：效率 > 美感。目标是"少点几次、少想一步"。Ant Design 是正确答案。
- **消费级/品牌**：感染 > 效率。目标是"想再来一次"。此时 Ant Design 会是错的起点。

## 四、中文排版自检清单（交付前逐条过）

- [ ] 正文字号 ≥14px（内容页 ≥16px），行高 ≥1.6
- [ ] 字体栈里中文字体在前，且覆盖 PingFang / YaHei / 思源
- [ ] 没有用中文斜体
- [ ] 没有依赖 500 字重做层级（或已确认字体有该档）
- [ ] 标点用全角；省略号是 `……`；破折号是 `——`
- [ ] `line-break: strict` 已开启（避头尾生效）
- [ ] 中文与西文/数字之间有间距
- [ ] 正文行长 ≤40 字（移动端 ≤20 字）
- [ ] 标题未逐字换行（`word-break` 未设 `break-all`）
- [ ] 数字列用 `tabular-nums`
- [ ] 图标风格已统一（线宽/圆角/填充）
- [ ] 字体许可可商用（尤其站酷/iconfont 资源）
