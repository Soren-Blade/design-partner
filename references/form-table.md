## 1. 表单的五个零件（结构先行，样式后议）

任何表单字段都是这五件套，缺一件就出问题：

1. **标签**（Label）——回答"这是什么"
2. **输入控件**（Control）——承载答案
3. **帮助文字**（Hint / Helper）——回答"怎么填、为什么填"
4. **校验反馈**（Error / Success）——回答"我填错了吗、错在哪"
5. **动作**（Actions）——提交 / 取消 / 重置

**顺序固定：标签 → 控件 → 帮助 → 错误**。帮助与错误**占同一个位置**（框下），有错误时错误替换帮助，不要同时出现两行小字（Carbon 明文：helper text 被 error/warning 消息替换）。

**自检**：把设计稿的小字全部遮住，用户还能不能填对？如果不能，说明帮助文字缺失或标签写成了内部术语。

## 2. 标签：位置三选一，别混用

### 2.1 三种对齐的取舍（Ant Design 原文结论，可直接引用）

| 方式 | 优点 | 缺点 | 适用场景 |
|---|---|---|---|
| **顶对齐**（推荐默认） | 浏览与处理速度最快；标签长度弹性大（可两行） | 非常占垂直空间 | 希望用户**快速**填完；移动端；字段名长 |
| **右对齐** | 节约垂直空间 | 可读性下降；标签长度与输入框弹性都小 | 既要省空间、又要快（多数桌面 B 端表单） |
| **左对齐** | 文字起笔对齐，便于阅读；省空间 | 填写速度最慢；弹性最小 | 希望用户**放慢、逐项思考**（风控、医疗、申报） |

**决策规则**：
- 移动端 → 一律顶对齐（无第二选择）。
- 桌面端字段 ≤6 个 → 顶对齐更清晰；≥7 个或需要紧凑 → 右对齐。
- 需要用户谨慎填写的合规/申报表单 → 左对齐（用慢换准）。
- **同一产品内只允许一种**。混用会让用户每次重新找标签位置。

### 2.2 标签文案

- **句首大写、不加冒号、不加句号**（GOV.UK / Carbon 一致要求）。中文对应：**不加句号，右对齐可保留冒号**（Ant 默认带冒号，`labelColonMarginInlineStart: 2px`、`InlineEnd: 8px`）；顶对齐时**不要冒号**。
- 长度：英文 ≤3 词（Carbon），**中文 ≤8 字**；超过就说明该拆字段或写进帮助文字。
- 用**用户的语言**，不用系统字段名：「联系电话」不是「联系方式字段」；「公司规模」不是「org_scale」。
- 需要解释为什么收集敏感信息（手机号、身份证）时，写进帮助文字，不写进标签。

### 2.3 标签宽度的具体值

- 右对齐：标签列固定宽，取**最长标签宽度 + 8–16px**，常见 80–120px（中文 4–6 字约 80–100px）。
- Ant 24 栅格实现：`labelCol={{span: 6}}` + `wrapperCol={{span: 18}}` 是最常用比例；短标签用 `span: 4–5`，长标签 `span: 8`。
- 标签列必须**右对齐到同一条轴**，否则右对齐失去意义（这是最常见的实现 bug）。

## 3. 字段宽度：按内容长度定宽（最被忽视的一条）

**铁律：输入框宽度传达"预期输入多长"。全部等宽 = 放弃了一条免费提示。**

GOV.UK 的做法是按**字符数**给固定宽度类（width-2/3/4/5/10/20/30），且**跨屏不变**（只有视口更窄时才收缩）：

| 内容 | 建议宽度 | 说明 |
|---|---|---|
| 验证码 6 位 | 120–140px | 数字等宽 |
| 手机号 11 位 | 160–180px | 含分段空格 |
| 身份证 18 位 | 240–260px | |
| 邮编 / 区号 | 100–120px | |
| 姓名 | 200px | 中文 3–4 字够用 |
| 邮箱 / 网址 / 地址行 | 全宽或 320–400px | 无法预知长度 |
| 金额 | 180–220px + 右对齐 | 后缀「元」在框外 |

**中文场景换算**：数字按 `字号 × 0.6` 估算单字符宽，汉字按 `字号 × 1.0`。14px 下 11 位手机号 ≈ 11×8.4 + 内边距 22 ≈ 114px，加分段空格与图标留 160px 更稳。

**栅格化**：Ant 24 栅格下，短字段占 6–8 栅格、中等 8–12、长字段 12–24；**同一行不要出现 3 种以上宽度**。

**反面案例**：一行三个框，分别填「姓名」「身份证」「备注」，却都拉成等宽 400px——用户无法从形状判断该填多少，且备注框太窄。

## 4. 控件尺寸与内边距（三体系精确值）

### Ant Design（中文 B 端事实标准）

| 尺寸 | 高度 | 纵向 padding | 横向 padding | 字号 |
|---|---|---|---|---|
| 小 `small` | 24px | 计算值 ≈0–1px | 7px | 14px |
| **默认** | **32px** | **4px** | **11px** | 14px |
| 大 `large` | 40px | ≈6px | 11px | 16px |

计算式（源码）：`paddingBlock = (controlHeight − fontSize × lineHeight)/2 − 1`；`paddingInline = paddingSM(12) − 1`。圆角 6px，边框 1px，聚焦时边框不变色而加 2px 外发光（`controlOutline`）。

### Carbon（IBM，规格最完整）

| 尺寸 | xs | sm | md（默认） | lg | Fluid |
|---|---|---|---|---|---|
| 高度 | 24 | 32 | **40** | 48 | **64** |

- 标签 12px（`$label-01`）、字段文字 14px、帮助 12px、错误 12px
- 标签下间距 8px、帮助上间距 4px、字段左右 16px、下边框 1px、聚焦/错误边框 **2px**
- **Fluid 变体**：标签内嵌在框内上方，容器高 64px；出错时高度会变化（这点要预留空间，否则布局跳动）

### 选用建议

- 中文 B 端桌面：**32–40px 高**（Ant 默认 32 偏紧，表单页建议 `size="large"` 40px）。
- 触屏 / 移动端：**≥44px**（与触控目标下限一致）。
- 高密度后台（运维、财务录入）：32px 但**行距靠 24px 字段间距**撑开，不要靠缩小控件。

## 5. 必填与可选：只标少数派

**规则（Carbon 明文）**：
- 多数字段必填 → **只标可选项**，写作「（选填）」。
- 多数字段可选 → **只标必填项**，用红色 `*` 前置。
- 中文习惯：`*` 放标签**前**，红色（Ant `colorError`，默认 `#ff4d4f`）；表单顶部或底部加一行说明「带 * 为必填」——**只有在你确实标了 * 时才需要这行**。

**禁止**：
- 同时用 `*` 和「（选填）」两套语言。
- 用 `*` 标了却不解释（用户不知道 * 是必填还是重点）。
- 把必填标识做成纯颜色（色盲用户读不到，需配符号）。

## 6. 校验时机：三档，各有明确适用

| 档位 | 触发 | 只用于 | 不要用于 |
|---|---|---|---|
| **实时（键入）** | `onChange` | 格式约束类：密码强度、字数上限、可用性检查 | 「必填未填」——用户刚点进来就报红，等于骂人 |
| **失焦** | `onBlur` | **默认档**：格式错误（邮箱、手机号）、超长 | 需要跨字段比对的（确认密码） |
| **提交** | `onSubmit` | 兜底全量校验 + 汇总错误数 + 聚焦第一个错误字段 | 作为唯一校验手段 |

**实现差异（坑）**：Ant Design `Form.Item` 的 `validateTrigger` 默认 `onChange`；Semi Design 的 `trigger` **默认也是 `'change'`**。两个库都要**显式改成 `['onBlur','onSubmit']`**，否则用户打字打到一半就被判红。

**提交后的三条硬规则**：
1. **不清空已填内容**（WCAG 3.3.7 示例原文：信用卡号出错后不得清空表单）。
2. **滚动并聚焦到第一个错误字段**，且该字段旁显示错误文案。
3. 错误数量 >3 或表单跨屏时，**页首给错误摘要**，每条可点击跳到对应字段。

**跨字段校验**：确认密码、结束时间晚于开始时间——在**后一个字段失焦时**校验，且两边同时标红/解除，不要只标一个。

## 7. 错误文案：模板化，禁止「输入有误」

「格式不正确」「输入有误」「非法字符」——这三句等于没说。合格的错误文案必须包含**哪里错 + 怎么改**，能给例子就给例子。

GOV.UK 的错误文案模板（中文改写，可直接套）：

| 情形 | 模板 | 示例 |
|---|---|---|
| 未填 | 请输入{字段名} | 请输入手机号 |
| 超长 | {字段名}不能超过 {n} 个字符 | 详细地址不能超过 35 个字符 |
| 过短 | {字段名}至少 {n} 个字符 | 姓名至少 2 个字符 |
| 区间 | {字段名}需为 {n}–{m} 个字符 | 昵称需为 2–20 个字符 |
| 含不允许字符 | {字段名}不能包含 {字符} | 城市不能包含特殊符号 |
| 格式-数字 | {字段名}需为数字，例如 {例} | 每周工时需为数字，例如 30 |
| 格式-整数 | {字段名}需为整数，例如 {例} | 人数需为整数，例如 30 |
| 低于下限 | {字段名}不能小于 {n} | 每周工时不能少于 16 |
| 高于上限 | {字段名}不能大于 {n} | 每周工时不能多于 99 |
| 需小数 | {字段名}需保留小数，例如 123.45 | 金额需保留小数，例如 123.45 |
| 不需小数 | {字段名}不能带小数，例如填 123 而非 123.45 | 件数不能带小数 |

**中文写作四条**：
1. 说清「错在哪 + 怎么改」，一句说完，**不超过 30 字**。
2. 不用「非法」「无效」「错误」当主语——用字段名当主语。
3. **不用感叹号、不用「请重新输入」**（废话）。
4. 能自动纠正的就别报错：手机号多打空格、身份证末位小写 x → 静默归一化（Ant 原则原文：容错格式，能主动处理的不告诉用户这是错误）。

**位置与样式**：字段下方 4–8px，12–14px，红色 + **图标**（不只靠颜色，WCAG 1.4.1）；错误时输入框边框同步变红（2px，Carbon 规格），并把 `aria-invalid="true"` + `aria-describedby` 指到错误文本。

## 8. 帮助文字、占位符、前缀后缀

### 占位符的三宗罪（GOV.UK 原文，直接引用）

1. 用户一开始输入就消失，回看时无从对照，对记忆障碍用户尤其致命；
2. 并非所有屏幕阅读器都会朗读；
3. 浏览器默认样式的对比度常**不满足 WCAG 1.4.3**。

**结论：占位符不能替代标签，也不能承载任何必要信息。** 它只能放「格式示例」这种可有可无的提示。

### 帮助文字（Hint）

- **一句话，不加句号**（GOV.UK）；英文句首大写。
- **不放链接**（屏幕阅读器读字段描述时不会说"这是链接"）。
- 不写长段落——长解释改用「这是什么？」折叠说明或独立说明页。
- 位置：标签下、框上，或框下（与错误同位，错误优先）。**同一表单内统一一处**。

### 前缀 / 后缀

- 放**框外**（Ant `addonBefore/addonAfter`、Carbon 也是外置），不要塞进 placeholder。
- 不能是唯一的信息来源——「元」「%」「kg」要在标签或帮助文字里也说一次，否则屏幕阅读器读不到。
- 用户可能重复输入单位（在「金额（元）」框里又打了「元」）→ **校验时容忍并剥离，不报错**。

## 9. 控件选择矩阵（含中文特有字段）

| 数据形态 | 用什么 | 不要用 |
|---|---|---|
| 自由短文本（姓名、标题） | 单行输入 | 多行框（暗示要写长） |
| 长文本（备注、描述） | 多行框，初始 3–4 行，可拖高 | 单行框 + 横向滚动 |
| 纯数字（年龄、件数） | 单行 + `inputmode="numeric"` | `<input type="number">`（滚轮误改、非数字无反馈，GOV.UK 明确反对） |
| 金额 | 单行 + 右对齐 + 千分位 + 后缀「元」 | 左对齐（个位对不齐，无法比较） |
| 日期 | 日期选择器，格式 `YYYY-MM-DD` | 三个下拉（年月日）——点击成本 3 倍 |
| 日期区间 | 双月面板区间选择 + 常用快捷项（近 7 天/本月） | 两个独立日期框 |
| 二选一（是/否） | 单选（Radio）或开关 | 下拉（多一次点击） |
| ≤5 项多选 | 复选框组，全平铺 | 多选下拉（藏起来了） |
| >8 项多选 | 多选下拉 + 搜索 | 复选框墙 |
| 层级数据（省市区） | 级联选择 | 三个独立下拉 |
| 文件 | 拖拽区 + 明确格式与大小上限 | 只有一个「选择文件」按钮 |

**中文特有字段的硬规则**：

| 字段 | 规则 |
|---|---|
| 手机号 | 11 位，`1[3-9]\d{9}`；`inputmode="numeric"`；显示时自动分段 `138 0013 8000`；存储时去空格 |
| 身份证 | 18 位，末位可为 `X`（**大小写都接受，存大写**）；输入框宽 240px+；不要用日期选择器拆生日 |
| 验证码 | **单个 6 位输入框**，不要 6 个独立小框（粘贴只能进第一格 → 违反 WCAG 3.3.8 失败技术 F109）；自动提交或明确「验证」按钮 |
| 密码 | 提供「显示密码」切换；允许粘贴；强度提示实时但不拦截提交 |
| 统一社会信用代码 | 18 位，含数字与大写字母；`spellcheck="false"` |
| 地址 | 省/市/区三级级联 + 详细地址单行；不要一个框让用户自己敲全称 |
| 银行卡 | 4 位一组自动分段；`inputmode="numeric"`；不禁止粘贴 |
| 中文姓名 | 允许 2–20 字符，允许少数民族姓名中的「·」；**不要校验"必须 2–4 字"** |

## 10. 布局梯度：按内容量选，不按审美选

Ant Design 表单页规范给出 4 级梯度，**每一级兼容前一级**：

| 级别 | 形态 | 适用 |
|---|---|---|
| **1 基础** | 单列从上到下 | 内容少、无法分组（<7 项）；任务完成效率最高（有研究支撑） |
| **2 弱分组** | 短字段两三个并到一行 | 空间紧张且字段相关（省/市、开始/结束时间） |
| **3 区域内分组** | 小标题分隔的多个单列区 | 一个区域内内容多但可归类 |
| **4 卡片分组** | 每张卡片一个大标题 | 内容 >2 屏且可归类 |

**硬规则：一个区域内禁用多列表单**（Ant 原文）——多列会破坏阅读顺序，用户会跳过右列。

**可编辑列表的形态阈值（Ant 原文数值，极实用）**：

| 每条目的字段数 | 用什么形态 |
|---|---|
| ≤3 项 | 动态增减行（行内输入，无需独立标题） |
| 2–5 项 | **可编辑表格**（每行能完整呈现） |
| 6–8 项 | 折叠面板（Accordion）逐条编辑 |
| >8 项 | **抽屉（Drawer）**编辑 |

**设置页分组阈值（Ant 原文）**：<7 项不分组；7–15 项分组；>15 项用页签分组。

**分步表单**：3–5 步，每步 ≤7 个字段；必须显示步骤条与当前位置；允许回退且**回退不丢数据**；最后一步前给「确认信息」页（可编辑）。

**查询区（筛选表单）**：一行 3–4 个字段 + 「查询」「重置」；超过 4 个字段折叠为「展开更多」；筛选项 ≤3 用顶部横排，>3 且复杂用左侧栏。

**按钮位置**：
- 按钮组**必须与输入框左对齐**（Ant 表单规范原文）。
- 中文 B 端习惯：**主按钮在左、次按钮（取消）在右**；Material 系相反。团队内统一，别在一页里换。
- **主按钮禁用规则（Ant 原文）**：字段 <3 个时，必填未填可禁用主按钮（反馈链路短、规则易懂）；字段 >5 个时**不要禁用**（禁用原因难以识别，用户会困惑为什么点不动）。

## 11. 表单可访问性：可执行清单

- [ ] 每个控件都有**可见** `<label for>`；占位符不算标签。
- [ ] 按 WCAG 1.3.5，凡是收集用户信息的字段都要给 `autocomplete`：`name` `tel` `email` `street-address` `postal-code` `organization` `cc-number` `cc-exp` `one-time-code` `username` `current-password` `new-password`。
- [ ] 数字用 `inputmode="numeric"` / `decimal`，**不用 `type="number"`**。
- [ ] 姓名、邮箱、编号类字段 `spellcheck="false"`。
- [ ] **不禁用粘贴**、不用 JS 拦截自动填充（WCAG 3.3.8 失败技术）。
- [ ] 不用 `maxlength` 硬截断（无截断反馈，且会挡住用户惯用格式）；改用字数计数 + 提交时校验。
- [ ] 错误：`aria-invalid` + `aria-describedby` 指向错误文本 + 聚焦第一个错误字段。
- [ ] 多步流程**不重复问同一信息**（WCAG 3.3.7）：自动带出，或提供「同收货地址」这类一键复用；「可用选择」的数据要在同一页面可见或可展开。
- [ ] 登录：允许密码管理器填充、允许粘贴验证码、**不把 6 位码拆成 6 个框**；CAPTCHA 需提供非认知型替代（WCAG 3.3.8）。
- [ ] 移动端触控目标 ≥44×44px；键盘 Tab 顺序与视觉顺序一致。

## 12. 表格结构：五层 + 行高密度

### 12.1 五层结构

**标题/工具栏 → 表头 → 数据行 → 批量操作条 → 分页**

- 工具栏放全局操作：新建（主按钮）、搜索、筛选、列设置、导出。**最多 5 个操作**，多的收进溢出菜单（Carbon 原文）。
- 行内操作：**≤3 个用内联图标/文字链，>3 个用「更多」溢出菜单**（Carbon：溢出菜单选项 <3 时改为内联）。
- 批量条：选中行后**出现在表格顶部替换工具栏**；此时行内单操作图标应禁用（Carbon 原文）。

### 12.2 行高：三档够用，别自创

**Ant Design（源码推算，默认 14px 字号 + 22px 行高 + 1px 分隔线）**：

| 尺寸 | padding 上下 | 行高计算 | 实际行高 |
|---|---|---|---|
| `large`（默认） | 16px | 16+22+16+1 | **≈55px** |
| `middle` | 12px | 12+22+12+1 | **≈47px** |
| `small` | 8px | 8+22+8+1 | **≈39px**（Ant 注明：仅用于对话框内） |

**Carbon（五档，表头必须同高）**：xs 24 / sm 32 / md 40 / lg 48 / xl 64。xl 仅在预期单行有 2 行内容时使用。

**选择规则**：
- 通用 B 端列表 → 47–48px（可读性与密度平衡）。
- 财务/日志/监控等**扫读型**高密度 → 39–40px。
- 触屏 / 需要点行内按钮 → ≥48px（触控目标 44px 下限）。
- **表头、工具栏、批量条、分页四处高度必须与行高一致**（Carbon 硬规则），否则整张表看起来"歪"。

### 12.3 表头样式

- 底色：**浅灰填充**（Ant `colorFillAlterSolid`），不加粗黑底——黑底表头在长表里抢注意力。
- 字号：**与正文同号（14px）**，用字重 500–600 区分。**不要照搬英文的 12px 大写 + 字距**（中文没有大小写，全大写规则不成立，12px 中文在表头偏小）。
- 分隔：表头下 1px 实线（Ant `headerSplitColor`）；**行间是否画线二选一**：要么每行 1px 细线，要么斑马纹，**不要同时用**。
- 排序：三态（未排序 / 升 / 降），**仅当前排序列显示图标**，其余列悬停才显示（Carbon 原文）。默认排序必须有业务含义（如"按创建时间倒序"），不要按 id。

## 13. 列设计：决定表格好不好用的 80%

### 13.1 对齐（最容易错，且有官方依据）

| 内容类型 | 对齐 | 理由 |
|---|---|---|
| 文本（名称、描述、地址） | **左** | 阅读顺序从左起（Ant 排版规范原文） |
| 数字（金额、数量、百分比、时长） | **右**，或**小数点对齐** | Ant 原文：便于对个十百千位上的数字进行对比 |
| 日期（`YYYY-MM-DD`） | 左（同宽数字可右，但**全表统一**） | 格式统一时左对齐也可比较 |
| 状态标签 | 左或居中（**全表统一**） | |
| 操作列 | **右固定** | 拇指/视线落点 |
| 选择列（复选框） | 最左，宽 = 控件高（32px） | Ant `selectionColumnWidth` |
| 展开图标 | 在复选框**左侧**（两者都有时） | Carbon 明文 |

**等宽数字必开**：`font-variant-numeric: tabular-nums`。比例数字下 `1` 比 `8` 窄，数字列会左右跳动，右对齐也白做。

**表头对齐跟随内容**：数字列表头也右对齐，否则表头与数据错位。

### 13.2 列宽

- 按**内容实际长度**分配，不要所有列 `flex: 1` 均分（名称列被压成两行、备注列空一半）。
- 参考：选择列 32–48 / 序号列 48–64 / 短文本 100–140 / 名称 160–240 / 长文本 240–400（可省略）/ 金额 100–140 / 日期 110–130 / 状态 80–120 / 操作 80–160。
- 表格总宽 < 容器 → 拉伸"名称"这类弹性列；总宽 > 容器 → 横向滚动 + 固定首列与操作列。
- Ant 实现提示（原文）：`scroll.x` 设为一个大于表格宽度的固定值或百分比，且**非固定列宽度之和不要超过 `scroll.x`**；固定表头时若不指定列 `width`，表头与内容会错位；出现白色竖缝时留一列不设宽度做弹性。

### 13.3 截断与空值

- 单行 `text-overflow: ellipsis` + 悬停 `Tooltip` 显示全文；**关键列（名称/主键）不截断**，宁可加宽。
- 空值统一显示 **「—」**（长破折号）。不要 `null`、不要 `0`、不要留白（留白与"未加载"无法区分）。
- 长文本列若业务必须看全 → 用展开行或点击进详情，不要靠加宽列。

### 13.4 状态与语义

- 状态用**文字 + 颜色标签**，不只靠颜色（色盲可读）。
- 中文语义色：成功/进行中/警告/失败/失效；**财务涨跌用红涨绿跌**（中国习惯，与欧美相反）。
- 操作列文案用动词（编辑/停用/删除），**危险操作用红色且需二次确认**；确认弹窗写清对象（「删除 3 条规则？」而不是「确定删除吗？」）。

### 13.5 序号列

分页时必须计算全局序号：`(currentPage − 1) × pageSize + index + 1`。直接渲染 `index + 1` 是常见 bug（每页都从 1 开始）。

## 14. 表格规模化：分页、固定、批量、空态

### 14.1 分页 vs 滚动

| 场景 | 方案 |
|---|---|
| 需要定位到"第 N 页"、需要总数、需要跳页 | **分页**（默认选择） |
| 无限浏览流（动态、消息） | 无限滚动（需保留滚动位置、提供"回到顶部"） |
| >1000 行且需排序/筛选 | 服务端分页 + 虚拟滚动，**不要前端全量渲染** |

- 默认 `pageSize`：Ant 是 10；**B 端列表建议 20**，并提供 10/20/50 切换（Ant `showSizeChanger`）。
- 分页器放表格**右下**，与表格右边缘对齐；显示总数与当前区间（「第 1-20 条，共 246 条」）。
- 筛选/搜索条件变化时**重置到第 1 页**（否则用户看到空列表以为没数据）。

### 14.2 固定与滚动

- 行数 >15 或表格高度受容器限制 → **固定表头**（`sticky`/`position: sticky`）。
- 列数 >8 或总宽超容器 → **固定首列（标识列）+ 操作列**，中间横向滚动。
- 固定列必须有**明确的左右边界阴影或分隔线**，否则用户不知道还能滚。
- 表格容器高度固定时，**分页器固定在容器底部之外**，不要跟着滚。

### 14.3 批量操作

- 表头复选框三态：全选 / 未选 / **不确定**（indeterminate，部分选中）。
- 选中后显示「已选 3 项」+ 批量操作 + 「取消选择」；**不要只靠行底色表示选中**（配复选框勾选态）。
- 批量危险操作需二次确认，且确认文案带数量。
- 跨页选择要明确告知（「已选 3 项（本页）」vs「已选 12 项（全部）」），这是高频误解点。

### 14.4 空态、加载、错误

| 状态 | 处理 |
|---|---|
| 无任何数据（首次） | 插画/图标 + 一句说明 + **主行动按钮**（新建） |
| 有筛选条件但无结果 | 「没有符合条件的记录」+ **「清除筛选」按钮**（两种空态必须区分，否则用户以为数据丢了） |
| 加载中 | **骨架屏**优于 spinner（Carbon 原文），骨架行数 ≈ 一屏行数 |
| 加载失败 | 错误说明 + 重试按钮，保留已有数据 |
| 数据异常（某格为空/超长） | 「—」+ Tooltip，不要让整行塌陷或撑破 |

## 15. 表格可访问性与中文细节

**语义与键盘**：
- 用真 `<table>`（或组件库等价语义），不要 div 拼表格。
- 表头 `<th scope="col">`；行首标识列可用 `scope="row"`。
- 表格有标题时用 `<caption>`（可视觉隐藏），屏幕阅读器能念出"这是什么表"。
- 排序状态用 `aria-sort="ascending|descending|none"`。
- 行内操作必须可 Tab 到达，且有可读名称（图标按钮加 `aria-label`）。

**中文数字与格式**：

| 项 | 规则 |
|---|---|
| 千分位 | 金额、数量 ≥1000 加千分位：`12,345.67` |
| 大数缩写 | ≥1 万用「万」、≥1 亿用「亿」，保留 1 位小数（与 `dataviz.md` §6 一致） |
| 小数位 | 金额统一 2 位；百分比统一 1 位；**同列小数位必须一致** |
| 单位 | 写在**列名**里：「金额（元）」「时长（分钟）」，不要每格重复 |
| 日期 | `YYYY-MM-DD`；时间 24 小时制 `HH:mm`；相对时间（3 分钟前）只用于 ≤7 天内 |
| 脱敏 | 手机 `138****8000`；身份证 `110***********1234`；姓名 `张*` |
| 负数 | 用 `-1,234` 而非 `(1,234)`（中文财务少用括号法）；涨跌用红绿 + 正负号 |

## 16. 反模式清单（逐条给改法）

1. **占位符当标签** → 加可见标签，占位符只留格式示例。
2. **所有输入框等宽** → 按内容长度定宽（§3）。
3. **必填用红 * 但不解释** → 顶部加「带 * 为必填」或改用「（选填）」标少数派。
4. **一进来就全红** → 校验改 `onBlur` + `onSubmit`。
5. **错误只说"格式不正确"** → 套 §7 模板，写清哪里错、怎么改、给例子。
6. **提交失败清空表单** → 保留全部已填内容（WCAG 3.3.7）。
7. **一个区域内两列表单** → 改单列或拆成两个区域。
8. **主按钮居右且与输入框不对齐** → 与输入框左对齐，全站统一主左次右。
9. **6 位验证码拆 6 个框** → 单框 6 位（WCAG 3.3.8）。
10. **表格所有列居中对齐** → 文本左、数字右、操作右固定。
11. **数字列用比例数字** → `tabular-nums`。
12. **表头黑底白字 12px 大写** → 浅灰底、14px、字重 600。
13. **行线与斑马纹同时用** → 二选一。
14. **空值留白或写 0** → 统一「—」。
15. **两种空态不区分** → 无数据给新建按钮，无结果给清除筛选。
16. **每页都从 1 开始编号** → 全局序号公式。
17. **表头/工具栏/分页高度不一致** → 全部对齐行高。
18. **筛选后不重置页码** → 条件变化回第 1 页。

## 17. 交付自检（表单 10 + 表格 10）

**表单**
1. 每个字段有可见标签？占位符没被当标签？
2. 标签对齐方式全表统一？右对齐的标签列在同一条轴上？
3. 输入框宽度反映预期内容长度？没有一行三个等宽大框？
4. 必填/可选只标了少数派？有解释？
5. 校验时机是失焦 + 提交？没有一进来就报红？
6. 错误文案说清了「哪里错 + 怎么改」，≤30 字，无感叹号？
7. 提交失败保留已填内容？聚焦第一个错误字段？错误多时有摘要？
8. 手机号/身份证/验证码/金额用了正确控件与格式（§9）？
9. `autocomplete` 齐？不禁粘贴？没用 `type=number`？验证码单框？
10. 按钮与输入框左对齐？主按钮禁用规则符合字段数（<3 可禁、>5 不禁）？

**表格**
11. 行高在 39/47/55（或 Carbon 五档）里取值？表头/工具栏/批量条/分页同高？
12. 文本左、数字右、操作右固定？表头对齐跟随内容？
13. 数字列开了 `tabular-nums`？小数位同列一致？单位写在列名？
14. 列宽按内容分配？关键列不截断？长文本有 Tooltip？
15. 空值统一「—」？两种空态区分？加载用骨架屏？
16. 排序三态且仅当前列亮？默认排序有业务含义？
17. 分页默认 20 条 + 可切换？筛选变化重置页码？序号全局连续？
18. 批量：表头三态、已选数量、跨页说明、危险操作二次确认？
19. 固定列有边界提示？横向滚动时首列与操作列固定？
20. 语义：真 table + `scope` + `caption` + `aria-sort`？行内操作可 Tab？
